# Proposal

## Why

班级日历是家长「知情 + 准备」的核心入口，但它是**唯一没有规格覆盖的大模块**（活基线 16 个能力中无日历），行为语义从未固化，已产生三处实际断点：

1. **家长可见性失控**：家长端查询不过滤发布状态，老师所有的（含未打算发布的）事件家长都看得见
2. **「通知家长」是空头支票**：创建页开关承诺「发布后自动推送至家长端」，实际既不控制可见性、也不触发任何推送（创建/更新路径均不写 notice_id）
3. **类型与颜色四方漂移**：类型色散在老师端硬编码映射、事件存储字段、契约示例、设计稿四处，无单一来源

另有供给端缺陷：常规课表靠老师逐条手录不可持续（第 3 周即放弃 → 日历腐烂为空 → 家长端没内容 → 功能死亡）。本次一次把业务语义对齐，并补上课表供给机制。

## What Changes

- **受众范围**：事件从「仅班级」升级为「班级或园级」——假期/体检/全园活动不再要求按班复制 N 条
- **发布语义拆分**：新增草稿/发布状态控制家长可见性（家长只见已发布）；`is_published` 改为纯推送开关
- **推送链路**：发布/更新（经保存时确认）触发通知，复用通知模块的定向与已读追踪（已核实 notice-targeting 现有需求可覆盖班级/全园目标，不改其规格）
- **类型字典化**：事件类型 seed 为系统字典（5 内置 + 园所可扩展；取值来源：`domain/calendar.go` 常量 + `design-data/teacher-06` 图例，二者一致）；颜色/图标元数据入字典项；两端小程序改为字典驱动渲染，删除硬编码类型色映射。类型色是**数据驱动语义色**，不进 `tokens.json`
- **课表供给（园所开关）**：开启后教务在后台维护「年级模板 + 班级微调」课表，自动物化同步到日历（覆盖标记 + 滚动窗口）；课表实例默认不推送（节律 Pull，例外 Push）
- **变更提示**：已发布事件被修改后，家长端日历顶部显式提示变更（说明改了什么——价值在打破旧认知）；保存时弹确认「是否通知」，按变更实质预勾选
- **园级发布权限**：行政/教学/后勤/招生园长（管理端 RBAC 角色，挂日历发布权限码）与医生（doctor 系统角色）可发布园级事件；老师对园级事件只读

## 明确不做什么

- 不做通用重复规则引擎（RRULE 等）；规律性内容由「课表模板」承载
- 不做课表调整的审批工作流（覆盖即生效）
- 不做变更历史的完整审计表（存储粒度待定，见「阻塞与待定」）
- 不做家长端「近期重要活动」聚合视图与 importance 紧迫性表达（待产品决策）
- 不改通知模块既有需求（复用其定向 + 已读口径）
- 不扩展 doctor 端新能力（体检发布入口形态由 design 定）

## Capabilities

### New Capabilities

- `class-calendar`: 日历事件核心语义——类型字典驱动、受众范围（班级/园级）、发布状态与家长可见性、发布/变更的通知推送、变更提示、园级发布权限
- `class-timetable`: 课表子系统——年级模板 + 班级微调、园所开关、物化同步到日历（覆盖标记 + 滚动窗口）、课表实例默认不推送

### Modified Capabilities

（无——通知复用其现状能力；管理端权限沿用既有强制登记表机制；两者均无需求变更）

## 阻塞与待定

- `[待定]` 变更记录的**存储粒度**（用户声明「具体再定」）：行为规格只固化「变更须可提示、须说明改了什么」，存储形态留给 design
- `[待定]` 家长端 importance 紧迫性表达 + 「近期重要活动」聚合：待产品决策，本变更不覆盖
- design 阶段定：体检事件的发布入口（管理端 web vs 医生端小程序）

## Impact

- **涉及端**：teacher、parent、admin（发布/维护/权限）、doctor（体检发布入口待定）
- **契约变更声明**：本次将修改 `backend/api/`，属于契约变更（**BREAKING**）
  - `api-teacher/08-calendar.md`：查询参数与 dots 响应收敛（现契约 year/month vs 实现 start/end、dots 格式均已漂移）
  - `api-parent/08-class.md`：可见性过滤 + 内部字段不再外泄
  - `api-admin`：新增日历/课表相关段
- **契约字段溯源**：类型标签/颜色 ← 字典项（seed 自 `design-data/teacher-06` 图例）；受众范围/发布状态/变更提示 ← 本变更业务场景（design 将逐字段对齐或补设计）；现有外泄字段（`kindergarten_id`/`creator_id`/`is_published` 等）**无任何 UI 出处 → 删**
- **server**：`domain`（calendar 改 / timetable 新 / 字典 seed）、`repository`、`service`（teacher/parent/admin）、`handler`、`router.go`、**管理端权限登记表**（新增管理端接口必须登记，否则启动失败）、Wire DI、手工迁移 SQL + `cmd/dbcheck` 核实
- **teacher**：日历页（字典驱动、草稿标记）
- **parent**：日历页（可见性、变更提示、字典驱动标签）
- **admin**：课表维护（年级模板 + 班级微调）、园所开关、园级事件发布、角色配置（4 园长角色）
- **设计补缺**：家长端变更 banner、老师端保存确认弹窗（设计稿无此元素，需补设计）
- **测试**：`docs/tests/TEST_CATALOG.md` 补录 `TC-NEW-*`
