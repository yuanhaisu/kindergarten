# Spec Delta

## Purpose

按端隔离微信小程序登录身份：teacher / parent 各以本端小程序身份换取微信会话并落本端独立的 User，换端登录不得命中另一端账号。

## ADDED Requirements

### Requirement: 老师端微信登录落老师端独立身份
老师端小程序发起微信登录时，系统 SHALL 以老师端小程序的微信凭据换取会话，并在老师端身份域内查找或创建 User。该 User 与家长端账号彼此独立，不得因同一自然人而合并。

#### Scenario: 老师端首次微信登录
- **WHEN** 老师端小程序以 `role=teacher` 调用 `POST /auth/login/wechat`，且该微信身份在老师端从未登录过
- **THEN** 系统创建一条仅属于老师端的 User 并签发令牌，即使同一自然人已在家长端有账号，也不得复用家长端那条 User
- **TC**: TC-NEW-ATH-0001

#### Scenario: 老师端再次微信登录命中本端账号
- **WHEN** 老师端小程序以 `role=teacher` 再次登录，且该微信身份此前已在老师端建号
- **THEN** 系统命中同一条老师端 User 并签发令牌，不新建、不命中家长端 User
- **TC**: TC-NEW-ATH-0002

### Requirement: 家长端微信登录落家长端独立身份
家长端小程序发起微信登录时，系统 SHALL 以家长端小程序的微信凭据换取会话，并在家长端身份域内查找或创建 User。该行为与老师端对称。

#### Scenario: 家长端首次微信登录
- **WHEN** 家长端小程序以 `role=parent` 调用 `POST /auth/login/wechat`，且该微信身份在家长端从未登录过
- **THEN** 系统创建一条仅属于家长端的 User 并签发令牌，不与老师端 User 合并
- **TC**: TC-NEW-ATH-0003

#### Scenario: 换端登录不得命中另一端账号
- **WHEN** 同一自然人先后在老师端与家长端各登录一次
- **THEN** 系统产生两条 User 记录，各自持有本端登录身份；任一端后续登录只命中本端那条
- **TC**: TC-NEW-ATH-0004

### Requirement: 微信凭据选取失败必须显式报错
当登录请求的 `role` 无对应微信凭据配置、或换取会话失败时，系统 SHALL 返回明确错误，不得静默改用另一端凭据、不得静默降级为未登录。

#### Scenario: 未配置该端微信凭据
- **WHEN** 某端微信登录所对应的 AppID/Secret 未配置
- **THEN** 登录请求返回明确失败，错误信息可区分于网络抖动类临时错误；不得回退到另一端凭据继续换取会话
- **TC**: TC-NEW-ATH-0005

#### Scenario: 换取会话被微信侧拒绝
- **WHEN** 使用该端凭据换取会话时被微信拒绝（如 AppID/Secret 不匹配、code 已使用）
- **THEN** 登录请求返回明确失败并携带可诊断的错误信息，不得签发令牌
- **TC**: TC-NEW-ATH-0006

### Requirement: 老师端邀请码重绑登录身份
老师端通过邀请码完成的微信登录，系统 SHALL 将本次换取到的老师端微信身份写入该邀请所指向的预创建教师账号，而非新建 User。该路径用于切换老师端小程序后重绑失效的登录身份。

#### Scenario: 邀请码绑定预创建教师账号
- **WHEN** 老师端以有效邀请码 + 本端微信身份调用登录
- **THEN** 该微信身份绑定到邀请指定的教师账号，原账号的角色与班级信息保持不变，不新建 User
- **TC**: TC-NEW-ATH-0007

#### Scenario: 邀请码无效或已被使用
- **WHEN** 老师端以无效或已使用的邀请码调用登录
- **THEN** 登录请求返回明确失败，不绑定任何账号、不新建 User
- **TC**: TC-NEW-ATH-0008
