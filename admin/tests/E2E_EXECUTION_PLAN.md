## 一、总体策略

### 执行原则

1. **按模块串行**：一个模块跑完再进下一个，保证数据依赖链正确
2. **先创建再消费**：先跑 Classes → Students 等基础数据模块，后跑依赖它们的业务模块
3. **边测边修**：发现 bug 当场修复，记录到模块结果表
4. **截图留痕**：关键步骤、失败现场、修复后验证都截图
5. **最终回归**：全部模块跑完后做一轮快速冒烟回归
6. **数据留场（新增）**：除「删除接口」专项用例外，**不得在 Round 末尾把列表删空**；须保留本文件「Round 收尾数据量」中的下限，且最终截图中列表/统计区可见 **多条真实业务向数据**（非单条、非空态）
7. **命名真实感（新增）**：班级/师生/家长/任务等命名符合国内幼儿园常用说法（年级班组、教职工姓氏、幼儿小名等），避免无意义字符串 `test123` 占满生产式演示

### 执行顺序（数据依赖链）

```

  ├── Round 0: 登录 + 框架
  ├── Round 1: 系统设置 Settings

  ├── Round 4: 老师管理 Teachers       ← **8 名老师**（与班级带班关系可分配）
  ├── Round 5: 学生管理 Students       ← **≥24 名学生**（每班至少 4 人，均匀或近似均匀）
  └── Round 6: 家长管理 Parents        ← **≥12 名家长**（优先「一孩一长一短号」，部分二孩家庭）
```

### 1.5 测试数据规模与完成标准（强制执行）

以下数量为 **本 Round 执行结束后的最低残留**（C 模式：数据保留在库中用于联调与截图验收）。**删除类用例**仅允许删除「本轮为测试删除而额外创建的一条冗余记录」，不得删除达到下限所需的主数据。

| 数据域 | 业务逻辑约束 | Round 结束时最少残留 |
|--------|----------------|----------------------|
| 学年 | 与当前园所学年制度一致 | **≥3 条学年**（含当前学年标记） |
| 自定义角色 | 与权限分工一致：教学管理 / 后勤 / 保健等 | **系统默认 1 + 自建角色 ≥4**（共 **≥5 行**） |

| 教职工 | 每班有主班；另有共用老师 | **≥8 名**老师，职务/带班字段合理 |
| 在园幼儿 | 每班定额 + 名单可读 | **≥24 名学生**，姓名像真实幼儿（可虚构） |
| 家长账号 | 与学生比例、接送现实 | **≥12 名家长**；**≥8 名学生**至少绑定 1 位家长 |
| 出勤 | 跨多日才有概览意义 | **≥18 条出勤明细**（覆盖 **≥3 个工作日**、多班多人） |
| 请假 | 待审+已审混合 | **≥5 条**请假记录（含 **≥2 条待审批** 若流程支持） |
| 接送 | 正常+异常混合 | **≥12 条**接送记录（含 **≥2 条异常或待授权** 若功能支持） |
| 成长记录 | 教师撰写、审核流 | **≥10 条**日志，审核后列表仍 **≥6 条** |
| 亲子任务 | 周任务节奏 | **≥5 个任务**；删除测试后仍 **≥4 个** |
| 积分 | 有流水才有概览 | **积分流水 ≥16 条**（或界面等价「满一页」） |

| 通知 | 园所日常通知 | **≥6 条**通知（草稿/已发/待审等状态尽量覆盖） |
| 公告 | 对外公示节奏 | **≥5 条**公告 |
| 内容审核 | 依赖 UGC 入口 | **≥4 条**待审或可追溯记录 |
| 副管理员 | 主账号不动 | **≥2 个新建副管理员账号**（列表总行数 **≥3** 含超管） |
| 操作日志 | 前序操作沉淀 | 列表可见 **≥40 条**（或日期筛选后仍 **≥15 条**） |
| 看板/统计 | 依赖上游汇总 | 各统计卡片/图表 **非全 0 空壳**（若接口为 0 须在报告说明数据缺口） |

**报告验收**：每个 Round 的 `REPORT.md` 小节须附 **收尾截图**，图中列表区行数或统计数字应能直观看出「多条数据」，并注明是否达到上表下限。

## 二、每个 Round 的标准测试流程

```
1. 导航到页面 → 截图（初始状态）
2. 检查 console 错误 → 记录
3. 验证列表接口 200（或正确的空态/有数据渲染）
4. 如有搜索/筛选 → 操作 → 验证接口带参 + 列表刷新
5. 新建操作：
   a. 打开表单弹窗 → 截图
   b. 空表单提交 → 验证必填校验
   c. 正确填写 → 提交 → 等接口 201/200 → 验证 toast + 列表刷新
6. 编辑操作：
   a. 点表格行操作按钮 → 弹窗打开 → 截图
   b. 修改某字段 → 提交 → 验证
7. 删除操作：
   a. 点删除 → 确认弹窗 → 确认 → 验证 toast + 列表刷新
8. 其他业务操作（审批、调班、导出等）
9. 收集 console 错误 → 截图（最终状态）
10. 遇到 bug → 修复 → 重新验证 → 记录
11. **Round 收尾**：对照本节「1.5」与本 Round 表格中的「收尾数据量」核对；**截图列表区或统计区**（须可见多条数据，禁止以空表作为通过依据，除非该模块合法空态且计划中已豁免——本文件未豁免主数据模块）
```
