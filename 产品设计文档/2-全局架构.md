### 三端应用技术栈

| 端 | 目录 | 技术栈 | 入口 |
|---|------|--------|------|
| 管理后台 | `admin/` | Nuxt 3 + Vue 3 + Element Plus + Pinia + ECharts + Tailwind | PC 浏览器 |
| 老师端 | `teacher/` | uni-app + Vue 3 + Vite (mp-weixin) | 微信小程序 |
| 家长端 | `parent/` | uni-app + Vue 3 (mp-weixin) | 微信小程序 |
| 后端 | `server/` | Go + Gin + GORM + Redis + Casbin + Alibaba OSS | `cmd/api/main.go` |

## 2.2 多租户数据隔离

所有核心业务表均包含 `kindergarten_id` 字段（索引，非空），通过中间件在请求上下文中注入当前园所 ID，确保：

- 管理员只能查看所属园所的数据
- 老师和家长的 `UserRole` 明确关联 `KindergartenID`
- 学生、班级、通知等全部业务数据按园所隔离

API 层面不暴露 `kindergarten_id` 参数——由后端根据当前用户身份自动解析。

## 2.3 认证与鉴权流程

### 2.3.1 管理后台登录（密码认证）

```
浏览器 → POST /api/v1/auth/login/password { phone, password }
       → 后端验证密码 → 签发 JWT access_token + refresh_token
       → 浏览器设置 Cookie: admin_token, admin_refresh
       → SPA 全局路由守卫检查 Cookie，无 token 跳转 /login
```

Token 续期：`useHttp` 拦截器在收到 401 时自动调用 `POST /auth/refresh`，刷新成功后重放原请求。

### 2.3.2 小程序登录（微信授权）

```
小程序启动 → wx.login() 获取 code
          → POST /api/v1/auth/login/wechat { code, role }
          → 后端调用微信 code2session 获取 openid
          → 查找或创建 User → 签发 JWT
          → 小程序存储 token 到本地 Storage
          → 每次请求在 Header 带 Authorization: Bearer <token>
```

老师端额外需传入 `inviteCode`（管理员创建老师后生成的邀请码）。

### 2.3.3 中间件鉴权链

| 中间件 | 位置 | 作用 |
|--------|------|------|
| `CORS` | 全局 | 跨域处理 |
| `RequestID` | 全局 | 为每个请求添加唯一 ID（日志追踪） |
| `ContextLogger` | 全局 | 基于 slog 的结构化日志，附 RequestID |
| `AuthJWT` | authed 路由组 | 解析 JWT，注入用户身份到 Context |
| `CasbinRBAC` | authed 路由组 | 基于 (role, path, method) 的权限校验 |

### 2.3.4 用户统一模型

一个自然人可以拥有多个角色：同一张 `users` 表，通过 `user_roles` 表关联多个身份。一个人可以同时是"A 园所某班的老师"和"B 园所某班的家长"。

## 2.4 文件存储 (OSS)

- 客户端获取 OSS 上传凭证 → 直传 OSS → 返回文件 URL → 前端提交到业务接口
- 后端为业务接口提供文件 URL 管理能力
- OSS 开启 CDN 加速，图片支持缩略图处理

## 2.5 API 设计约定

### 路由结构

```
/api/v1/
├── /auth/*          认证相关（公开）
├── /common/*         通用接口（需登录）
├── /admin/*          管理后台接口（需管理员角色 + Casbin 鉴权）
├── /teacher/*        老师端接口（需老师角色）
└── /parent/*         家长端接口（需家长角色）
```

### 响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": { ... },
  "request_id": "uuid-string"
}
```

- `code`: 0 表示成功，非 0 为业务错误码
- `request_id`: 与日志关联的请求追踪 ID

### 分页格式

```
GET /admin/students?page=1&page_size=20

Response:
{
  "list": [...],
  "total": 150,
  "page": 1,
  "page_size": 20
}
```

## 2.6 后端分层架构

```
cmd/api/main.go       →  入口（配置加载 → 日志初始化 → Wire 注入 → 启动）
internal/
  config/             →  INI 配置加载（支持环境变量覆盖）
  app/                →  Wire 依赖注入 + 路由注册
  auth/               →  JWT 签发/解析 + 微信 code2session
  middleware/          →  中间件链
  rbac/               →  Casbin 策略引擎
  domain/             →  GORM 数据模型（~40 个实体）
  repository/         →  数据访问层
  service/            →  业务逻辑层
  handler/http/       →  HTTP 处理层（Handler 聚合所有 Service）
  storage/oss/        →  阿里云 OSS 操作
pkg/
  log/                →  slog 封装
  response/           →  统一响应格式
  pagination/         →  分页工具
```

新增模块的标准流程：`domain → repository → service → handler → router 注册 → make wire`
