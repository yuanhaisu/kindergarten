# 7. 数据模型

> 最后更新 2026-05-24 · 状态 draft

**参考源码**: `server/internal/domain/` 下 35+ 个模型文件，对应约 50 张数据库表。

---

## 7.1 设计原则

1. **多租户隔离**: 所有业务表均包含 `kindergarten_id`（索引，非空），通过中间件注入，API 层不可见。
2. **统一用户表**: `User` 是所有自然人的唯一身份表，通过 `UserRole` 关联多个角色（同一个人可既是老师又是家长）。
3. **软删除**: 核心业务实体使用 `SoftDeleteModel`（含 `deleted_at`），便于审计追溯。
4. **多对多关联**: 通过独立关联表实现（如 `ClassTeacher`、`StudentParent`、`GrowthLogStudent`）。
5. **JSON 字段**: 少量灵活配置使用 JSON 存储（如 `KindergartenAppSetting.ExtraConfig`）。
6. **冗余快照**: `StudentDailySummary` 按学生+日期预聚合出勤/餐食/午睡/情绪数据，避免高频查询时的实时关联。

## 7.2 第1层：组织与人员

### 核心实体关系

```
Kindergarten (1) ──┬── Class (N)
                    │      ├── Student (N)
                    │      ├── ClassTeacher (N) ─── User (N)
                    │      ├── CalendarEvent (N)
                    │      ├── Notice (N)
                    │      └── ParentTask (N)
                    │
                    └── User (N, 通过 UserRole 间接关联)
                           ├── TeacherProfile (N)
                           └── ParentProfile (N)

Student (N) ─── StudentParent (N) ─── User (N)
```

## 7.5 第4层：成长记录

### 可见性规则

成长记录通过 `target_type` + `growth_log_students` 实现差异化的家长可见性：

| target_type | 含义 | 家长可见性 |
|:---:|------|------|
| 1 | 全班记录 | 孩子所在班级的**所有家长**可见 |
| 2 | 指定学生 | 仅 `growth_log_students` 中关联的**目标学生家长**可见 |
| 0 (旧数据) | 默认值 | 等同于 1（全班），向后兼容 |

**家长端查询逻辑**（统一信息流）：
```sql
SELECT * FROM growth_daily_logs
WHERE class_id IN (家长孩子的班级ID列表)
  AND deleted_at IS NULL
  AND (
    target_type = 1   -- 全班记录，所有家长可见
    OR (
      target_type = 2  -- 个体记录，仅目标学生家长可见
      AND id IN (SELECT log_id FROM growth_log_students WHERE student_id IN (家长的孩子ID列表))
    )
  )
ORDER BY date DESC, id DESC
```

| `point_accounts` | (student_id) UNIQUE | 一人一个积分账户 |
