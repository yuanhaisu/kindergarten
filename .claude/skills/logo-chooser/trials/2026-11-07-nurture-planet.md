# 回归用例 01 · 养成星球

**目的**：验证 `axes.json` 能不能表达真实发生过的决策。
**样本**：A1（定稿）与 P2b（备选）——两者在同一个项目里被反复比较过，是最好的对照组。
**方法**：把两个标的拆成轴坐标，看轴表是否可区分、可生成。

---

## 一、两个标的的轴坐标

实测数据来自 `assets/logo-v2/masters/A1-symbol-color.svg` 与 `directions-peel/p2b.svg`。

| 轴 | A1 | P2b | 是否区分 |
|---|---|---|---|
| `mark_type` | combination（符号 + 中文名） | combination | — |
| `mood` | warm / solid / calm | warm / playful | 弱 |
| `type_style` | geometric-sans（Noto Sans SC Bold） | 同 | — |
| `literalness` | metaphor | metaphor | — |
| `geometry` | circle（弧） | circle（盘） | — |
| **`figure_ground`** | **line**（等宽弧 + 实心点） | **negative**（实心盘挖掉一块） | **✅ 唯一决定轴** |
| `symmetry` | asymmetric | asymmetric | — |
| `container` | none | none | — |

**结论 1：8 条轴里只有 1 条在起作用。**

这不是缺陷。前四站已经把 7 条轴钉死了，最后一站只回答「线还是面」。固定路径的价值就在这里：**把一个大而模糊的决定，压缩成一个能说出口的小决定。**

但它带来一条硬要求：

> **发散时必须保证每条轴的每个取值至少出现一次，不能只出「看起来完整」的那一版。**

否则 `line` 会因为「不如实心完整」而被默认跳过——而 A1 恰恰就是 `line`。

---

## 二、轴表测不到的部分

### 2.1 连续参数

轴是**离散选型**，真实质量活在**连续参数**里：

| 标的 | 轴取值 | 决定成败的参数 |
|---|---|---|
| A1 | `line` | 弧扫过 **270°**、线宽 **22**、端点圆帽 11、点半径 18、点中心距 **67.9**（< 弧内径 73） |
| P2b | `negative` | 两圆圆心距 **d=86**、咬口 r=42、孩子 r=26 → 相接夹角 **59°** |

同一个 `line`，弧扫 270° 是「被托住」，扫 300° 就变成「勒住」；同一个 `negative`，d=86 是被啃开，两圆相切（13°）是刀口。

**所以轴表不能直接交给渲染器当参数用。** 轴的职责是选型，参数的职责是 `logo-design` 的构造阶段。交接时必须把参数的**意图**带过去（「开口要能托住那颗点」），不能只传 `figure_ground=line`。

### 2.2 元素关系

A1 的琥珀点为什么不能随便放？因为它必须落在**开口的角平分线**上（225°），且中心距小于弧内径。偏离这条线，语义立刻从「被养育」变成「卫星绕行」——这正是那次「审美回退」的根因。

这类关系不在任何轴上，已单列为 `axes.json` → `relations` 的四项不变量（锚定 / 过渡 / 层级 / 呼吸）。

**结论 2：轴表 + 关系不变量，才是完整的发散约束。只有轴表会产出「坐标对、看着不对」的稿子。**

## 三、盲测推演：A1 能被走到吗

按六站走一遍，不看结果倒推：

| 站 | 实际取值 | A1 是否在候选空间内 |
|---|---|---|
| 0 名片 | 给园长买、老师用、家长感知；解决家园共育的记录与沟通 | — |
| 1 气质 | warm「像被照顾」+ solid「站得住」；geometric-sans | ✅ |
| 2 意象 | 「一个圆，边上开一道口，口里有一颗东西」 | ✅ |
| 3 类型 | 5 类试穿 → 留 combination、abstract | ✅ |
| 4.1 构造 | `figure_ground` × `geometry` = 3 × 2 = 6 | ✅（`line × circle` 在列） |
| 4.2 | `literalness` × `symmetry` = metaphor × asymmetric | ✅ |
| 4.3 | `container` = none | ✅ |

**A1 能被生成。** 前提是 4.1 那一轮真的把 `line` 摆出来了。

**但 A1 不一定被选中。** 真实历史是：先选 P2（`negative`），两轮之后才回退到 A1（`line`）。

**结论 3：工程负责让 A1 出现在选项里；选不选它，取决于判断在时间上是否稳定。因此「回退」必须是流程的一等公民，不是异常分支。**

## 四、这次回退暴露的产品问题

回退发生在「已经收敛到 P2b、并做了尖角钝化之后」。也就是说，用户在两轮构造工作之后才意识到：「我要的是被养育，不是破壳。」

这说明**卡片当时只给了形，没给义**。如果 4.1 的六张卡各带一句语义：

| 卡 | 一句话 |
|---|---|
| `line` | 一条线围出空间，里面留出位置 |
| `negative` | 从实体里挖掉一块，露出里面的东西 |
| `solid` | 一整块，边界清楚 |

用户很可能第一轮就选 `line`——因为他要的是「养育」，而「破壳」是另一个故事。

## 六、轴表的已知缺口

| 缺什么 | 影响 | 补法 |
|---|---|---|
| 开口角度 / 扫过角 | 决定「托住」还是「勒住」 | 进 `relations`，作为锚定参数的约束 |
| 线宽 | 决定 16px 存活 | 进站 5 体检，不进轴表 |
| 色彩 | 影响气质但不影响构造 | 站 5 之后单独一轮 |
| 字体授权 | 硬约束，不是选项 | 站 1 之前先过滤 |
| 元素数 | 影响复杂度，但是结果不是选择 | 作为验收指标 |

## 七、0.1.0 轴表校验（同日执行）

纸面推演之外，先做了一次**结构性校验**：`axes.json` 的每条取值是不是真的指认得出来。

```bash
python -I scripts/validate_axes.py
```

**首轮结果：47 条取值里 13 条不成立。**

| 轴取值 | 被指认的作品 | 库里的真实 mood |
|---|---|---|
| `mood.warm` | `ello.svg` | friendly, minimal |
| `mood.clean` | `patreon.svg` | bold, minimal |
| `mood.solid` | `bluetooth.svg` | technical, trustworthy |
| `mood.calm` | `squarespace.svg` | bold, elegant |
| `mood.fresh` | `processwire.svg` | fluid, friendly |

**根因不是缺库，是挑法。** `warm` 在库里有 59 个、`solid` 86 个、`playful` 159 个——取值本身都成立，是 exemplar 凭印象手挑，和 filter 打架。

这恰好踩中 SKILL.md 自己写的硬规则：「指认不出来的取值不许进表」。**规则写在文档里不等于会被执行**，所以补了一个脚本把 exemplar 从 filter 推出来：

```bash
python -I scripts/suggest_exemplars.py --axis mood
```

排序偏好是「能不能学构造」而不是好看：`exemplary` 优先、无渐变、颜色少、锚点少；符号类偏方形画幅，字标类偏横排。

重建后 **47/47 通过**。同时把 `mood.precise` 改名为 `mood.technical`——它的 filter 一直是 `mood: technical`，id 和谓词对不上，库里 394 个命中全被 `precise` 这个名字挡住了。

### 顺带暴露的第二个缺口：中文品牌

站 1 要求「同名试排」，但库里 1432 个样本**没有一个中文字标**，8 个 `type_style` 对中文全部空转。已补 `references/zh-type.md`：只有思源黑体 / 思源宋体可商用，8 张卡改用 `mood × 字重`，实际只有 5 种能落地。

这不是可以凑数的地方——凑出来的 3 张会让用户在一个不存在的选项里做决定。
