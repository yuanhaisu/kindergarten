# 回归用例 02 · Airbnb

**目的**：验证轴表能不能表达一个与养成星球无关的行业。
**为什么选它**：出行住宿（无关行业）；双边平台（房东 + 房客），与家园共育的结构同形，便于对照；标志在库中，元数据可作第三方 ground truth。

**方法上的一个约束**：坐标不靠我的记忆，全部取自 `catalog.json`。该文件在建立本 skill 之前就已存在，**不是从答案反推的**——这是这次试跑唯一能压住后见之明的办法。

---

## 一、库给出的 ground truth

```json
mark_type : abstract
subject   : "Belo loop merging pin, heart and A"
geometry  : organic
techniques: line-monoline, hidden-meaning, mirror-symmetry
mood      : friendly, warm
shapes    : 2   anchors: 73   n_colors: 1
```

核对源文件：`airbnb.svg` 里**只有一个闭合路径**（`M238.041 223.123 C…`），另一个 `shapes` 是背景矩形。也就是说，Bélo 是**一笔画完的等宽带子**，不是描边，也不是多块拼合。

## 二、轴坐标

| 轴 | Airbnb | 养成星球 A1 | 关系 |
|---|---|---|---|
| `mark_type` | abstract | combination | **不同** |
| `mood` | warm + friendly | warm + solid | 部分重叠 |
| `type_style` | —（纯符号） | geometric-sans | — |
| `literalness` | metaphor（三读） | metaphor（单读） | 深度不同 |

| `figure_ground` | line（等宽带） | line（等宽弧） | 同 |
| `symmetry` | mirror | asymmetric | **不同** |
| `container` | none | none | 同 |

**8 轴上 3 轴可区分**，比用例 01（1 轴）更有信息量。

## 三、盲走六站：Bélo 在候选空间内吗

按 brief 走，不看结果倒推：

| 站 | 取值 |
|---|---|
| 0 名片 | 房东 + 房客，全球；解决「住进陌生人的家」 |
| 1 气质 | warm「像被欢迎」+ fresh「轻、能走」 |
| 2 意象 | 门 / 钥匙 / 心 / 定位针 / 拥抱 / 字母 A |
| 3 类型 | 符号为主，锁图为组合 |
| 4 构造 | metaphor × organic × line × mirror × none |

**在。** 而且这次不需要靠「覆盖每个取值」的硬规则来救——`organic` 和 `mirror` 都不是「看起来不完整」的那一档，它们会自然出现。

但同一格里可以塞进成千上万个形。**Bélo 不是被轴表推出来的，是被意象句推出来的。**

---

## 四、三个 schema 缺陷

### 缺陷 1：`mark_type` 混装了两个问题

| 标的 | 符号类型 | 锁图类型 |
|---|---|---|
| Airbnb | abstract | 符号 + 字标（组合） |
| A1 | 抽象线形 | 符号 + 中文名（组合） |

「这个标志是什么类型」实际上有两问：**符号怎么画**、**锁图怎么排**。两例都踩中，不是偶发。

→ 建议拆成 `lockup`（symbol / combination / stacked / wordmark）+ `symbol_type`。

### 缺陷 2：`figure_ground` 把「看起来」和「造出来的」混在一起

Bélo **视觉上是实心色块**，库里却标 `line-monoline`——因为它是一条等宽带子，不是描边，也不是多块拼合。

我的轴问的是「墨和空谁是主体」（视觉），库的 tag 回答的是「怎么造出来的」（构造）。同一个词两个意思，筛选和描述会对不上。

→ 建议拆成：
- `figure_ground`：solid / negative / outline（**视觉**）
- `construction`：等宽带 / 实心块 / 变宽笔画（**构造**）

### 缺陷 3：缺「元素数 / 笔画连续性」

三个样本刚好是 1 / 2 / 3：

| 标志 | 元素数 | 连续性 |
|---|---|---|
| Airbnb Bélo | 1 | 一笔闭合 |
| A1 | 2 | 弧 + 点，断开 |
| P2b | 3 | 盘 + 咬口 + 孩子，层叠 |

这不是巧合。它直接决定「看起来是一个东西还是几个东西」，也直接决定 16px 存活率——而 16px 是站 5 的头号指标，却在站 4 没有任何对应的选择。

→ 建议新增 `element_count`：1 / 2 / 3+。

---

## 五、一条新规则：意象句必须可构造

Bélo 对应的句子不是「一颗心被拉成房子」，而是：

> 一条线，从左边出发，绕成 A 的左腿，折回来抱住一颗心，再绕成右腿——全程不断开。

差别在于**句子有没有说「怎么连起来」**。

| 句子类型 | 例子 | 能不能直接构造 |
|---|---|---|
| 像什么 | 「一颗心被拉成房子」 | ❌ |
| 怎么连 | 「一条线绕成 A，中途抱住心」 | ✅ |

用例 01 没暴露这条，因为 A1 和 P2b 的句子本来就是可构造的（圆 + 开口 + 点 / 圆 + 挖掉 + 圆）。

→ 站 2 补硬规则：**意象句必须能翻译成「基本形 + 位置关系 + 连接方式」**。翻不出来就退回重写。

## 六、第二例的结论

**轴表是必要条件，不是充分条件。**

| 用例 | 判别轴数 | 能否推出具体形 |
|---|---|---|
| 01 养成星球 | 1 / 8 | 否——形来自「点落在开口角平分线」这个关系 |
| 02 Airbnb | 3 / 8 | 否——形来自「一笔不断」这个构造约束 |

所以这个工程的正确定位不是**生成器**，是**排除器**：

> 它保证选项空间里一定包含你需要的那个方向，并保证不会因为「看起来不够完整」而漏掉；它不负责替你画出那个形。

这与用例 01 的结论一致，但这次是独立验证的——不是同一条结论换个说法。

## 七、对轴表的修改建议（待批准）

| 改动 | 理由 | 影响 |
|---|---|---|
| 拆 `mark_type` → `lockup` + `symbol_type` | 两例都混装 | 站 3 卡片分两行 |
| 拆 `figure_ground` → `figure_ground` + `construction` | Bélo 一例即暴露 | 站 4 增一条轴 |
| 新增 `element_count` | 1 / 2 / 3 刚好覆盖三样本 | 站 4 增一条轴 |
| 站 2 加「可构造」硬规则 | Bélo 的句子类型 | 改一句话术 |

改完轴数 8 → 10（旧的 `mark_type` 拆成两条，`figure_ground` 拆成两条，再加 `element_count`）。

**先不改。** 单例改动轴表是用例 01 已经踩过的坑——等第三例确认这三处是通病，再一起动。
