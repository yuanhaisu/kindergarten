# 盲测 02 · 新版站 3（3 类型）

**目的**：在「站 3 从 5 列改成 3 类」之后重跑一遍，看新布局是否更好用。

---

## ⚠️ 结论先行：这是流程测试，不是偏好测试

**已确认：与盲测 01 是同一个人，同一天。**

他当天已经看过同样的 8 张气质卡、同样的 15 句话、同样的站 3 页面。
因此本轮记录的**偏好数据全部受记忆锚定影响**，不能用来证明任何关于「工具稳定性」
或「偏好一致性」的结论。

**这一轮唯一有效的成果是流程与规则层面的：**

1. 15 句都有示意之后，站 2 → 站 3 不再断供
2. 站 3 的「至少跨 2 种类型」在 3 类布局下太紧，连拦两次
3. 破例机制（`--allow-single-type` + 强制写理由）可用

下文的路径数据只作记录，**不作证据**。

## 二、站 3 被拦了两次

### 第一次：只给了一格

```
❌ 站 3 必须选 2–3 格，你选了 1 格
```

按设计追问「除了这个还有哪个你能接受」，他补了一格。

### 第二次：两格都是「组合」

```
❌ 都在同一种类型里，那样没有在比较类型。
   组合：S01、S04
```

**这条规则在 3 类型布局下太紧了。**

原规则是为 5 列写的：那时从同一列选 3 张，确实等于没比较类型。
但现在每行只有两个形态，「两个都是组合」的真实含义是：

> **我要组合形态，并且 S01 比 S04 好。**

这是一个完整答案。逼他补一个「符号」等于制造一个他并不持有的偏好。

### 处理：加了破例开关

```bash
python -I scripts/narrow.py --station 3 --pick S01-combination,S04-combination \
  --allow-single-type "他两次都给组合，未再补不同类型的格子"
```

- 不加开关，规则照旧拦
- 加了必须写理由，理由进 `brief.md`：`- **破例**：只有一种类型（组合）：…`
- 与 `station3.cut` 同一套思路：**可以破例，但破例要留名**

### 建议的规则改法（待定）

> 站 3 允许同类型，但要求**至少跨 2 个不同的想法**，而不是 2 种类型。

因为「两个都是组合，一个 S01 一个 S04」确实做了比较——比的是想法，不是类型。
这条要等第三例盲测确认后再改，单例改动规则是用例 01 已经踩过的坑。

## 三、跨版本重合：作废

| 轮次 | 布局 | 站 3 首选 |
|---|---|---|
| 盲测 01（去名版） | 5 列 | S01-combination |
| 盲测 02 | 3 类 | S01-combination |

两轮选出同一格——但**同一个人、同一天、同一批材料**，这只能说明他记得上次的答案。

**这条不构成工具稳定性的证据。** 要验证稳定性，必须换一个没参与过的人跑同一布局，
或同一个人隔足够久重跑。

同理，站 1 的 2/4 重合、站 2 的 1/5 重合，也都不能解读。

> 这一条本来是本轮最有价值的候选发现。因为它依赖一个我没在开跑前确认的事实，
> 现在整条作废。**测试者身份必须在开跑前记录，而不是事后补。**
