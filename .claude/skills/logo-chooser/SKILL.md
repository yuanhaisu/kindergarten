# Logo Chooser

## 一句话

**不要让没有设计能力的人描述想要什么，让他指认哪个不对。**
前者是生成，他做不到；后者是辨别，不需要会设计也能做。

## 这个工具不能让你独立完成

它把专家从「画 logo」挪到了两处，但没有取消专家：

| 谁做 | 做什么 | 一次要多久 |
|---|---|---|
| **你（不需要会设计）** | 指认：哪几张、哪几句、哪几格不对 | 未计时（唯一数据：三站合计约 70 分钟，含等待） |
| **AI（或会写会画的人）** | 写站 2 的 15 句意象；画站 3 的示意图；画站 4 的黑稿 | 每个品牌 1–2 小时 |

**站 2 是断供点。** 15 句「这是一个 ___」不能由脚本生成——脚本不认识你的行业，
生成出来的只会是「成长 / 温暖 / 未来」这类画不出来的东西。

**站 3 同理。** 示意要从句子变成形，那是构造，不是选型。

还有一个容易被忽略的成本：**示意是按句画的**。站 2 有 15 个选项，但只有已经画过的那些
才能进站 3。选了三句没画过的，就得先补三张（每句 1–2 张）。

**站 2 的代价比看起来大。** 2026-11-09 盲测 01 里，没参与过的测试者把三站排了序：
最难的是站 2，理由不是「选不出来」，而是**「每一句都要在脑子里构造形状」**。
15 句 = 15 次脑内建模。站 1 和站 3 是「看」，站 2 是「想」。

同一轮的第三条回答更值得记住：「我也是凭感觉的」——他能点、能坚持，但说不清自己选了什么。
**可能是「指认成功、决策没有发生」**，但这是**假设不是结论**：n=1，而且设计师同样凭感觉做判断，
「必须能说清理由」这条标准本身未经验证。详见 `EVIDENCE.md` §2.4。

所以正确的期待是：

- 你仍然需要一个会写、会画的人（或 AI）陪你走前两站的**生产**环节
- 但**每一个判断都由你做**，而且你不需要会画一笔
- 工具负责：不漏选项、不重复、记清每一次改选与过期

开工前先跑一次自检，别走到站 2 才发现缺料：

```bash
python -I scripts/preflight.py --brand 养成星球
```

## 何时用

- 用户说「说不上来哪里怪」「都不太对」「再来几个看看」
- 用户不是设计师，但要做购买决定
- 已经有一批方向，需要收敛到一个
- 用户选过一次又退回来了

**不用**：用户能明确说出需求（直接走 `logo-design`）；或需要的是完整品牌系统而非单个标识。

## 与 logo-design 的分工

| 阶段 | 谁做 |
|---|---|
| 定位 / 转译 / 选型 / 收敛 | **本 skill** |
| 几何构造、曲线质量、光学校正 | `logo-design` 的 Phase 4–5 |
| 16px / 单色 / 反白 / 货架测试 | `logo-design` 的脚本，本 skill 的第 5 站调用 |
| 出 kit | `logo-design` 的 `export_variants.py` |

本 skill **不生产几何**，只决定「下一批该往哪个方向做」。

## 六站固定路径

| 站 | 发散物 | 收敛 | 硬规则 |
|---|---|---|---|
| 0 名片 | — | — | 一句话必须含「给谁」和「解决什么」 |
| 1 气质 | 同名试排 8 张 | 留 2–3 | 不能全在同一（字族 × 重量档） |
| 2 意象 | 5 词 × 3 具象 = 15 句 | 留 3 | 每句 ≤20 字，形/位/连三段齐全，三句来自 ≥2 个词 |
| 3 类型 | 3 句 × 2 形态 + 1 张全局字标 = 7 格 | 留 2–3 格 | 标 16px 存活率与文字依赖度；选格子不选整列 |
| 4 构造 | 沿轴窄化，每轮 4–9 个黑稿 | 留 3 | 每轮只动 1–2 条轴；层级/呼吸实测，锚定/过渡人工核对 |
| 5 验收 | 自动体检（4 项实测 + 2 项人工） | — | 未过项必须修，不参与「挑」 |

详细话术、卡片规格、记录格式见 `references/station-path.md`。

## 发散引擎

轴表在 `axes.json`，共 8 条：

`mark_type` `mood` `type_style` `literalness` `geometry` `figure_ground` `symmetry` `container`

三条硬约束：

1. **每个取值必须挂 3 个真实 exemplar**，指认不出来的取值不许进表（`validate_axes.py` 强制）
2. **不做全笛卡尔积**——贪心窄化，每轮只动上一轮没定过的 1–2 条轴（站 4 未实现，尚未强制执行）
3. **exemplar 只用来学构造**，不用来对行业气质（库里 1432 个样本偏科技/软件，直接照抄会跑偏）

另有一条比上面三条更致命的，在 `divergence_rules.coverage`：

> **每条轴的每个取值，至少要在候选里出现一次。**
> 缺一个取值，正确答案就可能根本不在桌上——A1 是 `figure_ground=line`，只出实心版它就永远进不来。

这条现在由 `coverage_check.py` 强制：`typeset.py` / `matrix.py` / `narrow.py` 出图前都会调用，
缺一个取值直接退出。裁掉某个取值可以，但必须在 `axes.json` 里申报理由（`station3.cut`），
否则按「未申报缺失」处理。

**但逐站检查不等于路径检查。** `coverage_check` 只管当时传进去的那条轴。站 4 的一轮声明
`geometry: [circle, square]` 也能通过它——另外 6 个取值永远不会出现，却没有一条断言会响。
2026-11-10 实测：全路径 47 个取值只出现 20 个，22 个无声缺失。

全路径由 `coverage_path.py` 兜底：把站 1 / 站 3 / 站 4 实际摆出来的取值并起来对轴表，
缺一个就退出；裁掉必须在 `axes.json → path_cut` 申报理由。`preflight` 报告待办，
`audit.py` 在站 5 硬判——**站 4 收口后，缺一个取值就过不了验收**。

`divergence_rules` 每条都带 `enforced_by` 字段：写明由哪个脚本执行，或者 `null` 表示还没执行。
**没有代码执行的规则不许写成已执行。**

## 轴表测不到的东西

轴描述的是**单个取值**，测不到**元素之间的关系**。这四项必须单独校验，否则会产出「坐标对、看着不对」的稿子：

| 不变量 | 规则 |
|---|---|
| 锚定 | 附属元素必须落在主元素的半径 / 切线 / 角平分线上 |
| 过渡 | 两形相接处夹角 ≥ 45°；≤30° 会被读成刀口 |
| 层级 | 主元素面积 ≥ 次元素 3 倍 |
| 呼吸 | 分离元素最小间隙 ≥ 主元素短边 1/12 |

来源与实测数据见 `axes.json` → `relations`。

## 记录与失效

`picks.json` 是唯一真相源，`brief.md` 由它派生（每次记录整篇重写，不追加）。

依赖关系是**显式登记**的，不是"所有下游都失效"：

```
站 1 ──┐
       ├──> 站 3
站 2 ──┘
```

改站 1 不会让站 2 失效（站 2 选的是句子，与字重无关），但会让站 3 失效。登记在 `scripts/picks.py → DEPENDS_ON`，新增站时必须补。

三种状态：

| 状态 | 含义 | 怎么出现的 |
|---|---|---|
| `active` | 当前有效 | 刚记录的那次 |
| `superseded` | 同站有更晚的选择 | 同站再选一次 |
| `stale` | 上游改过，结论不再成立 | 它依赖的站被重选 |

被标 `stale` 的记录**保留在 brief.md 里并带警告**，不会消失——但也绝不会被当成有效结论。
`matrix.py` 只读 `active` 的站 2 记录；全被标脏时会拒绝出图，要求先重选。

### 回退

```bash
python -I scripts/narrow.py --station 1 --restore 2   # 把站 1 的第 2 次恢复为当前
```

回退**不重新生成、不追问**，只是把状态翻回来；被它标记过期的下游会重新变成 `stale`。

恢复一条结论前会核对它当时依据的上游版本（`based_on`，存的是单调序号 `seq`）：

```
❌ 站 1 当前有效的是 2026-11-08 21:42（#1），而这条结论是按 #2 的站 1 得出的。
   直接恢复会得到一个自相矛盾的记录。先恢复站 1，或重做站 3。
```

> ⚠️ 版本标识必须用 `seq` 而不是时间戳。实测踩过：同一秒内连续做三次选择，
> 秒级时间戳全部相同，`based_on` 比对永远通过——守卫形同虚设。

没有 `based_on` 的老记录，只要该站有依赖就拒绝恢复（无法判断是否还成立），要求重做。

## 四个失败模式

1. **指认 ≠ 想要**。选「看起来专业」的那张，常常是怕选错。
   → 每张卡必须带一句「它意味着什么」；强制选 2 张以上不同分支。
2. **指认会漂移**。用户先选 A，两轮后回到 A 的前一版。
   → **回退是一等操作**：每站留历史，回退不丢上下文，不回退到第一站。
3. **轴表会僵化**。8 条轴是归纳，不是真理。
   → 没有 exemplar 的轴不许进表；每完成一个真实项目就复核一次轴表。
4. **规则会空转**。站 1 写「必须来自 2 个不同 mood 分支」、站 2 写「必须是 3 个不同物件」——两条都永远成立，因为每张卡本来就是一个 mood、每个物件本来就不重名。
   → 写校验前先举一个**它真的会拦下的例子**。举不出来，这条规则就是装饰，写进文档反而给人已经防住了的错觉。

## 工具

| 脚本 | 用途 | 何时跑 |
|---|---|---|
| `scripts/validate_axes.py` | 校验每条轴取值都有 3 个真实 exemplar，且元数据与 filter 一致 | 改完 `axes.json` 必跑 |
| `scripts/suggest_exemplars.py` | 按 filter 从库里筛候选 exemplar，替代手挑 | 新增取值、或校验失败时 |
| `scripts/typeset.py` | **站 1 同名试排**：按 `mood × 字重` 排 8 张可点选的卡 → `runs/<品牌>/round-1.html` | 站 1 开始时 |
| `scripts/draft.py` | **站 2 渲染**：校验 15 句意象（长度 / 抽象词 / 形位连），出可点选的卡片页 | 词库写完之后 |
| `scripts/matrix.py` | **站 3 渲染**：3 句 × 5 类型矩阵，读 `sketches/` 里的示意 | 3 张示意画完之后 |
| `scripts/coverage_check.py` | **站内覆盖断言**：这一站摆出来的取值必须齐，缺一个就退出 | 渲染前自动调用；也可单独审计 |
| `scripts/coverage_path.py` | **全路径覆盖断言**：站 1 / 3 / 4 并起来对轴表，缺一个就退出；`path_cut` 里申报过的除外 | `preflight` 报待办、`audit.py` 硬闸；也可单独跑 |
| `scripts/preflight.py` | **开工自检**：字体 / 词库 / 示意图齐不齐，缺什么一次说清 | 开工前 |
| `scripts/survive.py` | **16px 存活率实测**：符号缩到 16×16，与 96×96 二值图比连通块 / 洞 / 墨占比 | 站 3 渲染时自动调用；也可单独测任意 SVG |
| `scripts/construct.py` | **站 4 构造**：按本轮声明的轴校验覆盖，量层级 / 呼吸 / 元素数，出黑稿网格 | 每轮稿子画完之后 |
| `scripts/audit.py` | **站 5 验收**：16px / 纯黑 / 反白 / 禁用元素 四项实测，货架与「一句话」标人工 → `audit.md` | 站 4 收敛之后 |

站 3 的两个徽章不再是按类型写死的常量。`16px` 是逐格量出来的，鼠标悬停能看到三行数据
（16px 与 96px 各自的墨占比、块数、洞数，以及不过项的原因）。含文字的格子标「不适用」——
16px 上文字本来就不可读，编一个「低」不如说「测不了」。
| `scripts/narrow.py` | **站 1 / 2 / 3 收敛**：记录指认结果并校验是否塌缩成一个想法 → `brief.md` + `picks.json` | 用户选完之后 |

```bash
python -I scripts/validate_axes.py
python -I scripts/suggest_exemplars.py --axis mood
python -I scripts/typeset.py --brand 养成星球
python -I scripts/narrow.py --pick 04,05 --note "沉静像园长看的样子"

python -I scripts/draft.py --brand 养成星球
python -I scripts/narrow.py --station 2 --pick S01,S07,S12

python -I scripts/matrix.py --brand 养成星球            # 默认读站 2 的选择
python -I scripts/narrow.py --station 3 --pick S07-pictorial,S07-combination

python -I scripts/construct.py --brand 养成星球 --round 4.1
python -I scripts/narrow.py --station 4 --pick d1,d3,d4

python -I scripts/audit.py --brand 养成星球      # 默认读站 4 的选择

python -I scripts/narrow.py --station 1 --restore 1   # 回退到该站第 1 次，不重选
```

**站 2 的 15 句不由脚本生成。** 词库（`runs/<品牌>/words.json`）由人写或 AI 写，脚本只做两件事：把不合格的句子挡在门外，以及记录指认结果。这是整个工程的分工——**人负责创作，机器负责让不合格的东西进不来**。

站 1 的闭环是：**打开 `round-1.html` 点卡片 → 复制底部编号 → 交给 `narrow.py`**。页面不需要服务器，`file://` 直接打开就能用。

`typeset.py` 的 8 张卡读 `axes.json → zh.station1_cards`，不读 `zh-type.md`——文档只是说明，配置才是真相源。输出的名字全部轮廓化（没有 `<text>`），固定画布高度保证 8 张卡字号一致，先按墨迹面积做等面积校正再按等墨迹间隙排版。

**exemplar 必须由 filter 推导，不能凭印象挑。** 首轮校验就抓到 13 处「mood 写 warm、作品实际是 bold」——手挑的 exemplar 会和谓词打架，轴表就失效了。

## 中文品牌

库内 1432 个样本没有一个中文字标，站 1 的 `type_style` 会空转。走法见 `references/zh-type.md`：

- 只有**思源黑体 / 思源宋体**两个字族可商用（其余中文字体不得用于标识）
- 8 张卡用 `mood × 字重` 组合，实际只有 5 种试排能真落地，**不要凑数**
- 站 1 只定气质方向，中文字标的真正差异在站 4 的结构改装

## 验收标准

> ⚠️ **这条标准还没有被真正执行过。**
> 下面列的 01–04 都是**纸面推演**：把已知答案拆成轴坐标去核对，不是让人从零走六站。
> 两者差很多——前者我造的表当然能表达我造的答案（见 `EVIDENCE.md` §2.3）。
> 真跑过的只有养成星球，而它同时是校准集，不能当留出集用。

拿一个**已经定稿**的品牌做回归：把定稿从候选池移除，走完六站，看是否落在它的邻域。

- 落在同轴邻域 → 轴表有效
- 落在不相干处 → 卡片不是按轴生成的，重做
- 找不到 → 轴表缺一条轴，补

回归用例：

- 01 `trials/2026-11-07-nurture-planet.md` — 中文、幼教；8 轴中 1 轴判别
- 02 `trials/2026-11-07-airbnb.md` — 英文、出行；8 轴中 3 轴判别，暴露 3 处 schema 缺陷
- 03 `trials/2026-11-09-blind-run-1.md` — **第一个外部样本**；站 2 是认知瓶颈、覆盖够、指认≠决策；暴露 `_holes()` 计数 bug
- 04 `trials/2026-11-09-blind-run-2.md` — 新版 3 类型站 3；**与 01 同一人同日，偏好数据作废**；唯流程结论：站 3 规则「同类型」太紧、破例机制可用
