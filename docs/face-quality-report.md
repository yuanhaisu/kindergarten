> 变更：`photo-tagging-face-recognition` 任务 1.3。供应商：腾讯云 IAI（`SearchFaces`）。
> 实测数据：28 张照片（`assets/face-img/`，含儿童照片的样本目录已 gitignore，不入库）。
> 报告只记编号与分数，不含姓名与可识别信息。
>
> **状态：初测（样本不完整，结论仅作线索）**。经与产品确认：本样本不足以支撑设计决策，
> **项目按「人脸识别能力满足要求」的前提继续推进**（阈值分级 + 预勾照常实现，
> 阈值配置化）。本文档中的观察记录待真实场景（活动合影、标注数据）充分后复审；
> 若彼时证实分数重叠，调整仅涉及阈值配置，不改代码与交互架构。

## 一、样本

| 项 | 值 |
|---|---|

## 二、结果

### 2.1 同图自匹配（注册该图 → 搜索该图）

```
28/28 命中自身   score 全部 = 100.00   零混淆
```

管线正确性验证通过：底库注册（CreatePerson）、1:N 搜索（SearchFaces）、人员识别映射全链路无误。

### 2.2 跨图次高分人工核对（本报告的关键部分）

搜索时每图返回 Top3；对「第二位分数 > 40」的 6 组做了人工目检：

| 组 | 关系（人工判定） | 分数 |
|---|---|---|
| #12 / #22 | **同一孩子**（眼镜男孩，两种场景） | 42.33 |
| #1 / #4 | **同一孩子**（女孩，两张自拍） | 43.42 |
| #18 / #24 | **同一孩子**（男孩，发型不同） | 52.25 |
| #13 / #14 / #17 | **同一孩子**（三张） | 54.80 / 57.27 |
| #21 / #23 | **不同孩子**（男/女） | 50.70 ← **误报** |
| #2 / #6 等其余对 | 不同孩子 | 24 ~ 38 |

### 2.3 分数量级

| | 区间 |
|---|---|
| 同人 · 同图 | 100 |
| 同人 · 跨图 | **42 ~ 57**（另有一组 50.7 未定论，见局限 1） |
| 异人 · 跨图 | 24 ~ 50.7 |

## 三、观察（初测线索，待充分数据验证）

**观察 1：本样本中同人跨图分与异人分出现重叠。**
最低的「同人跨图」分（42.33）**低于**最高的「异人」分（50.70）。**但本样本量小、
无标注、且全部为证件照缩略图——不足以据此下结论**。若后续真实场景数据证实此重叠：

- 阈值分级（预勾）需要重校甚至退化为纯候选排序；
- 由于阈值是配置项，调整不涉及代码改动。

**观察 2：方向性排序在本样本中是有效的。** 28 张里所有真匹配（含跨图同人）全部
排在第一位。此观察支持「候选排序天然可用」，但同样待充分数据验证。

**观察 3：同图自匹配 100 分且零混淆** —— 管线正确性的证据，与阈值设计无关，结论稳定。

## 四、测量局限（必须知道，且决定下一步）

1. **无 ground truth**：同/异判定依赖 6 组目检；#13/#14/#17 一组存在误判风险（若其中含不同孩子，同人分上限会下移，结论只会更差）
2. **样本是证件照缩略图**（126-192px）：真实场景是 OSS 的 200px 缩略图与更大图——本测试与生产输入分辨率相近，但**构图不同**
3. **未测真实场景核心用例**：**活动合影中的小脸/远脸**（孩子跑动、侧脸、光照变化）对证件照底库的匹配——这是生产里最主流的输入，**本测试完全未覆盖**
4. 底库规模 28 人；官方阈值文档基于 1 万人底库，小库的分数分布本就不适用

## 五、对后续实现的约束（已反映到 design.md 修订）

| 原设计 | 修订为 |
|---|---|
| D6 置信度分级 + 高置信预勾 | **候选排序展示（Top-N）+ 老师逐项确认/拒绝**；无预勾、无置信度显示 |
| `[face].suggest_high=80 / suggest_low=70` | 起始 `suggest_low=35`（候选护栏下限）；`suggest_high` 保留配置但当前不触发任何自动行为 |
| — | **生产启用前置**：上线前必须补一次「真实活动合影 → 证件照底库」的标注实测（≥3 个班、含合影、人工标注），验证候选排序在真实场景是否有用 |
