# 0004 — 膳食模块以既有产品为交互与语义基线

- Status: Accepted
- Date: 2026-11-01

## Context

园所此前使用育健（oyujian）膳食管理，一线营养师/保健医已形成固定操作习惯：基本参数、网格周食谱、食物库、四张营养报表与结论文案。本次要在 admin 后台复刻带量食谱，若重新设计信息架构，迁移成本会落在这些使用者身上，且容易出现报表口径不一致。

## Decision

功能、字段名、页面结构、按钮文案、报表四表与结论话术以参考产品为基线；视觉层（颜色/间距/组件）按本项目 design token 重画。允许的偏离仅限：

- 供餐配置做成园所单例，不提供集体对象列表
- 菜谱库增加管理页（参考产品没有）
- 模板周由我们自建 2~4 套（参考产品是 12 套省级模板）
- 保存即生效，不做草稿箱
- 同一道菜内同一种食物自动合并克数
- 首版裁剪：餐后调查、膳食会议、月计划、采购清单、就餐人数、分析图、家长/老师端

## Consequences

后续维护者不应把「7 天 × 餐次的网格」「按钮叫这个名字」当作可优化点；任何进一步偏离需单独立项并更新本 ADR。参考产品是 JSP 多页应用，我们只对齐信息架构与行为，不对齐 DOM/技术栈。

## Alternatives considered

重新设计一套现代化膳食管理（信息架构更清晰、移动端优先）——被否。目标用户是既有园所，学习成本与报表口径风险高于设计收益。
