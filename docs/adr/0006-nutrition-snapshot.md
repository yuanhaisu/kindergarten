# 0006 — 周食谱明细在录入时固化营养快照

- Status: Accepted
- Date: 2026-11-01

## Context

营养分析基于「食物每 100g 可食部」的浓度值。如果报表实时 join 食物库，食物数据一旦修正，历史周食谱的营养结论会被改写；园所也可能修改预置食物。

## Decision

周食谱明细（`MealPlanItem`）在录入或从菜谱带出时，把该食物当次的 27 项营养浓度与食部写入快照字段；报表只用快照计算。菜谱库的 `RecipeItem` 只存食物 ID 与克数，不存营养快照。

## Consequences

- 历史报表稳定、可审计；食物库修正只影响新录入。
- 存储增加（27 个数值/行，一周约 200 行）。
- 若要「按最新食物数据重算历史」，必须走显式迁移，不做隐式重算。

## Alternatives considered

实时 join 计算：模型更规范，但历史报表会随食物库变更漂移，与老产品的行为不一致。
