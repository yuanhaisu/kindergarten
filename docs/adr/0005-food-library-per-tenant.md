# 0005 — 预置食物库按园所复制，不做全局共享 + 覆盖层

- Status: Accepted
- Date: 2026-11-01

## Context

平台预置约 1,700 条食物成分数据，园所需要修改食部/营养值、补充本地食材，且修改不能影响其他园所。项目现有惯例是所有业务表带 `kindergarten_id`。

## Decision

新园初始化时把平台预置库复制一份到该园（`Food` 表带 `kindergarten_id`），园所对副本增删改。平台数据升级用一次性同步命令按版本处理，不自动覆盖园所改过的行。

## Consequences

- 存储成本可忽略（1,700 条 × 27 个数值字段/园）。
- 数据升级需要逐园同步，且要区分「未改行」与「已改行」；升级命令必须显式处理这一差异。
- 查询简单，不需要合并全局层与覆盖层；多租户隔离与项目惯例一致。

## Alternatives considered

全局预置 + 园所覆盖层：存储省、升级统一，但每次查询都要合并两层，「修改内置项」的语义也变复杂。首版不采用。
