# 0010 — 幼儿媒体使用私有 OSS 桶 + 短期签名 URL

- Status: Accepted
- Date: 2026-11-03

## Context

成长相册与班级相册包含幼儿照片 / 视频。公共读桶意味着 URL 一旦外泄（转发、日志、Referer）任何人都能访问。项目已有 `PresignGet` 能力，但生产路径未使用。

## Decision

生产与预发 OSS 桶均为私有；媒体引用在数据库中以对象引用保存（新写入为 object key，历史完整 URL 由解析器兼容）；读取接口按需签发 1 小时有效的 GET URL；响应层 MUST NOT 直接下发数据库中的对象引用；小程序端遇到过期 URL 重新拉取；首期不启用 CDN。

## Consequences

- 读取路径需要签名，客户端需处理 URL 过期。
- 历史数据中的完整 OSS URL 仅作内部引用；解析器同时接受 object key 与完整 URL。
- `file_url` 等既有字段名保留，但新值语义为对象引用；字段重命名留作后续清理。
- 分享链接有时效；若未来需要长期外链，需另设受控分享机制。
- 引入 CDN 时必须支持回源签名。
- 相比公共读，增加少量签名计算与客户端重试逻辑。

## Alternatives considered

- **公共读 + 不可枚举 key**：实现最简单，但泄露即公开，不适合幼儿媒体。
- **私有桶 + CDN 回源签名**：更完整，但首期规模不需要 CDN。
- **长期有效签名 URL**：降低安全性，过期策略形同虚设。
