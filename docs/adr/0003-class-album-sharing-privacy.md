# 0003 — 班级相册的共享与隐私模型

- Status: Accepted
- Date: 2026-11-01

## Context

班级相册将承载未成年人影像，且现状有三处缺口：

- 班级相册当前仅老师可见，没有家长端接口；设计原意是家长可见。
- `allow_growth_share`（允许展示成长记录）与 `show_phone_to_teacher` 已存储但全代码无读取方，是死开关。
- 班级相册没有编辑/删除，照片也不关联幼儿；一旦家长可见，撤回同意、错图、合影都无法处理。

幼儿园的常见做法是「班内共享、园外谨慎」：家长默认接受孩子在班级相册中出现，但对外传播必须显式同意。

## Decision

采用「班内默认开、园外默认关、照片级过滤、整张隐藏」的模型：

- **两个共享开关**：`班内共享` 默认开（园所入学同意书覆盖，家长可撤回）；`园外分享/下载` 默认关（家长显式开启）。老师/园长按角色访问，不受家长开关影响。
- **双视图**：家长端默认「我的孩子」，园所可开启「全班」视图；MVP 先上「我的孩子」。
- **照片-幼儿混合关联**：从成长记录选的照片自动带出关联幼儿；新上传按批次选参与幼儿，可逐张微调。
- **撤回同意**：其他家长视图中，含该孩子的照片**整张隐藏**；该孩子自己的家长仍可见。不做人脸模糊。
- **发布流程**：草稿 → 预览 → 发布；支持编辑、下架、软删除；本班任一老师可操作并写审计日志，园长只读且可下架。
- **留存**：毕业后家长端只读保留 90 天、可导出；转园/退园立即失去访问；软删除保留 180 天审计。
- **媒体范围**：MVP 仅图片；视频、园外分享、全班视图、通知/周报留到 Phase 2。

## Consequences

- 需要新增：班级相册发布状态与审计、`album_photo_students` 关联、家长端班级相册接口、按孩子与同意状态的过滤。
- `allow_growth_share` 需要拆分/迁移为两个开关，并真正接入展示路径；`show_phone_to_teacher` 接入老师端联系方式。
- 现有班级相册照片需要回填参与者（至少相册级），否则「我的孩子」视图无法工作。
- opt-out 会导致含该孩子的合影对其他家长整张不可见；老师发布前需看到提示并可换图/调整参与者。
- 毕业后与软删需要定时清理任务；导出能力需在 90 天窗口内提供。

## Alternatives considered

- **单开关、默认关（严格 opt-in）**：隐私最稳，但班级相册会因少数未同意而几乎为空，老师上传动力低。
- **全班默认可见、opt-out 整册隐藏**：实现简单，但会因一个孩子让整本相册对其他家长消失，伤及全班。
- **人脸模糊/打码**：需要人脸检测与误模糊兜底，MVP 成本与风险都高。
- **发布需园长审核**：更严，但会成为日常发布瓶颈；先用审计日志与园长下架权替代。
