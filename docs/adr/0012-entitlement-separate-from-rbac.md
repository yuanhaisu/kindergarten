# 0012 — 授权与权限分离

- Status: Accepted
- Date: 2026-11-06

## Context

现有 Casbin 只做 `(role, path, method)` 的粗粒度放行，细粒度由管理端路由的权限码登记表承担；`kindergarten_app_setting` 承载的是运营规则（是否需审核、体温阈值），不是「园所买了哪些功能」。商业化需要另一条正交的判断：这个园所是否购买了某个功能模块。

## Decision

**权限**（账户能做什么，RBAC）与**授权**（园所买了什么，entitlement）分开建模。运行时两者都必须通过才放行；授权以「功能模块」为最小单位，二元开关，另加在园幼儿数上限，不做计量配额。

## Consequences

- 新增一层模块中间件与缓存；现有路由需要标注所属模块，默认全部归为 `base`，只把成长记录/相册/成长报告、膳食营养标为 `premium`。
- 前端需要拿到本园的模块清单来隐藏入口，但后端仍必须独立强校验。
- 管理端的权限树与商品目录互不影响，改套餐不会改权限。

## Alternatives considered

- **把套餐塞进 Casbin**：会让 RBAC 模型承担商业语义，权限树与商品目录互相污染，且 Casbin policy 是按角色而非按园所实例化的。
