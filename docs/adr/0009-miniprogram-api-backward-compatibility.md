# 0009 — 小程序 API 必须向后兼容最旧线上版本

- Status: Accepted
- Date: 2026-11-03

## Context

微信小程序正式发布受审核约束，用户升级不同步；服务端无法假设客户端已升级到最新版本。一次破坏性变更可能让仍在旧版本的用户直接报错，而服务端无法强制其更新。

## Decision

后端 API 以「向后兼容仍在线上运行的最旧小程序版本」为硬约束：

- 先加字段 / 接口，后删旧字段 / 接口；
- 破坏性语义变更拆两次发布：先兼容双写 / 双读，再清理；
- `backend/api/` 契约标注弃用时间与最低客户端版本；
- `/api/v1` 不因日常发布而升版。

## Consequences

- 功能交付可能多一个发布周期。
- 旧字段 / 旧表列需要保留到兼容窗口结束。
- 契约评审必须检查旧客户端兼容性，而不只是新客户端行为。
- 数据库清理迁移必须晚于所有线上客户端升级。

## Alternatives considered

- **强制升级**：微信不提供可靠手段。
- **每次破坏性变更升 `/api/v2`**：维护成本高，且旧版本仍需服务。
- **服务端与小程序同步发布**：审核周期不可控，不现实。
