# Feature Specs（功能规格目录）

## 工作流

```
讨论需求 → 写规格 → 用户确认 → 写代码 → 更新完成状态
```

1. **新功能**：在对话中讨论清楚需求后，先在此目录创建规格文件（命名 `YYYY-MM-DD-feature-name.md`），得到用户确认后再开始实现。
2. **实现完成后**：更新规格文件的状态为「已完成」，如有偏差在文件末尾备注。
3. **规格文件是事后回溯的锚点**：不是为了写文档而写文档，而是确保每次动手之前有一次明确的「设计确认」。
4. **关联 Skill**：如果某个 Skill（如 `growth-records`）覆盖了这个功能，在规格中注明。

## 规格文件模板

复制 `TEMPLATE.md`，填入以下内容：

- **背景与动机** — 为什么做、解决什么问题
- **数据模型** — 涉及的表/字段变更
- **API 设计** — 新增/修改的接口
- **前端交互** — 分端描述 UI 和用户操作
- **边界与异常** — 空状态、错误、权限、并发
- **验收标准** — 可操作的检查项
