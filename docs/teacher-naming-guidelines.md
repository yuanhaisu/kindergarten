# 老师拍照与点名规范（照片点名 / 人脸识别）

> 变更：`photo-tagging-face-recognition`（D11 大合影与全班一键）。
> 面向对象：**老师**（交付时随功能说明一并发送）。设计侧背景见 `docs/face-quality-report.md`。

## 一、为什么拍照方式会影响点名

照片点名决定「**哪些家长能在成长记录里看到这张照片**」。识别有两级：

1. **系统识别**（后台自动）：对每张照片做 1:N 人脸搜索，给出「这张照片里可能是谁」的建议；
2. **老师确认**（点名）：只有**确认过**的点名才真正生效。识别建议不确认 = 家长端不生效。

所以：照片拍得越好，系统建议越准；老师点名越全，越少家长漏看。

## 二、拍摄建议

| 建议 | 原因 |
|---|---|
| **尽量拍单人照**（一个画面一个孩子） | 单人照的识别最准，系统会给出可一键确认的建议 |
| 集体照/合影单独拍，不要和孩子特写混在一张里 | 合影走「一键全班」而不是逐人识别（见下） |
| 人脸尽量正、无遮挡（帽子、口罩、低头会显著降低识别率） | 识别基于人脸特征 |
| 避免逆光、过暗、剧烈运动模糊 | 同上 |

> 注意：识别**只认已录入底库的孩子**。班里还没录入人脸照片的孩子，任何照片都不会被自动建议——老师点名时按实际画面手动勾选即可（点名不依赖识别）。

## 三、点名：三种路径，用哪个？

| 场景 | 用什么 | 位置 |
|---|---|---|
| 一张照片里 1–5 个孩子 | **单张点名**：点照片角标 → 勾选 → 确定（AI 高置信建议已预勾，逐个核对） | 记录编辑页 / 详情页 |
| 同一次活动多张照片、孩子基本相同 | **批量点名**：批量选照片 → 选择学生（追加语义，不覆盖各自已有点名） | 记录编辑页 |
| **大合影 / 集体照** | **一键全班**（见下） | 详情页照片下方「大合影 · 一键全班」；编辑页面板内「全班（当日到场）」 |

## 四、大合影：一键「全班（当日到场）」

一张合影里有二三十个孩子，逐人确认注定不完整、也是白做的功——所以：

- 系统检测到人脸数达到阈值（默认 6）时，**不再产生逐人建议**，照片上直接出现「**大合影 · 一键全班（当日到场 N 人）**」入口；
- 一键点名 = **记录当天的到场学生**：
  - 当天**已批准请假**、或考勤被标记**缺勤/请假**的孩子**不会**被点上（家长已知道孩子没去，不算漏）；
  - 没有请假/考勤数据的日子，**按全员到场处理**——宁可多标，不让家长错过孩子的照片。

**「全班」是默认值，不是锁定**：拍合影时总有几个孩子跑出画面或背对镜头，老师可在点名面板里取消勾选他们，再确定。

## 五、常见问题

**Q：为什么这张合影没有任何「AI 建议」？**
A：全班活动的合影不产生逐人建议是设计如此（见上），用「一键全班」即可。注意：发给指定孩子的记录（个体记录）里的合影**会有**建议，且只会建议该记录的目标孩子。

**Q：家长说看不到孩子的照片？**
A：按顺序检查：① 这张照片有没有把该孩子点上（点名才是唯一依据）；② 该孩子是否当天请假/缺勤（一键全班会排除，需手动补点）；③ 家长端是否切到了「看全部照片」以外的视图（默认只看我的孩子）。

> 补充说明（家长视角）：集体照片与「孩子的照片」在家长端是同一栏里可解释的内容——家长默认栏看不到孩子被漏标的合影时，切一下「看全部照片」就能看到全部（含其他孩子的照片）。所以偶发的漏标不会让家长「看不到活动」，只会让那张照片不出现在默认筛选里。

**Q：改了点名需要重新发布吗？**
A：不需要。点名确认即时生效，家长端立即按最新点名筛选。
