## 与现状的差异

- **卡片收口**：源码是「作者卡 / 状态标签 / 正文卡 / 评论区」四段散块；原型把作者与当日状态并成一张卡、正文/标签/照片/互动并成一张卡，评论单独一张卡，减少卡中卡层级。
- **照片筛选选中态改用深色**：品牌橙只留给点赞与发送，避免一屏出现三处橙色主色块。
- **新增底部照片预览弹层**：源码 `uni.previewImage` 是系统查看器；原型用弹层模拟，带标题、「第 N 张 / 共 M 张」、关闭按钮，支持遮罩与 Esc；弹层内「上一张 / 下一张」、←/→ 键与左右滑动可在当前筛选结果内切图（对应源码传入的全量 `urls`），首尾张对应按钮禁用。
- **发送按钮空输入时显式降级**：源码空文本直接 `return`，界面无提示；原型让「不可发」这件事可见。
- **新增骨架与错误态**：源码只有一行「加载中...」，且 `loadData` 无 `catch`；原型按批次要求补整页错误卡与重试。
- **回复对象可见**：源码只 toast「回复 昵称」，输入栏写「回复中」；原型在输入栏上方常驻「回复中 · 昵称」+ 取消。
- **评论回复不跳页**：源码回复后重新拉列表；原型本地追加并 toast「评论成功」，保持页面位置。

## 遗留

1. **点赞不持久化（后端已知问题）**：`POST …/like` 返回 `is_liked=true`，但重新 `GET` 仍为 `false`（见 memory `parent-like-api-does-not-persist`）。原型只做本地态切换，**不代表已落库**；需后端修复后再验收「点赞后重进仍为已赞」。
2. **源码没有标题字段**：`detail` 无 `title`，页面「标题」实际由徽章 + 表现标签承担；若产品要标题，需先改 `backend/api/api-parent` 与 service。
3. **错误态是设计补充**：`loadData` 只有 `try/finally`，请求失败会停在空数据；原型按批次要求补了错误卡与「重试」。
4. **相关孩子未在本示例展示**：该块只在个体记录（`target_type=2`）出现，本示例是全班记录；不编数据，真实实现按源码条件渲染。
5. **评论计数口径不一致**：行动栏用 `detail.comments_count`（服务端口径，可能含子回复），标题用 `comments.length`（仅顶层）。原型统一为 4；若服务端把回复计入，落地时两处会跳数，需统一口径。
6. **子回复不计入顶层评论数**：原型发送子回复只追加节点、不 +1；真实接口以重新拉取结果为准。
7. **照片筛选空态不可达**：`media-empty`（默认视图没拍到自家孩子）结构已实现，本示例有 2 张点名照片，不会触发；真实实现需在无点名照片的数据下补验。
8. **评论无点赞/删除/置顶**：源码评论只有「回复」，原型严格照此，没有发明。
9. **预览弹层不是真实图片查看器**：只把同一占位渐变放大，支持左右切换（按钮 / ←→ 键 / 滑动）与首尾禁用，但不支持双指缩放。
10. **体积**：`styles.css` 19.9KB（未超 20480B 上限）、`app.js` 14.0KB、`index.html` 18.7KB。
