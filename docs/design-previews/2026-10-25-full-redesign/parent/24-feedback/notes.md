# 意见反馈（家长端）

- 源码：`parent/src/pages/feedback/index.vue`（`fetchFeedbackList` → `GET /parent/feedback`；`submitFeedback` → `POST /parent/feedback`，提交 `category / content`）
- 接口实现：`server/internal/service/parent_portal_service.go:2425-2464`（列表分页返回 `list / total / page / page_size`；`CreateFeedback` 只强校验 `content`，`category` 原样落库）
- 设计系统：`user:nurture-planet-local`，surface=parent
- 生成方式：OpenDesign（project `ec755006-a0e8-45db-baea-ea1f9485b5c1`，run `00823e99-afce-4541-8436-0b759787d433`，943s 成功）。交付前手工修正了四处：类型胶囊选中态失效（HTML 用 `data-category`，脚本读 `dataset.type`）、清空内容后未切到阻断态、成功标题的程序化焦点框、以及只为真正被三行截断的记录保留展开箭头
- 方向：**「一张便笺，回声可见」**——上半页是一张安静的表单便笺，下半页是同一条时间轴上的历史回声；必填缺失在按钮上方常驻说明，提交成功换成整页确认，而不是一闪而过的 toast。

## 信息层级

1. 微信外壳：20px 状态栏 + 44px 导航栏（返回箭头、标题「意见反馈」、右侧胶囊）；本页为 `navigateTo` 子页，无 tabBar
2. 反馈便笺（白卡）：`反馈类型` 三枚等宽胶囊（建议 / 投诉 / 问题，单选，默认建议）→ `反馈内容 · 必填` 多行输入 + 右下角 `32 / 500` → 一行提示「写明时间、地点或页面，园所处理更快」
3. 我的反馈：标题 + `共 3 条`，下发为时间轴（左侧状态点 + 右侧记录卡）；记录卡含类型标签、状态、日期、内容，长内容三行截断可展开；有回复时追加「园所回复」块
4. 底部固定提交栏：常驻一行说明（默认 / 阻断 / 提交中三选一）+ 48px 主按钮；失败时说明行上方再挂一条持久失败条
5. 整页成功态：居中三层圆环对勾 +「反馈已提交」+ 提交摘要卡 +「查看我的反馈 / 再提一条」；不叠加在表单上

## 覆盖状态

| 状态 | 表现 |
| --- | --- |
| 正常（默认） | 建议选中（橙描边 + `--accent-wash` + 对勾）；内容 32 字示例，计数 `32 / 500`；记录 3 条（问题·已提交·10月24日 周六 / 建议·已回复·10月19日 周一 / 投诉·已关闭·10月8日 周四）；提交栏说明「提交后可在记录里查看进展」，主按钮品牌渐变可点 |
| 必填未完成 | 内容清空，计数 `0 / 500`，输入框 `aria-invalid="true"`；提交栏说明变红「还需填写：反馈内容」；按钮转灰底（`--bg` + `--muted`）、`aria-disabled="true"`，点击不提交、不弹 toast，只把焦点送回输入框；重新输入即自动恢复常态 |
| 空（无历史） | 记录区整体换成空态卡「还没有反馈记录 / 提交后可以在这里查看园所回复」+「写下第一条」按钮，计数 `共 0 条`；表单保留可写 |
| 加载 | 记录区换两段时间轴骨架（圆点 + 卡 + 呼吸线），计数「加载中」；表单与提交栏保持可用，不画假数据 |
| 提交中 | 表单整体 `inert` + `opacity:.62`，类型胶囊 `disabled`、输入框只读；按钮显示小转圈 +「提交中…」，说明行「正在提交，请稍候」；1.3s 后进入成功态 |
| 失败 | 记录区换成错误面板「反馈记录加载失败 / 请稍后重试，或检查网络连接」+ 重试；提交栏上方出现 `--danger-wash` 持久失败条「提交失败，请重试」+ 重试，默认说明行隐藏；列表重试 → 恢复 3 条 + toast「已刷新」，提交重试 → 提交中 → 成功态。两条重试各管各的：恢复列表不会让提交失败条消失，重试提交也不会把未加载成功的记录显示出来。演示芯片把两条失败一起铺开只是为了少点一次 |
| **提交成功（整页，非 toast）** | `body[data-view="success"]` 隐藏表单页与提交栏，居中显示：112px 三层圆环 + 白色对勾 →「反馈已提交」→「园所的回复会出现在「我的反馈」里」→ 摘要卡（类型标签、10月26日 周一、刚提交内容）→「查看我的反馈」（回列表，新记录置顶并高亮 2.4s，计数变 `共 4 条`）/「再提一条」（回表单顶部并聚焦输入框）。标题只做程序化聚焦供读屏播报，不画视觉焦点框 |

演示芯片：正常 / 必填 / 空态 / 加载 / 提交中 / 失败（`data-mp-state` = `normal / required / empty / loading / submitting / failed`），六态都走真实 `app.js` 分支。成功态不占芯片，由「提交中」延时 1.3s 或真实点提交进入。

状态实现上拆成两条独立通道，各自挂在自己的 data 属性上，芯片只负责把两者一起铺开：

- 列表通道 `.mp-app[data-list-state]` = `ok / loading / empty / failed`，只由列表请求结果改写（`ok → 骨架 / 空态 / 错误面板 / 记录列表`）。
- 提交通道 `.mp-app[data-submit-state]` = `idle / required / submitting / failed`，只由提交请求结果改写（底栏说明行、失败条、按钮灰化与转圈、表单 `inert`）。
- 真实交互只动自己那条：列表重试只回 `listState`，提交重试只回 `submitState`；两条都失败时互不清除。场景不再成立时 `data-state` 置为 `custom`，避免芯片高亮谎报当前状态。
- 清空内容一律进 `required`（含「查看我的反馈」「再提一条」返回路径），保证「空内容 = 阻断」在任何入口都成立。

## 与现状的差异

- **表单从「点 + 反馈才展开」改为常驻便笺**：源码 `showForm=false`，首屏只有标题和列表，用户要先点右上角 `+ 反馈`；原型把填写区放在首屏，历史记录在下，减少一次决策（见遗留 8）。
- **提交按钮从表单末尾改为底部固定栏**：源码按钮在卡片内、随页面滚走；原型固定吸底并预留安全区，内容区底部留 156px 防遮挡，失败时留出失败条高度。
- **必填校验从 toast 前移到界面**：源码 `if (!content.trim()) uni.showToast("请填写反馈内容")`；原型改为常驻红色阻断文案 + 灰按钮 + `aria-disabled`，点击只聚焦输入框，清空内容也会即时进入阻断态，不再等用户点提交。
- **成功从 toast 改为整页成功态**：源码 `showToast("提交成功")` 后清空、收起表单并 `loadData()`；原型按批次要求给整页成功态、提交摘要与两个去向，确认感更强（见遗留 5）。
- **失败从 toast 改为持久失败条 + 重试**：源码 catch 只弹 `err.message`，列表请求失败更是被静默吞掉、永远显示「暂无反馈记录」；原型给提交失败条与列表错误面板两条独立重试路径。
- **新增列表加载骨架与错误态**：源码 `loadData` 的 catch 为空，网络失败与「没有记录」不可区分；原型拆成 加载 / 空 / 失败 三态。
- **类型标签改为前端可兜底的双色胶囊**：源码读 `item.category_label`，但后端 `ListFeedback` 并未返回该字段；原型按 `category` 映射「建议 / 投诉 / 问题」并上色（见遗留 1）。
- **日期从原始切片改为中文日期 + 星期**：源码 `created_at?.slice(0, 16)` 会显示成 `2026-10-24T09:12`（UTC 且带 T）；原型显示「10月24日 周六」。
- **回复区改为独立「园所回复」块**：源码一行 `回复: …`；原型用暖底 + 左侧品牌色细线区分园所声音。
- **新增字数统计、长内容展开、空态 CTA**：源码只有 `maxlength=500`、无计数；记录内容完整平铺；空态是一行灰字。原型补 `0 / 500`、三行截断（仅超长记录显示展开箭头）、「写下第一条」入口。
- **未画图片与联系方式**：domain / 创建契约支持 `contact` 与 `images`，但源码表单没有任何入口；按「以源码为准」不发明（见遗留 3）。

## 遗留

1. **`category_label` 契约缺口（需产品 / 后端确认）**：`ListFeedback` 只返回 `category`（`suggestion/complaint/bug`），源码 `f-cat` 却直接渲染 `item.category_label` → 真机上类型标签会是空白。原型按枚举映射兜底；落地要么后端补 `category_label`，要么前端建映射表。
2. **园所回复没有生产入口（需产品确认）**：仓库里没有管理端 / 老师端的反馈列表或回复接口，`status / reply / replied_at` 目前只能直接改库。若「已回复」要真实发生，需先补后台反馈管理页与 `PUT /admin/feedback/:id/reply` 一类契约。
3. **`contact` / `images` 有契约无 UI（需产品确认）**：`Feedback` domain 与 `CreateFeedback` 入参都支持联系方式与图片 JSON，但源码表单只有类型 + 内容。原型未画上传与联系方式；若要支持，需补 `uni.chooseImage`、上传与回填，并明确是否必填。
4. **列表分页未落地**：后端返回 `total / page / page_size`，源码 `fetchFeedbackList()` 不传分页参数、也没有触底加载，只会拿到第一页；原型 `共 N 条` 统计的是当前 DOM 记录数（示例 3 条），落地应改用接口 `total` 并补加载更多。
5. **成功后的去向**：源码成功后留在本页、收起表单并刷新列表；原型先给整页成功态，再由「查看我的反馈 / 再提一条」决定。若产品希望更轻，可保留成功态但 2s 后自动回列表；不建议退回纯 toast。
6. **日期与时区口径**：后端 `created_at` 是 `UTC()` 的 RFC3339；源码直接 `slice` 会同时暴露 `T` 与 UTC 偏差。落地统一用本地时区格式化为「10月24日 周六」或「2026-10-24 09:12」，二者选一。
7. **分类是否只有三种**：源码固定 `suggestion / complaint / bug`，没有「其他」。原型沿用三胶囊；若产品要加分类，需同步 domain 枚举、字典与两端文案。
8. **入口交互变更**：去掉 `+ 反馈 / 取消` 切换后，历史记录多的人首屏会先看到表单。若产品坚持「历史优先」，可把便笺折叠成一行「写反馈」入口，但需保留同一套阻断与成功态。
9. **未做的**：反馈详情页、撤回 / 删除反馈、回复红点或订阅消息、图片预览、草稿保存——源码与契约均无，原型不发明。
10. **失败态只能由演示芯片触发**：原型真实提交永远成功；审阅失败路径请用「失败」芯片（它同时铺开列表与提交两条失败，点任一条的重试只会恢复那一条）。落地时 `loadData` 的 catch 映射到 `data-list-state="failed"`，`handleSubmit` 的 catch 映射到 `data-submit-state="failed"`，别共用一个状态位。
