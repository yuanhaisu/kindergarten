# 接送二维码（parent）

- 源码：`parent/src/pages/pickup/qrcode.vue`（`onLoad` → `ensureLogin()` + `GET /parent/pickup/qrcode`；「刷新二维码」= 重新 `loadData`；「更换今日接走人」/错误态「去指定今日接走人」→ `uni.navigateTo('/pages/pickup/authorized')`）
- 接口契约：`backend/api/api-parent/05-pickup.md` → `GET /parent/pickup/qrcode`（`qr_code` / `student{name,photo}` / `person{name,relation,photo}` / `expire_at`；凭证当日过期、一次有效）
- 设计系统：`user:nurture-planet-local`，surface=parent
- 生成方式：OpenDesign（run `f311f316`，441s，`status: succeeded`，`exitCode: 0`；交付目录的 `styles.css` 用项目终态版 14749B 覆盖了脚本在 20:36 拷到的中间版 14748B，index/app 两版一致）
- 方向：**「一张当日通行证」**——凭证卡做成登机牌：上半人证对照、下半大方留白的二维码，暖橙只落在状态胶囊、主按钮、步骤序号上。

## 信息层级

1. 微信外壳：20px 状态栏 + 44px 导航栏（**返回箭头**，标题「接送二维码」，右侧胶囊）
2. 凭证卡：`接送凭证` + 状态胶囊（有效 / 已过期 / 刷新中）→ 标题「乐乐的接送二维码」→ 人证对照（孩子「乐」→ 今日接走人「奶/奶奶/奶奶」）→ 票根虚线 + 左右缺口 → 232px 二维码面板（内含 200×200 装饰占位）→「有效期至 10月26日 23:59」→「请向老师出示此码，核验后一次有效」
3. 操作区：主按钮「刷新二维码」+ 过期时提示「刷新后即可继续使用」+ 描边按钮「更换今日接走人」
4. 使用说明卡：3 条（出示给老师 / 核验后立即失效 / 当日 23:59 过期，过期或换人时刷新）

## 与现状的差异

- **新增「已过期」态**：源码只把 `expire_at` 当一行文案展示，过期后二维码照旧满色显示、没有刷新引导。原型给出「置灰二维码 + 过期胶囊 + 红色有效期 + 刷新提示」，让家长一眼知道要刷新（见遗留 3）。
- **新增「刷新中」禁用态**：源码只有 `loading` 整页分支，点刷新会整页闪一下「加载中...」；原型把刷新收敛为按钮禁用 + 二维码遮罩 spinner，页面骨架不闪。
- **错误/加载从单行文字升级为状态卡/骨架**：源码加载态是一行「加载中...」；错误态是一张「文案 +『去指定今日接走人』」的小卡（qrcode.vue:84-88），且错误态下仍渲染「刷新二维码」「更换今日接走人」两个按钮。原型给骨架屏与可操作的状态卡：失败卡在源码文案基础上补「重试」，并保留「去指定今日接走人」；操作区在失败态保留「更换今日接走人」。
- **人证对照更像「人证」**：源码 112rpx（56px）照片 + 姓名 + 「孩子」/关系，原型 48px 首字头像 + 姓名 + 关系标签，中间加虚线箭头，强调「孩子 → 今日接走人」的对应关系。
- **凭证卡做票根结构**：虚线 + 卡片左右 14px 圆形缺口，把「人证」与「码」在视觉上分成两段，同时保留 232px 面板 + 16px 内边距的充足静区。
- **新增使用说明卡**：3 条内容全部来自契约（一次有效、核销后失效、当日过期），不是新业务能力；源码只有二维码下方两行说明。
- **二维码改为不可扫的装饰占位**：原型由 app.js 用确定性伪随机生成 90 个模块 + 三个定位角 + 中心橙色星球 logo，**不构成有效编码、不可扫描**；真实实现仍用 `qrcode-generator` + canvas。

## 遗留

1. **`expire_at` 时区缺陷（真实问题，建议修）**：`GetQRCode` 把本地 `23:59:59` 存进 `ExpireAt`，返回时却是 `qr.ExpireAt.UTC().Format(time.RFC3339)`；`qrcode.vue` 直接 `expire_at.slice(0,16).replace('T',' ')` 展示。中国时区（UTC+8）下页面会显示「15:59」而不是「23:59」。原型按用户可理解的本地时间画「23:59」。落地需前端 `new Date(expire_at)` 转本地，或后端返回带偏移的本地时间。
2. **`relation` 字典口径不一致，需产品确认**：契约示例是 `grandmother`，而 `authorized-create.vue` 的关系选择器写入的是中文（爸爸/妈妈/爷爷/奶奶/外公/外婆/叔叔/阿姨/其他），`qrcode.vue` 又直接渲染 `person.relation`。原型显示中文「奶奶」；建议契约与分析接口统一为枚举 + 前端映射文案。
3. **「已过期」是设计提案，源码无判断逻辑**：`qrcode.vue` 没有任何过期判断或过期后刷新入口，原型补了这一状态。落地需要在 `loadData` 后比较 `expire_at`，并在监听回前台（`onShow`）时重新判断。
4. **「刷新」不一定换新码**：后端若已有有效凭证且接走人未变，会复用同一 `qr_code`（`FindActiveQRCodeByStudent`）。原型按钮文案沿用源码「刷新二维码」，toast「二维码已刷新」不承诺换码；若要「换新码」需后端支持强制重建。
5. **照片字段未在原型使用**：契约返回 `student.photo` / `person.photo`，源码有 `<image>` 分支但真实头像缺失时回落灰色占位；原型统一用姓名首字（与批次其他页一致）。
6. **一次性核销后本页不会实时失效**：家长在老师核销后停留在本页时，二维码仍显示有效；真实实现需在 `onShow` 重新拉取（与遗留 3 同一处修）。
7. **未做的**：倒计时秒数、保存/分享、扫码记录、历史凭证、多孩子切换——源码均无，原型不发明。
