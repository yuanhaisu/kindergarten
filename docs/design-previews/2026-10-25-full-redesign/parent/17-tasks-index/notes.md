# 亲子任务（家长端）

- 源码：parent/src/pages/tasks/index.vue（路由 pages/tasks/index，非 tabBar 页）
- 设计系统：user:nurture-planet-local，surface=parent
- 方向：**任务节奏**——卡片主轴是「本周期是否已提交」这个二元事实，用一条周期状态行（待提交/已提交/已回应）替代源码里 0%/100% 的进度条。

## 信息层级

1. 导航栏：返回箭头 + 「亲子任务」+ 胶囊（子页，无 tabBar）
2. 班级墙入口：低矮白卡（淡橙圆图标 + 标题 + 说明 + 箭头），去 `/pages/tasks/wall`
3. 分类分段：进行中 / 已打卡 / 全部，等宽三段；「进行中」带 16px 危险色数量点
4. 待完成提醒：12px 一行「本周期还有 N 个任务待提交」，前置 6px 琥珀圆点
5. 任务卡（三段）：谁的任务（图标+标题+描述两行）→ 周期事实（频次·累计 / 截止日 / 星星罐 / 周期状态行）→ 动作（主 + 次等宽两列）
6. 列表脚注：11px「任务由老师发布 · 下拉可刷新」

## 覆盖状态

- **正常**：5 张卡覆盖 待完成 / 已提交 / 已回应（含未读悄悄话）/ 已结束 四种组合
- **空**：按分类区分文案（进行中「当前没有待完成的任务」、已打卡/全部「暂无任务」），CTA 按钮切到另一分类并真实恢复列表
- **加载**：3 张骨架卡，含图标/标题/描述/状态行/双按钮占位，shimmer 在 `prefers-reduced-motion` 下停用
- **错误**：首次失败整块错误态（未绑定时文案换成「未绑定孩子信息」并隐藏重试）；已有列表时顶部 inline 错误条「加载失败，点击重试」，保留旧列表
- **重试**：按钮进入「正在重试…」+ aria-busy，1s 后回正常态并 toast「已重新加载」
- **禁用**：已结束卡整卡降饱和，主按钮不可点「已结束」，次按钮仍可查看详情

## 与现状的差异

1. **默认分类改为「全部」**：源码默认「进行中」，但那样首屏只能看到 2 张待完成卡，四种卡片状态都看不见。原型默认「全部」以便一屏评审；筛选逻辑（进行中 = status=1 且未提交、已打卡 = 已提交、全部）与源码一致。
2. **待完成提醒改为页面级**：源码只在「进行中」显示 pendingCount 提醒；原型在默认「全部」下仍保留该行，否则会被隐藏。
3. **新增列表卡字段**：`end_date` → 「截止 10月31日」，`star_scope`/`star_goal` → 「星星罐 20 星」/「班级星星罐」。两者都是接口真实返回字段，但当前列表卡没展示——属于本批次要求补充展示的评审项。
4. **进度条 → 周期状态行**：源码用 0%/100% 进度条表达二元事实，视觉上像「完成度」，改成待提交空心点 / 已提交对勾 / 已回应双勾的周期状态行。
5. **班级墙入口去橙底**：源码是整块橙色底，原型改为白色低矮卡 + 淡橙图标，减少暖色面积。
6. **已结束卡主按钮禁用**：源码仍渲染「去提交」，原型降级为不可点「已结束」，避免对已结束任务发起提交。
7. **不出现任何积分**：本产品任务不发积分（`backend/api/api-parent/06-task.md` 已移除 points 字段），原型不写积分数值，奖励只表达星星罐机制。

## 遗留 / 需产品确认

- 列表卡是否正式增加「截止日」与「星星罐」两行信息（接口有字段，现网列表未展示）？若加，`star_scope=class` 时是否要显示班级累计星数（接口未返回，原型只写「班级星星罐」不写数字）。
- 已结束任务的主按钮在产品上应禁用还是保留「去提交」（原型取禁用），需要和老师端发布/结束流程对齐。
- 原型默认「全部」仅为评审方便，落地时是否保留源码默认「进行中」需产品拍板。
