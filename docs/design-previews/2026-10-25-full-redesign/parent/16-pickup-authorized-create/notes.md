# 添加授权接送人（parent）

- 源码：`parent/src/pages/pickup/authorized-create.vue`（`createAuthorizedPerson` → `POST /parent/pickup/authorized-persons?student_id=...`；`student_id` 走 query，body 里的会被后端忽略；提交成功后 toast「已提交，待园所审核」并 `navigateBack`）
- 设计系统：`user:nurture-planet-local`，surface=parent
- 生成方式：OpenDesign（run `d9f43db8`，322s；daemon 终态 `succeeded`，三件套齐全，交付目录与项目终态逐字节一致，未走手写兜底）
- 方向：**「核验登记表」**——先回答「这个人是谁」，再回答「他能做什么」；不靠图标和装饰制造安全感，靠分组、留白和一条提前说明的审核规则。橙色只落在开启的开关、关系值、主按钮与选中项，面积 ≤ 10%。

## 信息层级

1. 微信外壳：20px 状态栏 + 44px 导航栏（**返回箭头** + 标题「添加授权接送人」+ 胶囊）；**无 tabBar**（`navigateTo` 子页）
2. 孩子上下文（只读）：28px `--accent-wash` 首字「乐」+「为 **乐乐** 添加接送人」，无切换入口
3. 基本信息卡：姓名* / 手机号* / 与孩子关系*（整行可点，右侧值 + `›`）/ 身份证号（选填）；分组标题右侧「3 项必填」，必填标签带 `--danger` `*`
4. 权限设置卡：5 行 `role="switch"`，每行「主标签 + 11px 解释性副文案 + 51×31 开关」；默认开 `可接送孩子`、`接送时通知我`
5. 审核说明条：`--warning-wash` 底 + 盾牌图标 +「提交后需园所审核通过，授权才会生效。审核通过前，该接送人不能接走孩子。」
6. 底部固定提交栏：常驻阻断/事实行 + 48px 主按钮；失败态在其上方插入失败条

## 与现状的差异

1. **审核规则从页尾一行灰字改为说明条**：源码只有一个 `.hint`；原型做成 `--warning-wash` 条并在原文后补「审核通过前，该接送人不能接走孩子」——依据是契约里「有效接送人 = status 1 且 review_status 1」，把「提交 ≠ 生效」提前说清。
2. **校验从事后 toast 改为事前阻断**：源码点提交才 `showToast('请填写完整信息')`；原型在按钮上方常驻「还需填写：…」、字段就地报错、按钮置灰，用户填之前就知道差什么。
3. **关系从原生滚轮 picker 改为底部选择面板**：9 个选项（爸爸/妈妈/爷爷/奶奶/外公/外婆/叔叔/阿姨/其他）一屏可读，选中项 `--accent-wash` 底 + 对勾；小屏面板内部可滚动。
4. **开关补解释性副文案**：源码只有 5 个裸标签；原型每行加 11px 说明能力边界（如「允许门卫核验身份后接走孩子」），没有新增任何开关或字段。
5. **提交按钮从页面流内改为固定底栏**：源码按钮在表单末尾（`padding-bottom: 160rpx` 硬留白）；原型固定在底部并处理安全区，长表单不用滚到底才能提交。
6. **失败从全局 toast 改为可重试失败条**：源码 `catch` 为空、依赖 `http.js` 全局 toast；原型保留用户已填内容并在提交栏上方给出「重试」。
7. **必填可视化**：分组标题右侧「3 项必填」+ 标签 `*`，源码没有必填标识。
8. **输入约束落地**：手机号实时过滤非数字、限 11 位；身份证只保留数字与 X、限 18 位；源码只设了 `maxlength`。
9. **成功态停留审阅**：源码 toast 后 900ms `navigateBack`；原型只 toast「已提交，待园所审核」并恢复按钮，便于评审反复查看。

## 遗留

1. **孩子姓名/班级是占位（与批次 A3 同一问题）**：本页源码只调 `getCurrentStudentId()`，拿不到姓名与班级；上下文条「乐乐 · 小一班」需从 overview 注入或由 `student_id` 查询，落地前必须补数据来源。
2. **关系字典口径不一致（需产品/后端确认）**：源码提交的是中文值（「爸爸」「爷爷」…），而 `backend/api/api-parent/05-pickup.md` 的请求示例写 `"relation": "grandfather"`。后端若按英文枚举校验，当前源码会失败；需统一字典并回写契约。
3. **刻意不做的两项，需要产品拍板**：① 授权类型（长期/临时）——新建接口不收 `expire_at`，建出的「临时授权」不会过期；② 短信验证码——`CreateAuthorizedPerson` 不校验 `sms_code`。若要支持，先改契约再补 UI。
4. **身份证号加了看不到**：添加时可选填 18 位，但 `GET /parent/pickup/authorized-persons` 不返回证件号字段，后续列表/编辑无法回显与核对。需产品确认是否保留该字段及回显方式。
5. **三项权限在别处不可见**：`allow_view_status` / `notify_on_pickup`（以及 `allow_growth_view` 的部分场景）在列表页没有标签，用户设完无法核对。建议列表卡片补齐权限标签或增加详情页。
6. **多孩子账号无分组**：提交只带当前 `student_id`，页面不显示还有其他孩子；切换孩子需回首页操作。与 15 授权列表同一问题。
7. **头像字段未用**：契约接受 `avatar`，源码表单无上传入口；本页不画头像上传（与 15 的姓名首字方案一致）。
8. **演示芯片为 5 个**：批次 findings 提过「无列表页不要造第 5 个状态」；本页把空态槽位映射为「必填未完成」，另加「加载」与「提交中」两个表单真实状态，与已验收的 07 请假申请同构。若批次要求严格 4 个，可删「加载」芯片（提交中保留，它是本页核心状态）。
