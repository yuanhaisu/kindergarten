# 成长时光（家长端）

> 生成方式：部分手写（OpenDesign run 卡在 context compaction，缺 app.js）

- 源码：`parent/src/pages/growth/index.vue`
- 设计系统：`user:nurture-planet-local`，surface=parent
- 方向：暖橙时间轴上的成长流。孩子卡先回答「这是谁的成长」，视角切换控制在手边，月份做轻分组，让家长在长列表里始终知道自己在看哪一段。

## 信息层级

1. 孩子卡：导出相册、头像/姓名/班级、四项统计（成长记录 / 照片 / 奖章 / 出勤）
2. 视角切换：只看孩子 / 看全部，各自带「N 条 · N 张」摘要，下方一句范围说明
3. 时光轴标题：`2026年` + 当前视角条数
4. 月分组：`2026年10月` / `2026年9月`，组内按时间倒序
5. 记录卡：老师头像与称呼、日期时间、归属胶囊（专属记录 / 集体 · 含孩子 / 班级记录 / 含孩子 / 其他孩子）、可选奖章、正文、照片网格、隐藏照片提示、点赞/评论/分享
6. 底部 tabBar：首页 / 成长 / 接送 / 我的，「成长」选中

## 覆盖状态

| 状态 | 表现 |
|---|---|
| 正常 | 6 条记录；只看孩子 5 条 · 8 张，看全部 6 条 · 15 张；10-22 班级记录在只看孩子时只露 2 张点名照片，并提示「还有 4 张班级照片」；9-28 纯班级记录默认不出现 |
| 空 | 「老师还没有发布成长记录」+ 说明 + 「刷新看看」；视角切换与时光轴隐藏，孩子卡「成长记录」归零，照片/出勤保持「—」 |
| 视角筛选为空 | 有记录但「只看孩子」一条也没匹配时：时光轴标题保留并显示「0 条」，月份分组隐藏，列表位置出现提示卡「还没有与乐乐相关的成长记录」+「可以先看看班级动态，或等老师发布新的记录。」；「看全部」入口仍由顶部视角切换承担，不额外放行内按钮 |
| 加载 | 三张骨架卡；视角切换、导出、点赞/评论/分享置为 `aria-disabled` 并降色；时光轴隐藏 |
| 错误 | 「加载成长时光失败」+ 重试；重试按钮进入「重试中…」（900ms）后回到正常态并提示「已重新加载」 |
| 禁用 | 加载/错误态下所有主操作不可点，视觉降级；正常/空态恢复 |

## 与现状的差异

- **月份呈现**：源码在流内插入单行月份 marker；原型改为按月分组标题，降低长流定位成本。派生方式不变，仍由 `date.slice(0, 7)` 得出。
- **照片 / 出勤统计**：源码这两项目前没有可靠数据源，显示为 `0` 与空串；原型改为「—」，避免把「暂无数据」误读成「真的为 0」。
- **导出相册**：源码有胶囊但未绑定事件；原型点击给出「已打开成长相册」轻提示，不伪造跳转。
- **孩子视角无内容**：标题与说明沿用源码文案（「还没有与{孩子}相关的成长记录」/「可以先看看班级动态，或等老师发布新的记录。」），渲染为时光轴「0 条」下的提示卡；源码的行内「看全部班级动态」按钮仍由顶部常驻的视角切换承担，不重复入口。
- **照片点击**：源码在列表页没有独立预览，点卡片进详情；原型沿用整卡点击（提示「已打开成长详情」），没有新增弹层。

## 遗留 / 需产品确认

- 点赞接口 POST 返回 `is_liked=true` 但 GET 仍为 `false`，后端不落库（见 `_shared/findings.md` #9）。原型只做本地态反馈，不假装已持久化。
- 照片数与出勤率缺少数据源，孩子卡这两项只能占位。
- 导出相册入口需要确认落点（相册页 / 系统分享）后再接线。
- 月分组标题是本次设计提案，若要与源码完全一致可退回行内 marker。
- 视角筛选为空由数据触发（当前 fixture「只看孩子」恒为 5 条），演示条四态无法强制进入；若要一键演示，需批次级新增演示芯片规范，本页未单独扩芯片。
- `index.html` 26KB，超过审计 20KB 提示线；属批次已知体积提示，非结构问题。
