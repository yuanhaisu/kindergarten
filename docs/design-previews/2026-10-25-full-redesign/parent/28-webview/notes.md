# 内嵌网页（家长端）

- 源码：parent/src/pages/webview/index.vue
- 设计系统：user:nurture-planet-local，surface=parent
- 方向：一页安静的外部网页容器——网页挂载前先把「这是外部网页」说清楚，挂载后把整块页面让给第三方页面；加载与失败都不抢戏。

## 信息层级

1. 导航栏「详情」+ 返回箭头（源码 `pages.json` 标题为「详情」，非 tabBar 页，由 `navigateTo` 进入）
2. 打开前确认（`data-state="confirm"`）：地球图标 + 「即将打开外部网页」+ 一句「该页面由第三方站点提供，请注意保护个人信息」+ 域名与完整地址卡片 + 「继续打开」主按钮 + 「返回」文字按钮
3. 全屏网页画布（`data-state="normal"`）：导航栏以下整块 `var(--surface)`，正常态为中性虚线占位（「外部网页内容」+ 一句说明），不伪造第三方内容
4. 原型状态条：打开前 / 正常 / 空态 / 加载 / 失败

## 覆盖状态

- 打开前：来源信息与「继续打开 / 返回」都在这一步完成。此时 `web-view` 还没挂载，所以页面上没有任何会被它覆盖的元素——这是来源信息唯一可常驻的位置。
- 正常：整块画布就是网页本身（真机由 `<web-view>` 铺满导航栏以下，页面不再放其他自有 UI）。占位块用虚线边框与页面底色区分「外部内容的位置」，不是本页自己的卡片。
- 空态：对应源码 `v-else` 分支「缺少页面地址」。隐藏确认页与画布，整页居中（断链图标 + 「缺少页面地址」+ 引导语 + 「返回上一页」主按钮）。
- 加载：画布内小圆环 + 「正在加载网页…」+ 3 行骨架条，容器 `aria-busy="true"`；与确认页互斥。
- 错误：画布内警示图标 + 「网页无法访问」+ 一句原因（网络不稳定 / 链接失效）+ 「重新加载」主按钮 + 「返回上一页」文字按钮。
- 禁用：加载中再点「继续打开」不重复触发（`openExternal()` 在 `loading` 态直接返回）；演示中切换状态芯片会清掉进行中的计时器，不会在别的状态里突然跳回正常态。

## token 映射

- 页面底色 `var(--bg)`、确认页地址卡与画布 `var(--surface)`、分隔线与虚线 `var(--border)`
- 确认页地球图标底 `var(--accent-wash)`、图标 `var(--accent-deep)`；loading 圆环顶边 `var(--accent)`
- 错误图标 `var(--danger)` / `var(--danger-wash)`；主按钮 `var(--fg)` 底 + `var(--on-brand)` 字
- 正文 `var(--fg)` / `var(--fg-2)`、次要说明 `var(--muted)`（本页已不使用 `var(--hint)`）
- 圆角 `var(--radius-card)` 地址卡 / `var(--radius-xl)` 占位与图标 / `var(--radius-2xl)` 状态图标 / `var(--radius-pill)` 按钮与标签
- 阴影只 `var(--shadow-sm)`，toast 用 `var(--shadow-lg)`
- 字号 `var(--text-2xl)` 状态标题 / `var(--text-xl)` 占位标题 / `var(--text-md)` 域名 / `var(--text-base)` 正文 / `var(--text-sm)` 地址
- 动效 `var(--motion-fast)` / `var(--motion-base)` + `var(--ease)`，`prefers-reduced-motion` 下全部停用

## 与现状的差异

- 源码只有一个 `<web-view>` 与 `v-else` 空态，没有任何加载/失败表现；原型按批次要求补齐加载、失败、重试三态。
- **来源信息前置为「打开前确认」（设计提案，需产品确认）**：源码的 `url` 只作为 `web-view` 的 `src`，用户看不到打开了哪个链接。原型把域名与完整地址放进打开前的确认页，点「继续打开」后页面只留网页本身。
- 原型的顶部常驻来源条、刷新按钮与画布脚注**已移除**：`<web-view>` 挂载后会盖住它们，留着就是不可实现的骨架（见「遗留」1）。刷新能力只在失败态以「重新加载」保留。
- 源码没有重新加载能力；原型失败态的「重新加载」是演示交互，真实实现需要重建 `web-view`（改 key 或重新赋值 `src`）。
- 空态沿用源码文案「缺少页面地址」，补充引导语与返回按钮。
- 家长端是非个人主体小程序，`<web-view>` 可用，因此错误文案只写网络/链接原因，不写老师端那种「未开通内嵌网页能力」的平台限制。

## 遗留

1. **平台硬约束：`<web-view>` 会自动铺满整个页面并覆盖其他组件。** 除原生导航栏外，网页挂载后页面上任何自有 UI 都会被盖住，所以来源条/刷新/脚注不能按普通 view 与网页同屏常驻。当前设计把来源信息前置到「打开前确认」，网页态保持裸 `web-view`。若产品坚持同屏显示来源，只能改用 `cover-view` / `cover-image` 叠加，并接受遮挡第三方页面内容。
2. 加载态与失败态是原型提案：失败态要在 `binderror` 之后卸载 `web-view` 才能露出错误面板；加载态只在 `web-view` 挂载之前成立，真实网页自身的加载过程无法在不遮挡的前提下展示。接入时按微信文档补 `bindmessage` / `binderror`、加载进度与业务域名白名单校验。
3. 当前 `parent/src` 内没有任何 `navigateTo` 指向 `pages/webview/index`（全量 grep 未命中），入口是否存在、由哪个功能进入需产品确认；「打开前确认」是否保留同样是产品决策。
4. 空态在真实场景由入口是否传 `url` 决定，原型通过演示状态条切到；打开前/正常/加载/失败四态也均为原型演示，真实加载时序由 `web-view` 决定。
