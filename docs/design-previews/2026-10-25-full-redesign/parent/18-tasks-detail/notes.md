# 任务详情（家长端）

- 源码：`parent/src/pages/tasks/detail.vue`
- 接口：`GET /parent/tasks/:id`、`GET /parent/tasks/:id/checkin-history`、`POST /parent/tasks/:id/checkin`、`POST|DELETE /parent/tasks/checkins/:id/public-request`、`POST /parent/tasks/responses/:id/reaction`、`POST /parent/tasks/:id/read`（契约见 `backend/api/api-parent/06-task.md`）
- 设计系统：user:nurture-planet-local，surface=parent
- 方向：**一次提交的完整回路**——任务是什么 → 我交了什么 → 老师回了什么 → 以前交过什么。把「本周期这一次提交」做成一张可翻阅的记录卡，而不是一张大表单。

## 信息层级（从上到下）

1. 任务卡：频次 pill + 本周期状态 chip → 标题 → 一句描述 → 详细介绍 → 3 条要求（数字圆点）→ 截止时间 / 星星罐两格 → 学习关联
2. 未读提示「老师又给你留了一句悄悄话」（已提交 / 已通过态，对应 `has_unread_supplement`，与本周期是否提交相互独立）
3. 王老师的回应（已提交 / 已通过 / 有回应·未提交三态均显示）：贴纸 / 语音 / 三档反馈 / 补充回应 / 给孩子看
4. 我的提交（已提交 / 已通过）：提交时间 + 内容 + 照片 + 公开状态行（申请 / 取消公开，两步确认）
5. 今日提交（仅未提交态）：照片位 + 一键提交 + 输入框 + 打卡按钮
6. 打卡历史：竖线时间轴，日期 + 公开状态徽标 + 内容 + 申请/取消公开（两步确认）

## 覆盖状态

| 状态 | 表现 |
|---|---|
| 正常（未打卡） | 任务卡「本周期待提交」+ 打卡区 + 3 条历史；默认渲染 |
| 已提交 | 打卡区隐藏，换成「我的提交」卡；chip「已提交」；公开行默认无徽标 +「申请公开」；未读提示与老师回应均可见 |
| 已通过 | 「我的提交」卡 chip 换「已通过」；公开行「老师已通过 · 本班家长可见」+「取消公开」；未读提示 + 老师回应与补充回应 + 反馈 chip |
| 有回应·未提交 | 老师回应与未读提示可见，今日打卡区同时可用，「我的提交」不渲染——证明回应独立于本周期提交 |
| 空态 | 任务卡与打卡区保留，打卡历史换成空态卡（图标 + 一句话 + 「去打卡」） |
| 加载 | 3 块骨架（任务卡 / 提交卡 / 历史），`.mp-app[data-state="loading"]` |
| 失败 | 顶部「这条消息是另一个孩子的任务」提示条（切换查看）+「任务已结束或不存在」错误卡 + 重试 |
| 禁用 | 内容与照片都为空时「打卡」置灰、不可点，并提示「填写内容或上传照片后可提交」 |

演示切换条：未打卡 / 已提交 / 已通过 / 有回应·未提交 / 空态 / 加载 / 失败（`mp-demo` + `data-mp-state`，由 `_shared/shell.js` 驱动）。

## 已落地的真实交互（CDP 实测全通过，console 干净）

- 照片位 → 选中后显示占位图 + 右上移除；移除回到虚线位
- 输入框有内容或已选照片 → 「打卡」启用；提交后清空草稿、toast「已提交，等待老师回应」并切到「已提交」
- 「今天完成了（一键提交）」直接提交（无内容）
- 老师回应：三条反馈单选、语音播放/停止（同一时间一条）、「给孩子看」全屏遮罩（点内容区不关、点空白关、Esc 关）
- 「我的提交」公开状态：申请公开 → 待审核；首次点「取消公开」变「确认撤下？」，再点一次变「未公开」+「重新申请」；随「已通过」演示态同步为「老师已通过」
- 打卡历史：按 publicState 四态渲染（已通过可见 / 已通过不可见 / 待审核 / 未公开），申请与取消公开均两步确认，徽标与说明同步变化；一键完成行无公开入口
- 空态 CTA 回未打卡并聚焦输入框；失败态「重试」→ 900ms 后恢复

## 与现状的差异

1. **区块顺序**：与源码一致——任务卡 → 未读提示 → 王老师的回应 → 今日提交 → 打卡历史；「我的提交」卡只在已提交 / 已通过时出现，承载这次提交的公开状态，回应不并入提交卡（两者独立渲染）。
2. **补了契约里有、页面没渲染的事实**：`end_date` → 截止时间。源码详情页原本不显示它。
3. **打卡按钮改为「空内容禁用」**：源码是点击后用 toast 校验；规则相同（内容或照片至少一个），这里把规则前置成禁用态，补上批次要求的禁用态覆盖。
4. **照片位改为单张方形上传块**：源码 `uni.chooseImage({count: 1})` 只支持一张，因此没有做九宫格——九宫格会让人以为能传 9 张。
5. **视觉重构**：截止/星星罐从纯文字行改为两格等宽小卡；打卡历史从卡片列表改为时间轴 + 公开状态徽标；「给孩子看」「取消公开」从实心色块改为文本按钮，压低橙色面积。
6. **未读提示**只在已提交 / 已通过态出现：这两种态本周期有提交、可能有补充回应；未打卡且无回应时不显示。

## 遗留 / 需产品确认

- **多图提交**：若产品希望一次传多张，需要后端 checkin 支持多 media，本页才能做九宫格；当前按 `count:1` 设计。
- **截止时间常驻**：`end_date` 是真实字段，但源码详情页未展示；本次按批次要求补上，是否长期保留待确认。
- **多孩不一致提示**：源码里它独立于加载状态存在；原型只在失败态演示（避免正常态叠两条提示），其它状态未画。
- **公开墙**：家长端尚无「班级墙」页面（`fetchPublicWall` 无调用方），所以「已通过」文案只说可见性，不给跳转入口，与源码一致。
- 语音播放、照片上传、切换孩子均为原型模拟；下拉刷新未模拟。
- 「给老师的反馈」按家长账号维度记录（契约如此），多孩共用一条，本页未额外标注。
