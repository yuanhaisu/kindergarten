# 绑定孩子（parent）

- 源码：`parent/src/pages/auth/bind.vue`（接口 `parent/src/api/parent-student.js` → `POST /parent/students/bind`；服务端语义见 `server/internal/service/parent_portal_service.go#BindStudent`）
- 设计系统：`user:nurture-planet-local`，surface=`parent`
- 方向：把「填一个码」做成一次有把握的仪式——两条入口（手输 / 扫码）共用同一块输入区，缺什么、错在哪、正在提交都在原位说清，不弹二次弹窗打断。
- 信息层级：hero（是什么）→ 邀请码输入（唯一动作）→ 确认绑定 + 缺项提示（主行动）→ 扫码（并列入口）→ 关于邀请码三条（信任与兜底）→ 一行「另一位家长也能绑同一个孩子」收尾。

## 真实产品事实（决定页面内容的部分）

- 本页**只有邀请码一个字段**（`invite_code`，`maxlength=20`）。源码里**没有手机号、没有短信验证码**——手机号授权发生在家长首页（`GET` 微信手机号 → `/common/user/bind-parent-phone`），与本页无关。
- 邀请码 = 园所内该孩子的 `student_no`（服务端按 `student_no + kindergarten_id` 查学生，查不到返回「未找到该学生，请检查邀请码」）。
- 已绑定过同一孩子 →「已绑定或邀请码无效」；其他异常 →「绑定学生失败」。
- 成功后父应用 toast「绑定成功」并在 1 秒后 `navigateBack()`。
- 扫码走 `uni.scanCode`，扫到内容直接填入并**立即自动提交**，没有二次确认。
- 绑定关系含义：**一个家长可以绑定多个孩子**（`/parent/students` 返回列表、端上可切换）；单个学生可被多位家长分别绑定；本页写入 `relation=other`、`is_primary=false`，**不抢占孩子已有的主家长**。
- 本页是 `navigateTo` 进入的子页（`pages.json` 标题「绑定孩子」），因此画返回箭头；**不画 tabBar**。

## 覆盖状态

| 状态 | 演示条 | 表现 |
|---|---|---|
| 正常 | 正常 | 邀请码已填 `KP20241015`，计数 10/20，主按钮实心品牌橙可点，无提示噪音 |
| 空态 / 信息不全 | 空态 | 输入为空、显示占位符，主按钮灰底禁用，下方出现橙色圆点 +「还差邀请码」；helper 仍显示邀请码来源 |
| 加载 / 提交中 | 加载 | 输入框禁用并降透明，主按钮变为圆环 +「绑定中...」并轻微降饱和，扫码按钮灰禁，`aria-busy=true` |
| 失败 | 失败 | 输入框红边，位置固定的错误行换成红底 +「未找到该学生，请检查邀请码」，出现「重新填写」，主按钮仍可点（改码重试） |
| 客户端校验 | 输入 1–5 位 | 打字阶段提示行只显示中性的「还差 N 位」（不标红、无「重新填写」）；离开输入框或提交时才转为红底错误行「邀请码至少 6 位」，不发请求 |
| 成功 | 扫码/提交后 | 屏幕中央深色 toast：白圆勾 +「绑定成功」+「正在返回…」，1 秒后收起并让返回箭头短暂高亮 |

交互细节：输入自动转大写、去首尾空格；不足 6 位时打字阶段只给中性「还差 N 位」，失焦或提交才转错误；「重新填写」只在服务端失败时出现（位数不足时清空输入没有意义）；`Enter` 提交；扫码层 1.4 秒后自动填入示例码并提交；扫码层支持右上角关闭与 `Esc`；「返回」给出轻提示。

## 与现状的差异

- 现状是一张垂直堆叠的白卡（标题、说明、输入、两个按钮），页面居中且没有外壳；原型给足小程序外壳，并把「缺项 / 校验 / 提交 / 失败」四种句子都固定在同一块输入区播报，避免 toast 一闪而过看不到原因。
- 主按钮从 `--semantic-info` 蓝改为品牌橙渐变，与家长端主色一致；扫码从纯文字按钮升级为带相机图标的描边按钮，仍是次要动作。
- 新增「关于邀请码」三点说明，把源码里没写但产品必须交代的关系讲清楚：学号即邀请码、可绑多个孩子且不抢主家长、无效时找老师。
- 输入框加了实时计数（20 上限来自源码 `maxlength`）与客户端最少 6 位校验（源码只校验非空），让"校验失败"成为可演示状态而不是静默失败。

## 遗留 / 需产品确认

1. **客户端最少 6 位**是原型新增规则（源码仅 `if (!code)`）。若学号可能短于 6 位，需要产品确认是否保留；保留则应与后端校验对齐。
2. **邀请码 = 学号**来自服务端实现（`Where("student_no = ?")`）。页面文案已按「学号就是邀请码」表述，若产品不希望暴露学号概念，需要改成「老师提供的邀请码」并同步后端字段设计。
3. 后端对「查无此人（404）」与「已绑定或邀请码无效（400）」是两条不同文案，原型只演示前者；产品若要求区分提示，需在 UI 上补第二个错误分支。
4. 扫码为**模拟**：不申请相机权限，也不覆盖扫码取消 / 无权限 / 识别失败三种真实分支。
5. 本页不提供解绑入口（解绑在「我的 → 我的孩子」，`DELETE /parent/students/:id`），原型未越界新增。
6. 若产品希望本页同时支持「手机号 + 验证码」绑定，需要新增接口——当前后端没有这个能力，本次不虚构。
7. **本页在家长端没有入站入口**：`parent/src` 内没有 `navigateTo` / `redirectTo` 指向 `pages/auth/bind`，`App.vue` 也不处理场景值。建议在「我的 → 我的孩子」（23-student-index / 27-profile）增加「绑定新孩子」入口；该入口落在其他页面目录，属批次级统一处理，本页未擅自添加。
