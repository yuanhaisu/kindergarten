## 这个页面真实的产品事实

**页面定位**：老师每天打开小程序的第一屏。回答两个问题——「我班上今天什么情况」和「我现在要处理什么」。

**数据来源**（3 个接口，均需登录态）：
- `GET /teacher/home/overview` → 今日概览
- `GET /teacher/home/todos` → 待办列表（前端只渲染前 3 条）
- `PUT /teacher/home/todos/:id/action` → 处理待办，body `{ action, remark }`

**overview 真实字段**：
`date`、`weekday`、`class_info { id, name, title, title_label }`、`attendance { present, leave }`、`pending_approvals`、`unread_notices`、`teacher_name`。
前端兜底值：老师名默认「老师」，班级名默认「小一班」，职务默认「主班老师」。

**页面区块顺序（必须保持这个顺序）**：

1. **顶部问候区**：头像（老师姓名首字）+ 老师名 + 副行「班级名 · 职务」；右侧一个铃铛按钮（未读通知 > 0 时带红点），点击去「消息中心」。
2. **今日班级概况**：标题「今日班级概况」+ 当天日期（格式 `2026年10月24日 星期五`）；下面 4 个数字：**已出勤**、**请假**、**待审批**、**未读通知**。
3. **功能入口**：8 个磁贴，4 列 × 2 行，顺序固定为
   发布通知 / 成长记录 / 接送管理 / 亲子任务 / 班级日历 / 请假审批 / 班级相册 / 更多。
   每个磁贴 = 图标 + 文字，点击 `uni.navigateTo` 到对应页面（更多 → `/pages/more/index`，该页是完整入口聚合页）。
4. **待办事项**：标题「待办事项」+ 右侧「查看全部」（去 `/pages/more/index`）；最多 3 条。
   每条 = 类型图标（单字：审 / 通 / 录）+ 标题 + 描述 + 操作按钮。
5. **没有底部 tabBar**（见下方硬约束）。页面到底就是内容结束 + 安全区。

**待办的 4 种操作（真实文案，不要改写）**：

| action | 按钮文案 | 行为 |
|---|---|---|
| `approve` | 同意 | 调 `PUT .../action`，成功后 toast + 重新加载列表 |
| `reject` | 拒绝 | 先弹「拒绝原因」输入框，留空则 toast「请填写拒绝原因」并中止；填写后提交 |
| `share` | 转发 | 走小程序原生 `open-type="share"`，不调接口 |
| `go_record` | 去记录 | 直接跳 `/pages/growth/create`（添加成长记录） |

**三种状态的真实文案**：
- 加载失败：显示错误文案（如「班级数据加载失败」）+「重试」按钮
- 待办为空：「今天没有新的待办，保持轻松节奏。」（原文，一字不改）
- 处理成功：toast 提示接口返回的 message，如「已同意请假申请」

**角色差异**：首页 8 个入口对**所有老师固定**，不随角色变化。保健医（doctor）多出的「入园晨检」入口只出现在「更多」页，不在本页。所以本页不需要做角色分支。

**已知的展示现状（这次要改掉的）**：
- 顶部是一整屏品牌渐变，白卡片浮在上面，暖色占了半屏。
- 4 个数字用了绿/黄/红/蓝四种语义色，像仪表盘，四个都在喊。
- 8 个入口图标是位图，虽然已统一成暖橙，但 8 个同样重的方块没有主次。
- 3 条待办是 3 张独立阴影卡，每条按钮各自一种颜色（绿/红/蓝/紫），第二个彩虹。
- 页面底部画了一个模拟的 4 项底栏（首页/班级/消息/我的）——**这次不要画**，见硬约束。

## 示例数据（中文，幼儿园语境，数字必须自洽）

- 老师：**王老师**，**小一班 · 主班老师**
- 日期：**2026年10月24日 星期五**
- 概览：已出勤 **26**、请假 **2**、待审批 **3**、未读通知 **5**（26 + 2 = 全班 28 人）
- 待办 3 条：
  1. 类型 `approve` / `reject` —— 标题「**乐乐妈妈的请假申请**」，描述「**感冒发烧，请假 2 天（10月24日–10月25日）**」
  2. 类型 `share` —— 标题「**「秋季亲子运动会」通知未读提醒**」，描述「**还有 5 位家长未读，可转发提醒**」
  3. 类型 `go_record` —— 标题「**今日成长记录待提交**」，描述「**还未上传今日班级活动照片和记录**」

## 设计方向（一个方向，照做）

主题：**「今天」优先**。第一眼看到班级状态和要处理的事，功能入口退到第二层。

1. 去掉整屏渐变 header。问候区直接排在页面底色上，**不套卡片**——它只是「谁 + 哪天」。
2. 今日概况收成**一条数字带**：4 格用 1px 分隔线切开，数字统一用 `--fg` 的正常字重层级，**只有「待审批」用 `--accent` 加一点 `--accent-wash` 胶囊底**——它是唯一需要动作的数字。不要四色彩虹。
3. 功能入口 8 个：统一 `--accent-wash` 圆角底 + `--accent` **单色线性图标**，语义靠图形本身区分（这是产品已有的决定，延续它）。「更多」降级：用 `--muted` 处理，音量明显低于前 7 个。
   图标必须**内联 SVG**（stroke 用 `currentColor`），禁止外链图片、禁止 base64 图片、禁止 emoji 当图标。
4. 3 条待办合并进**一张卡片**，用 1px `--border` 分隔线分格——不要 3 张各自投影的卡。
5. 待办操作分主次：主操作（同意 / 转发 / 去记录）= `--accent-wash` 底 + `--accent` 文字胶囊；次操作（拒绝）= 透明底 + `--muted` 文字。操作放在描述下方**第二行右对齐**，触控高度 ≥ 44px。
6. 层级只靠字重 + 字号：标题 600、正文 400、标签 500。不要靠 4 种颜色分层。

## 视觉与结构硬约束

- `<html lang="zh-CN" data-surface="teacher">`
- 390px 手机视口；单列纵向流；不做桌面布局、不做横向滚动、不做侧边栏
- **微信小程序外壳（必须一眼可辨）**：
  - 20px 状态栏：左「9:41」，右侧信号 / wifi / 电池三个小图标（用 CSS 或内联 SVG 画，不用图片），颜色 `--fg-2`
  - 44px 导航栏：标题「**老师工作台**」居中、14px、600；**左侧不要返回箭头**（这是根页面）
  - 右上角**胶囊按钮**：约 86×32，1px `--border` 边框，`--radius-pill`，内为 `···` 与 `◎`，中间一条 1px 分隔线
  - 状态栏 + 导航栏固定顶部，内容区在下方可滚动
- **老师端没有 tabBar：页面底部不要画任何底栏、tabBar、底部导航。** 底部只留 `padding-bottom: calc(24px + env(safe-area-inset-bottom))`
- 颜色**只能**写 `var(--*)`，禁止裸 hex / rgb / hsl / 颜色名。需要 token 里没有的颜色就退回最接近的 token
- 无直角：最扁平元素 ≥ `var(--radius-sm)`；按钮/标签/头像 `var(--radius-pill)`；卡片 `var(--radius-card)`/`var(--radius-2xl)`
- 阴影只用 `var(--shadow-sm|md|lg)`，禁止写黑色投影
- 暖色（accent）面积 ≤ 10%：大面积是 `--bg` / `--surface` 中性底；渐变只允许出现在一个紧凑元素或主按钮上
- 触控目标 ≥ 44×44px；正文 ≥ 13px（`--text-base` 起）；对比度满足 WCAG AA
- 点击反馈只做 `:active` 缩放/压暗（`transform: scale(.98)` 或 `filter: brightness(.96)`），**信息不能只在 hover 时可见**
- 整页在 390×1000 截图内要看到完整主要内容（问候 + 概况 + 8 入口 + 3 条待办），不要出现大片空白，也不要内容溢出被裁

## 状态覆盖（数据区必须有，默认渲染正常态）

一个**原型演示**状态切换胶囊固定在右下角（半透明、小、标注「原型演示」、带关闭按钮，不能干扰主体视觉），可切换：

1. **正常**：上面的完整数据（默认）
2. **空**：待办区替换为图标位 + 原文案「今天没有新的待办，保持轻松节奏。」+ 一个主行动按钮「写今日记录」；概览数字保留
3. **加载**：概览 4 格数字变骨架块 + 待办区 2–3 行骨架屏（不要 spinner 转圈占满屏）
4. **错误**：待办区显示「班级数据加载失败」+「重试」按钮
5. **禁用**：正常态里点过「同意」的那条待办，按钮变成「已同意」灰态（`--muted` + `--surface-warm` 底 + `cursor: default` + `aria-disabled="true"`），点击无反应

## 交互必须真的能点（app.js）

- 状态切换胶囊能切 4 种状态，并能关闭
- 8 个功能入口点击有 `:active` 反馈 + toast「已打开 发布通知」这类
- 铃铛点击 → toast「已打开 消息中心」
- 「查看全部」点击 → toast「已打开 更多」
- 「同意」→ toast「已同意请假申请」+ 该行变灰态
- 「拒绝」→ 弹**微信风格居中对话框**（标题「拒绝原因」+ 多行输入 + 说明文案 + 取消/确定）；留空点确定 → toast「请填写拒绝原因」且对话框不关
- 「转发」→ 底部 action sheet（「发送给微信好友」「分享到班级群」两个选项 + 取消）
- 「去记录」→ toast「已打开 添加成长记录」
- toast 用小程序风格深色小胶囊居中偏下，2 秒自动消失；**禁止 `alert()` / `prompt()` / `confirm()`**
- 控制台无报错
