# 亲子任务（teacher）

- 源码：`teacher/src/pages/tasks/index.vue`
- 设计系统：`user:nurture-planet-local`，`surface=teacher`
- 方向：把「新建表单 + 星星罐 + 任务列表」的长页面拆成「先看任务、再建任务」，列表用参与进度与待回应构成可扫读的工作台。
- 信息层级：
  1. 顶部三段筛选（全部 / 进行中 / 已结束，带计数）
  2. 班级与待回应汇总（小一班 · 共 4 个任务 · 8 条待回应）
  3. 任务卡（标题 + 状态 → 频率/仪式/日期 → 说明 → 参与进度 → 星星 → 待回应 + 查看回应）
  4. 班级星星罐（次级设置，放在列表之后）
  5. 固定底部「＋ 新建任务」，表单收进底部弹层
- 覆盖状态：
  - 正常：4 张任务卡 + 星星罐；筛选计数 4 / 3 / 1。
  - 空：隐藏任务列表与筛选计数，保留星星罐；显示「还没有亲子任务」+ 新建任务按钮。
  - 加载：3 张骨架卡 + 星星罐骨架，筛选计数隐藏。
  - 错误：显示「任务加载失败」+ 重试，重试 600ms 后回到正常态。
  - 禁用：标题或「和幼儿园学习的关系」为空时创建按钮真禁用；个体任务隐藏公开开关。
  - 未配置 / 名单失败（演示条可切换）：「星星罐未设」时星星罐隐藏进度与百分比、显示「本学期还没设目标」，保存按钮变「设置目标」，弹层内「按班级」置灰；「名单失败」时范围选择器只剩「班级」，并显示「班级学生加载失败，点击重试；恢复前只能创建班级任务」。
- token 映射：
  - 页面/卡片：`var(--bg)` / `var(--surface)`；圆角 `var(--radius-card)`、`var(--radius-pill)`；阴影 `var(--shadow-sm)`。
  - 主进度/进行中：`var(--accent)` + `var(--accent-wash)`；已结束进度改为 `var(--muted)`，与状态语义一致。
  - 待回应：`var(--warning)` + `var(--warning-wash)`；错误：`var(--danger)` + `var(--danger-wash)`。
  - 正文与次要文字：`var(--fg)` / `var(--fg-2)` / `var(--muted)`；分隔线 `var(--border)`。
  - 深色文字 `--ink-brand` / `--ink-warning` / `--ink-muted` 均由 token 经 `color-mix` 派生，未引入裸色值。
- 与现状的差异：
  - 源码把新建表单、星星罐、任务列表依次铺在页面上；原型把新建改为底部弹层，列表成为首屏主体，星星罐降为列表后的次级卡片。
  - 新增客户端状态筛选（全部 / 进行中 / 已结束），只读真实 `status` 字段，不是新后端能力。
  - 新增参与进度（已参与 N/30）与待回应汇总，均来自真实字段/统计端点。
  - 「范围」按源码的 picker 语义改为弹层内可滚动选择器（「班级」固定首项 + 全班 30 人），不再用固定的 6 个孩子 pill；名单对应 `GET /teacher/class/students` 的一次全量返回，原型以 30 个演示姓名占位。
  - 学生名单加载失败沿用源码分支：范围选择器只剩「班级」，并给出可点击重试的提示；选择器支持上下键移动、Esc 先收起列表再关弹层。
  - 老师端无 tabBar，按子页画返回箭头。
- 验证：
  - `od-check --width 390`：`problems: []`，`overflowing: []`，无横向滚动。
  - 交互实测：筛选、打开/关闭弹层、必填校验、范围选择器（31 项滚动、选中学生后隐藏公开开关、Esc 先收列表再关弹层）、学生名单失败只剩「班级」并可重试恢复、星星罐未配置显示「设置目标」并置灰「按班级」、保存目标后恢复配置态、创建后插入列表并更新计数、四态切换与重试均通过；控制台无 error / warning。
  - 弹层与星星罐表单在 390px 下无控件重叠、无横向溢出（输入框统一 `box-sizing: border-box`）。
- 遗留 / 需产品确认：
  1. 列表接口未聚合 `已参与 N/M`，该数字来自 `GET /teacher/tasks/:id/stats`。真实实现需要列表聚合字段，或接受逐卡请求（N+1）。这是批次级接口决策。
  2. 列表头「8 条待回应」是各任务 `pending_responses` 之和；若产品只想强调本周期，需要改用 `pending_period`。
  3. 个体任务的 30 人来自全班人数，对个体无意义，因此显示「已提交 N 条」；需确认文案是否合适。
  4. `star_count === null` 时隐藏星星信息；`star_goal = 0` 时同样不展示，均按源码逻辑处理。
  5. 星星罐目标维护是否长期留在任务页，还是移到班级设置，需批次层面确认。
