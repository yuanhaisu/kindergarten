## 这个页面真实的产品事实

**页面定位**：老师扫码进入小程序后的第一屏。只有一件事——用微信身份登录，进入工作台。**没有账号密码表单，没有手机号输入，没有验证码，没有短信登录。** 不要发明这些。

**真实流程**（源码 `handleWxLogin`）：
1. 老师点主按钮 → 若未勾选协议，`uni.showToast` 提示「请先阅读并同意用户协议和隐私政策」，**按钮不置灰、流程中止**
2. 已勾选 → `submitting = true`，按钮文案变「**登录中...**」且 disabled（透明度降到 0.55）
3. 调 `bindPhoneLogin()` → 内部 `uni.login()` 拿 code → `POST /api/v1/auth/login/wechat`（`role: "teacher"`）
4. 成功 → toast「**登录成功**」→ `uni.reLaunch` 到 `/pages/index/index`（工作台）
5. 失败 → **不弹 toast**（1.5 秒就消失，失败原因读不到），改为在卡片内渲染**常驻错误条**，按钮文案变「**重新登录**」

**错误条的真实文案分档**（源码 `toLoginError`，一字不改地采用其中任一组）：

| 场景 | 标题 | 说明 |
|---|---|---|
| 邀请码无效/过期 | 邀请码无效或已过期 | 请向园方索取新的邀请码 |
| 邀请码对应的账号不存在 | 邀请码关联的教师账号不存在 | 请联系园方确认你的账号 |
| 微信层失败 | 微信登录失败 | 请稍后重试 |
| 网络层失败 | 网络异常 | 请检查网络后重试 |
| 兜底 | 登录失败 | 请稍后重试 |

**页面区块顺序（必须保持这个顺序，从上到下）**：

1. **品牌区**（两端共用的 `BrandBlock`）：圆形 logo + 品牌名「**养成星球**」+ tagline「**幼儿园数字化管理平台**」
2. **登录卡**（`AppCard`，白底、卡片圆角、`--shadow-md`）：
   - 错误条（仅失败时出现，浅红底 `--danger-wash`，**文字用 `--fg` 前景色而不是红色** —— 源码注释说明 `#EF4444` 压在 `#FEE2E2` 上只有 3.1:1，不达正文 4.5:1，所以错误语义只由浅红底承担）
   - 主按钮（`AppButton size="lg"`，品牌渐变底、白色文字、胶囊圆角、`--shadow-md`）
   - 协议勾选行：一个方形勾选框（未选：白底 + 1px 边框；已选：品牌色底 + 白色 ✓）+ 文案「**我已阅读并同意《用户协议》和《隐私政策》**」。**整行可点**，命中区高度 ≥ 44px
3. **底部说明**（卡片外）：「**仅对幼儿园老师开放，需园方统一开通账号**」
4. **没有 tabBar**：老师端没有 tabBar，本页尤其不可能有

**其他真实约束**：
- 已登录（有 token）时会 `reLaunch` 直接进工作台，**所以这一屏只对未登录老师可见** —— 不需要画「已登录」分支
- 协议名在协议页落地前**是纯文本**，源码特意没做成死链。原型里也**不要**给《用户协议》《隐私政策》加点击跳转
- 无角色/权限分支：能到这一屏的都是未登录状态

## 设计方向（一个方向，照做）

主题：**「推门」——一次呼吸的登录页**。

这是一个每天要打开十几次的入口，不是营销落地页。克制到只剩三层：**我是谁（品牌）→ 我怎么进去（一个按钮）→ 我同意了什么（一行协议）**。

1. **紧凑品牌 hero**：logo 圆标 68–76px，**不要**铺满整屏的渐变背景块，**不要**大插画。logo 用内联 SVG 画一个「温柔宇宙」的抽象标记——暖橙渐变球体 + 一道极细的倾斜轨道椭圆 + 轨道上一颗小点。轨道用 `--accent-soft` 低透明度，别做成科技感 HUD。
   - logo 后面允许一层**极淡的琥珀柔光**（`radial-gradient` 用 `--accent-wash` 起、透明止），直径约 180px，透明度压到能感觉但不抢——这是本页唯一的装饰。
2. **主行动唯一**：卡片里只有一个主按钮，文案「**微信授权登录**」。按钮宽度占满卡片内宽，高度 48–52px，胶囊圆角，`--accent-gradient` 底。
   - 按钮**左侧**放一个 20px 的白色微信对话气泡图标（内联 SVG，stroke/fill 用白色），让人一眼知道是微信授权，而不是普通表单提交。
3. **协议行的视觉重量要低于按钮**：12px（`--text-sm`）`--muted` 文字，勾选框 20px、`--radius-sm`圆角、1px `--border` 边框；已勾选时品牌色底 + 白色 ✓（带 150ms 过渡）。整行居中，可换行，不要 nowrap。
4. **错误条在按钮之上**，宽度占满卡片，`--danger-wash` 底、`--radius-lg` 圆角、`--space-md` 内边距，标题 14px/600 `--fg`，说明 12px/400 `--fg` 居中。错误条出现时，**不要把整页变成红色警报**，只是卡片里多了一小块。
5. **底部说明**用 `--hint`、12px，距离卡片 28–36px，像一句脚注，不像警告。
6. **垂直呼吸**：内容整体在视口里垂直居中（导航栏以下），上下留白充分但不空。390×1000 截图里要看到完整的一屏，底部有余量而非被裁。
7. **层级只靠字重 + 字号**：品牌名 20px/700、tagline 14px/400 `--muted`、按钮 15px/700、协议 12px/400、脚注 12px/400 `--hint`。不要给每个元素换一种颜色。

## 视觉与结构硬约束

- `<html lang="zh-CN" data-surface="teacher">`
- 390px 手机视口；单列纵向流；不做桌面布局、不做横向滚动、不做侧边栏
- **微信小程序外壳（必须一眼可辨）**：
  - 20px 状态栏：左「9:41」，右侧信号 / wifi / 电池三个小图标（内联 SVG，`currentColor`，颜色 `--fg-2`），不用图片
  - 44px 导航栏：标题「**老师登录**」居中、14px、600
  - **左侧不要返回箭头**（这是入口根页面，没有上一页）
  - 右上角**胶囊按钮**：约 86×32，1px `--border` 边框，`--radius-pill`，内为 `···` 与 `◎`，中间一条 1px 分隔线
  - 状态栏 + 导航栏固定顶部；内容区在下方
- **老师端没有 tabBar：页面底部不要画任何底栏、tabBar、底部导航。** 底部只留 `padding-bottom: calc(24px + env(safe-area-inset-bottom))`
- 颜色**只能**写 `var(--*)`，禁止裸 hex / rgb / hsl / 颜色名（包括渐变里的色标、`box-shadow`、`outline`）。需要 token 里没有的颜色就退回最接近的 token
- 无直角：最扁平元素 ≥ `var(--radius-sm)`；按钮 / 标签 / 头像 / 勾选框圆角走 token；卡片 `var(--radius-card)`
- 阴影只用 `var(--shadow-sm|md|lg)`，禁止写黑色投影
- 暖色（accent）面积 ≤ 10%：大面积是 `--bg` / `--surface` 中性底；渐变只允许出现在**主按钮**和**logo 圆标**两处紧凑元素上
- 触控目标 ≥ 44×44px；正文 ≥ 13px（`--text-base` 起），只有协议与脚注允许 12px（`--text-sm`）
- **禁止 `white-space: nowrap`** 用于任何可能超宽的文本（协议行、脚注、按钮文案都必须能换行或自然收缩）
- **所有容器 `max-width: 100%`**；页面不得出现横向滚动；多列布局若出现，用 `grid-template-columns: repeat(N, minmax(0, 1fr))`（本页其实不需要多列统计）
- 点击反馈只做 `:active` 缩放 / 压暗（`transform: scale(.98)` 或 `filter: brightness(.97)`），**信息不能只在 hover 时可见**
- 无 JS 报错；不用 `alert()` / `prompt()` / `confirm()`

## 状态覆盖（默认渲染正常态）

登录页没有列表数据，所以把共享约束里的「正常/空/加载/错误」映射成**这一屏真实存在的四种状态**。右下角固定一个「原型演示」半透明小胶囊（可展开、可关闭，不能干扰主体视觉），四枚芯片：

1. **正常**（默认）：勾选框已选、无错误条、按钮「微信授权登录」可点
2. **未同意**：勾选框空、按钮保持正常可点外观（**源码就是可点，点了弹提示**，不是置灰）。点按钮 → toast「请先阅读并同意用户协议和隐私政策」
3. **登录中**：按钮文案「登录中...」、`opacity: .55`、`disabled`、`cursor: default`；勾选框同步降为不可点。不出现整页 spinner
4. **失败**：卡片内出现错误条（「微信登录失败 / 请稍后重试」），按钮文案变「重新登录」，勾选状态保持已选

**禁用态**（约束里要求单列）由「登录中」承担：按钮与勾选框同时降透明度且点击无反应。演示条不需要第五个芯片。

## 交互必须真的能点（app.js）

- 状态切换胶囊能切 4 种状态，并能关闭
- 点协议整行 → 勾选框切换（`aria-checked` 同步），带 150ms 过渡
- 正常态点主按钮 → 进入「登录中」1.4 秒 → toast「登录成功」→ 回到正常态（原型不真跳页）
- 未同意态点主按钮 → toast「请先阅读并同意用户协议和隐私政策」，不进入登录中
- 失败态点「重新登录」→ 进入「登录中」1.4 秒 → toast「登录成功」→ 清除错误条回到正常态
- toast 用小程序风格深色小胶囊，居中偏下，2 秒自动消失
- 控制台无报错
