# 内嵌网页（老师端）

- 源码：teacher/src/pages/webview/index.vue
- 设计系统：user:nurture-planet-local，surface=teacher
- 方向：页面就是网页本身——微信 `<web-view>` 会铺满导航栏以下的整个页面并覆盖其他组件，因此不设地址条、刷新按钮、卡片外壳或脚注，只保留整屏网页区域与空态。

## 信息层级

1. 导航栏「详情」+ 返回箭头（源码 `pages.json` 标题为「详情」，非 tabBar 页，由 `navigateTo` 进入）
2. 网页区域：导航栏以下整屏铺满，对应源码独占页面的 `<web-view>`；正常态为中性占位（「内嵌网页」+ 一句说明），不伪造第三方内容
3. 原型状态条：正常 / 空态 / 加载 / 失败

## 覆盖状态

- 正常：整屏网页区域 + 中性占位（图标 + 「内嵌网页」+ 一句说明）。网页区域从导航栏下方一直铺到页面底部，没有卡片边框、页边距或页脚，模拟真实 `<web-view>` 的独占布局。
- 空态：对应源码 `v-else` 分支「未提供页面地址」。隐藏网页区域，整页居中（断链图标 + 一句「请从包含网页地址的入口进入本页」+ 返回主按钮）。
- 加载：整屏替换网页区域（小圆环 + 「正在加载网页…」+ 3 行骨架条），网页区域 `aria-busy="true"`。真实实现应在 `<web-view>` 挂载前显示，挂载后整屏交给网页。
- 错误：整屏替换网页区域（警示图标 + 「网页无法打开」+ 一句原因（网络异常 / 未开通内嵌网页能力）+ 「重新加载」主按钮 + 「返回上一页」文字按钮）。真实实现应在 `binderror` 时卸载 `<web-view>` 再显示本态，二者互斥。
- 禁用：页面没有需要常驻禁用的控件——旧方案的地址条刷新按钮已随页内 chrome 一起移除；重试按钮只在错误态出现，加载/错误互斥，不会出现可连点的加载中刷新。

## token 映射

- 页面底色 `var(--bg)`、整屏网页区域 `var(--surface)`、占位图标底 `var(--surface)`
- 占位图标边框用 `color-mix()` 由 `var(--border)` 调透明，不引入新色
- 错误图标 `var(--danger)` / `var(--danger-wash)`
- 正文 `var(--fg)` / `var(--fg-2)`、次要说明 `var(--muted)`、禁用 `var(--hint)`
- 圆角 `var(--radius-2xl)` 状态图标 / `var(--radius-xl)` 占位图标 / `var(--radius-pill)` 按钮与标签
- 阴影只 `var(--shadow-sm)`（占位图标）、toast 用 `var(--shadow-lg)`
- 字号 `var(--text-2xl)` 状态标题 / `var(--text-base)` 正文 / `var(--text-xs)` 标签；字重 `--weight-normal` / `--weight-medium` / `--weight-semibold`
- 动效 `var(--motion-fast)` / `var(--motion-base)` + `var(--ease)`，`prefers-reduced-motion` 下全部停用

## 与现状的差异

- 源码只有一个 `web-view` 与 `v-else` 空态，没有任何加载/失败表现；原型补齐加载、失败两态，但都作为整屏替代态、与 `<web-view>` 互斥渲染，不与其同屏共存。
- 微信 `<web-view>` 会自动铺满整个页面并覆盖其他组件，页内无法保留任何常驻 chrome。因此本页不放地址条、刷新按钮与容器脚注：地址条属于浏览器语汇，且会被网页盖住；用户要知道打开的是哪个链接，应由入口页或打开前的确认层承担。
- 源码没有重新加载能力；错误态的「重新加载」是新增的原型交互，真实实现需要重建 `web-view`（改 key 或重新赋值 src）。
- 失败文案里「当前小程序未开通内嵌网页能力」对应老师端是个人号、`<web-view>` 实际白屏的现状（已划出验收范围），原型需要把这个不可用原因讲清楚，而不是假装页面正常。
- 空态沿用源码文案「未提供页面地址」，补了引导语与返回按钮。

## 遗留

- 老师端为个人号，`<web-view>` 真实不可用；本原型只表达容器形态，不能作为可用性验收依据。
- 真实网页的加载进度、域名白名单校验、`bindmessage` / `binderror` 回调在原型中未体现，接入时需按微信文档补。
- 平台硬约束：真实 `<web-view>` 会铺满整页并覆盖其他组件，本页不得再增加任何页内 chrome（地址条、来源条、脚注、浮动刷新等）；若产品需要展示链接或来源，只能放在入口页、打开前的确认层，或改用自绘 H5 容器。
- 空态目前不可达（演示状态条可切），真实场景由入口是否传 `url` 决定。
