# 任务回应（老师端）

- 源码：`teacher/src/pages/tasks/detail.vue`（页面数据 `GET /teacher/tasks/:id`、`/stats`、`/checkins`；动作 `POST /teacher/tasks/:id/batch-response`、`/checkins/:cid/response`、`/checkins/:cid/supplement`、`PUT /checkins/:cid/public`）
- 设计系统：`user:nurture-planet-local`，`surface=teacher`
- 方向：**一页看清「谁交了、谁待审、下一步点什么」**。任务卡只负责定场景，统计摘要、两段主分段与审核 chip 合并成一张卡负责定位，审核待办压成逐卡的「说明 → 勾选 → 批准」三步，公开类动作统一走微信居中对话框。

## 信息层级（从上到下）

1. 导航栏「任务回应」+ 返回箭头 + 微信胶囊（由任务列表 `navigateTo` 进入的子页；老师端无 tabBar）
2. 任务卡：`进行中`/`每日` 胶囊 → 标题「每日阅读15分钟」→ `小一班 · 10月20日 ~ 10月26日 · 全班` → `学习关联` + 一句主题说明 → 任务说明 → 星条 `本任务已集 18 星 / 按班级星星罐`
3. 统计 + 分段 + 审核筛选合并成一张卡（计数只保留一处，避免四层连续堆叠）：
   - 摘要行 `28 应交` / `6 已提交`（只在这里出现）
   - 两段主分段 `待回应 3` / `已回应 3`（对应源码仅有的 `status=pending|responded`）
   - 审核状态 chip（横向，非下拉）：`全部 6` / `待审核 2` / `已公开 1` / `未公开 1`；计数是全局的，筛选只作用于当前段，空结果给出「切到另一段看 N 条」
4. 待回应段：汇总条 `一键送贴纸（本周期）` + 小字 `「加星」才计入星星罐；贴纸回应不计星` → 逐条回应卡
5. 已回应段：逐条回应卡（含老师的回应/补充回应）
6. 任务设置卡：`编辑任务 ›` / `生成小程序码 ›`（源码里这两块挂在任务头部，原型下沉到列表末尾，避免抢审核主线的注意力）
7. 右下角 `mp-demo`：正常 / 空态 / 加载 / 失败

回应卡内部顺序（与源码一致）：首字头像 + 孩子名 + 「家长提交」→ 提交时间 → 正文（空内容显示「（一键完成）」）→ 旧周期提示（`旧周期 · 请逐条回应`）→ 单张媒体方图 → 审核块（状态 + 说明 + 勾选 + 批准/拒绝，或已公开/未公开文案 + 撤回）→ 底部操作 `❤️` `👍` `加星` `录音` → 老师回应/补充回应。

## 审核四态的界面语义

| `public_status` | 界面文案 | 可做的动作 |
|---|---|---|
| `pending` | `待审核` + `家长申请公开，待你审核` | 勾选确认 → 批准公开；拒绝 |
| `approved` + `public_visible` | `已公开` + `已公开 · 本班家长可见` | 撤回公开 |
| `approved` + 公开关闭 | `已通过` + `已通过，暂不对本班展示` | 撤回公开 |
| `revoked` | `未公开` | 无（等待家长重新申请） |
| 无公开申请 | 不渲染审核块 | 无 |

批准/拒绝/撤回/关闭公开都走微信居中对话框二次确认；批准与撤回提交中按钮显示 spinner（`批准中…` / `处理中…`）并锁住卡片内其它按钮。编辑弹层里的公开开关只是**暂存**：确认关闭后提示「已关闭公开，保存后生效」，点「保存」才切换页面公开状态，取消或关闭弹层不改动已公开内容（与源码「先改 `edit.allow_public`、`saveEdit` 才提交」一致）。

## 与现状的差异

1. **只保留源码真实存在的两段**：源码只有「待回应 / 已回应」，没有「已通过 / 已退回」。因此没有发明「已退回」分段；审核状态改用 chip 表达，且 chip 计数全局、筛选只作用于当前段（跨段时给「切到另一段」的跳转）。
2. **`revoked` 统一叫「未公开」，不区分谁撤回**：源码 `publicStateText()` 注释写明「老师拒绝」与「家长取消」写的是同一个 `revoked_at`，不替任何一方下结论。原型沿用中性文案。
3. **不显示家长姓名/头像**：`/checkins` 只下发 `student`，没有家长对象。每条卡只显示孩子名 + 「家长提交」标签；补家长信息需要改契约。
4. **一条提交只画一张图**：源码只有单个 `media_url`，家长端 `chooseImage({count:1})`。媒体区是 3 列网格中的 1 个方图，不伪造九宫格/多图。
5. **批准前必须显式勾选**：与源码 `scope_confirmed=true` 契约一致；未勾选时按钮禁用，点击提示「请先勾选确认内容中只有提交者孩子」。
6. **公开开关关闭后的降级**：与源码 `publicStateHint` 一致，待审核卡隐藏勾选与批准，只留拒绝；已公开卡文案切换为「已通过，暂不对本班展示」。
7. **旧周期逐条处理**：源码 `isCurrentPeriod()` 只在当前周期允许一键汇总；旧周期卡片内加一行 `旧周期 · 请逐条回应`，汇总条也注明「本周期」。
8. **编辑/分享下沉**：源码把编辑任务和生成小程序码放在任务信息区，会与审核动作争夺视线；原型收进底部「任务设置」卡，编辑走底部弹层，保存后按源码的「结构已锁定」提示只读展示结构。保存前校验与 `saveEdit` 对齐：任务标题与学习关联都必填，缺任意一项就就地提示、不落库（避免 hero 上留下空的「学习关联」行）。
9. **补充回应默认收起**：每条**有主回应**的已回应卡都提供「补充回应（个别夸一句）」入口（果果/一诺/可心三张一致，对应源码 `status === 'responded' && row.response`）；已有历史补充的果果先显示「补充回应 1 条 🌸 读得很认真」，点开才是 4 个补充贴纸 + 录音 + 源码提示「补充回应不发通知…不发星星」，避免长列表被设置项撑开。

## 遗留

- **家长身份缺口（需产品/后端确认）**：审核场景里老师往往需要知道是哪位家长提交的，但 `/teacher/tasks/:id/checkins` 只返回 `student`。若要显示家长姓名/头像，需在契约中补 `parent` 字段；原型不虚构。
- **「已退回」在产品上是否要独立状态（需产品确认）**：当前 `revoked` 同时承载老师拒绝与家长取消，无法在列表里回放「谁退回的」。若产品要区分，需要在 `public_status` 之外增加 `revoked_by` / 拒绝原因。
- **审核 chip 的口径（需产品确认）**：现在 `全部 6` 含 2 条从未申请公开的提交，而其余三档只统计有 `public_status` 的行。若产品希望「全部」只算可审核的 4 条，应改计数口径。
- **一键汇总只演示前端结果**：点击后 spinner + toast「已回应 3 条」，不会真的把三张卡从待回应移到已回应（原型不连后端）；同理「刷新」只 toast，不重新拉数据。
- **媒体与语音是模拟**：图片是 CSS 渐变 + 「照片」图标占位；录音是计时器模拟（点一下开始、再点发送），语音播放只切换播放态，不发声。
- **文件体积超建议**：`index.html` 34.6KB / `styles.css` 30.9KB / `app.js` 16.2KB，超过共享 brief 的「每文件 < 20KB」建议；原因是 6 条完整回应卡 + 审核四态 + 两套弹层 + 四态骨架都静态写在页面里。无外部资源、无内联大图，门禁与交互均通过。若要压到 20KB 内，需要把回应卡改成 JS 模板渲染（会牺牲静态可读性）。
