## 这个页面真实的产品事实（照此设计，不要发明功能）
老师从「亲子任务」列表点进一个任务，查看家长/孩子的打卡提交，逐条回应，并审核家长的公开申请；页面底部还有任务设置入口。

页面区块顺序（从上到下）：
1. **任务信息卡**
   - 状态胶囊「进行中」（`task.status=1`）+ 频率「每日」（`frequency: once|daily|weekly`）
   - 标题（`title`，如「每日阅读15分钟」）
   - 一行元信息：班级「小一班」、任务日期「10月20日 ~ 10月26日」、范围「全班（班级任务）」（`target_student_id=0` 即全班）
   - 「学习关联：……」一行（`learning_link`）
   - 任务说明（`description`，2 行以内）
   - 星星条：任务默认仪式为「贴纸」；`star_scope=class` 时显示「按班级星星罐」与「本任务已集 18 星」（`task.star_count`）。**不要**画星星目标进度环（班级目标不在此接口返回）。
2. **参与统计卡**：四列，`grid-template-columns: repeat(4, minmax(0, 1fr))`：应交 28（`total_students`）、已提交 6（`submission_count`）、待回应 3（`pending_count`，用品牌色强调）、已回应 3（`responded_count`）。
3. **主分段（源码真实选项，两段）**：「待回应 3」/「已回应 3」。切换后列表切换。待回应是默认段。
4. **审核状态筛选（移动端 chip 横排，禁止 `<select>` / 桌面下拉）**：全部 6 / 待审核 2 / 已公开 1 / 未公开 1。对应接口 `public_status`：`pending|approved|revoked`；没有申请过公开的提交（`none`）只出现在「全部」。老师拒绝与家长取消都落在 `revoked`，源码文案是「未公开」，**不要**写「已退回」替家长/老师下结论。
5. **待回应段**
   - 顶部汇总条（仅每日/每周的班级任务有）：主按钮「一键送贴纸（本周期）」（任务仪式是贴纸时；若是 `class_star` 则为「一键送星（本周期）」）。下面一行小字：「加星」才计入星星罐；贴纸回应不计星。
   - 每条提交卡片：
     - 头部：孩子头像（无图用姓名首字占位）+ 孩子姓名 + 小标签「家长提交」+ 提交时间（`created_at`，如「今天 20:15」；旧周期的写「10月24日 18:40」）
     - 正文（`content`；空内容源码显示「（一键完成）」）
     - 媒体：**一次提交只有一个 `media_url`（家长端 chooseImage count=1）**，所以每张卡最多一张方图，放在 3 列网格里占 1 格（不要伪造 3/6/9 张图）。点图打开底部弹层预览（CSS 渐变占位，放大 + 孩子名 + 时间 + 关闭）。
     - 旧周期提示：`row.date` 不在任务当前周期内时，显示一行警示「旧周期 · 请逐条回应」。
     - 公开审核块（仅 `public_status` 为 pending/approved/revoked 时出现）：
       - pending：琥珀色底，状态「待审核」，说明「家长申请公开，待你审核」；一行可点选确认「☐ 我确认内容中只有提交者孩子」；按钮「批准公开」（未勾选时禁用降级）与「拒绝」。
       - approved：绿色底，状态「已公开」，说明「已公开 · 本班家长可见」；按钮「撤回公开」。
       - revoked：中性底，状态「未公开」，说明「未公开」；没有按钮。
     - 回应操作行：贴纸按钮 ❤️ 与 👍（星星任务下不把 ⭐ 当普通贴纸）、文字按钮「加星」、「录音」。点击有 `:active` 反馈。
   - 第一张卡（乐乐）为 pending 审核；第二张卡（小雨）无公开申请、内容为空显示「（一键完成）」；第三张卡（朵朵）为 pending + 旧周期。
6. **已回应段**
   - 每条卡片头部同上；下方「你的回应」块：贴纸（如 ⭐）、语音（「🔊 点击播放语音」）、或班级星星（「⭐ 班级星星」）；可选回应文字（`response.content`）。
   - 果果一条：已公开（可撤回）+ 贴纸回应 + 「补充回应 1 条」+ 可展开「补充回应（个别夸一句）」面板（4 个补充贴纸 + 「录语音补充」+「收起」；源码提示：补充回应不发通知，家长在任务详情里看到；不发星星）。
   - 一诺一条：语音回应 + 未公开。
   - 可心一条：班级星星回应 + 没有公开申请（不画审核块）。
7. **任务设置卡（页面底部）**：两行 cell ——「编辑任务 ›」「生成小程序码 ›」。
   - 编辑任务打开底部弹层：标题 input、说明 textarea、学习关联 input、「允许家长申请公开」switch；下方**结构只读区**（已有 6 条提交，结构锁定）：频率 每日 / 日期 10月20日 ~ 10月26日 / 范围 全班（班级任务）/ 仪式 贴纸 / 星星 按班级（使用班级罐目标）· 已集 18 星；提示「已有 6 条提交，结构已锁定；要调整结构请新建任务」；底部「取消 / 保存」。
   - 关闭公开是破坏性操作：switch 从开切到关时，弹微信风格居中对话框「关闭公开？/ 关闭后，已公开内容将全部撤下，家长需要重新申请。/ 取消 / 确认关闭」。确认后 switch 关闭，待审核卡片里的「批准公开」与勾选框隐藏，改成一行说明「任务已关闭公开，不能批准；可撤回申请」。
   - 生成小程序码：cell 进入生成中状态（文字变「生成中…」），约 0.9 秒后 toast「已保存到相册，可转发班级群」。不画二维码弹层。
8. **审核二次确认（微信风格居中对话框）**：拒绝公开 →「拒绝公开申请？/ 拒绝后家长需要重新申请，这条内容不会出现在班级墙。/ 取消 / 拒绝」；撤回公开 →「撤回公开？/ 撤回后本班家长将看不到这条内容，家长需要重新申请。/ 取消 / 确认撤回」。批准公开不用再加对话框（勾选确认本身就是二次确认），但按钮要 loading。
9. **提交中 loading**：批准/拒绝/撤回点击后，按钮变「批准中… / 处理中…」带小圆环 spinner，同卡其他操作禁用；约 0.8 秒后落到新状态并 toast。

**不要发明**：家长姓名/头像（接口只返回 `student`，没有家长对象）、一条提交多张图、置顶、删除、导出、评论、评分排名。页面没有底部 tabBar（老师端一律没有）。

## 视觉与结构硬约束
- `<html lang="zh-CN" data-surface="teacher">`，390px 手机视口，单列纵向流，不做桌面布局。
- **外壳必须原样使用共享 shell**：先读 `D:/yuanhaisu/personal_projects/kindergarten/docs/design-previews/2026-10-25-full-redesign/_shared/shell.md` 与 `shell.css`，照抄其中的 `mp-statusbar` / `mp-time` / `mp-status-icons` / `mp-navbar` / `mp-back` / `mp-title` / `mp-capsule` / `mp-main` / `mp-demo` 标记与 SVG。引入顺序：`tokens.css` → `../../_shared/shell.css` → `styles.css`；末尾引入 `../../_shared/shell.js` 再引入 `app.js`。
- **禁止把 shell.css 复制进项目**，也不要改写状态栏 SVG；只写 `<link href="../../_shared/shell.css">`，文件在当前项目里不存在也没关系（最终由流程拼装）。
- **styles.css 里绝对不许出现任何 `.mp-*` 选择器或覆盖**（唯一例外是 `[data-state]` 状态选择器，写成 `.mp-app[data-state="empty"] .xxx`）。
- 子页：导航栏保留返回箭头，标题「任务回应」。老师端**不画 tabBar**。
- 颜色只写 `var(--*)`，禁止裸 hex / rgb / hsl；无直角（最小 `var(--radius-sm)`）；阴影只用 `var(--shadow-*)`。暖色（橙）面积 ≤ 10%：橙色只用在「待回应」强调数字、主按钮「一键送贴纸」、选中分段、少量标签；大面积保持暖奶白/白色。
- 微信小程序语汇：分段控件是胶囊/分段条，筛选是横向 chip，不用 `<select>`；底部弹层做图片预览与编辑；危险确认用居中对话框；不用 alert / prompt。
- 触控目标 ≥ 44×44px；正文 ≥ 13px；`:active` 必须有反馈（缩放或压暗）。
- 禁止对可能超宽的文本用 `white-space: nowrap`；多列统计用 `grid-template-columns: repeat(N, minmax(0, 1fr))`；所有容器 `max-width: 100%`，页面不得横向滚动。
- 状态覆盖（`data-state` 驱动，演示条用 `mp-demo`）：
  - 正常（默认）：完整任务 + 统计 + 列表；
  - 空：隐藏列表与汇总条，在列表区显示空态（图标位 + 「还没有家长提交回应」+ 主按钮「生成小程序码」+ 次按钮「刷新」），任务信息与统计保留（统计数字切到 28 / 0 / 0 / 0，分段计数 0 / 0）；
  - 加载：整页内容区换骨架屏（任务卡 3 行 + 统计 4 格 + 3 张提交卡骨架）；
  - 失败：一句话「回应加载失败」+ 说明「网络异常，未获取到提交列表」+「重试」按钮。
- 演示状态条 `mp-demo` 默认收起；页面没有固定底栏，用默认 bottom。
- 所有文本必须能换行；数字列用 `minmax(0, 1fr)`，长任务标题、长说明、长回应都必须自然折行。

## 交互（app.js，全部真实可点，无 console 报错）
- 主分段切换待回应 / 已回应列表；汇总条只在待回应出现。
- 审核 chip 筛选当前列表；无结果时显示「当前筛选下没有记录」；状态变化后 chip 计数实时更新。
- 勾选确认 → 启用「批准公开」；批准 → 按钮 spinner「批准中…」→ 卡片变已公开；拒绝 / 撤回 → 居中对话框 → 确认后 spinner → 卡片变未公开；toast 提示。
- 媒体缩略图 → 底部预览弹层；点遮罩/关闭按钮收起。
- 贴纸 / 加星 / 录音按钮 → toast（录音按钮切换为「停止」红态，再点 toast「语音已发送」）。
- 一键送贴纸 → 按钮 spinner「汇总中…」→ toast「已回应 3 条」。
- 补充回应展开 / 收起；点补充贴纸 → toast「已追加补充回应」。
- 编辑任务弹层、公开 switch 与关闭公开对话框、保存 toast；生成小程序码进入生成中再 toast。
- 空态按钮「生成小程序码」也走生成流程；「刷新」toast「已刷新」。
- 四态切换条可切换 normal / empty / loading / error。
