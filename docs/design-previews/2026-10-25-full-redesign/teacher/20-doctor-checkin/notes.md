# 入园晨检（老师端 · 保健医）

- 源码：`teacher/src/pages/doctor/checkin.vue`（接口 `GET /api/v1/doctor/health/queue`、`POST /api/v1/doctor/health/checks`）
- 设计系统：`user:nurture-planet-local`，`data-surface="teacher"`
- 外壳：外链 `_shared/shell.css` + `shell.js`（未复制、未改状态栏 SVG）；老师端无 tabBar；由 `navigateTo` 进入的子页，画返回箭头
- 方向：把「排队等晨检」做成一张可展开的检查台——一眼看清谁还没检，点开就地逐项勾，异常用浅底红标，而不是整屏警报。

## 信息层级

1. 今日卡：`10月26日 周一` + 测温政策胶囊（`按需测温 · 体温选填`）+ 总入园 / 待检 / 已完成三格
2. 园级事件入口（`→ pages/doctor/calendar`）：今日卡下方、班级筛选之上，与源码同序，首屏可见
3. 班级筛选：全部 / 小一班 / 中二班 / 大一班，切换即联动统计与待检、已完成两个列表
4. 待检列表：每个孩子一行（头像、姓名、`班级 · 入园时间`），右侧「待晨检 / 检查中」+ 展开箭头；一次只展开一人
5. 展开的检查面板（行内手风琴）：体温（按 policy 标「选填」，超过阈值即时提示）→ 喉咙 / 手部 / 口腔 / 眼睛 / 皮肤 五行三态 chips → 异常项出现拍照入口 → 备注 0/200 → 隔离开关 → 三档结论按钮
6. 已完成（可整块收起）：健康 / 需观察 / 劝返三色标签

## 状态覆盖

- 正常：18 人 / 待检 5 / 已完成 13；分班自洽（小一班 5·2·3、中二班 6·2·4、大一班 7·1·6），已完成为 10 健康 / 2 需观察 / 1 劝返
- 空：待检 0，三格变 18 / 0 / 18，已完成 18 行（按入园时间排序）；统计、列表与空态文案（18 名已完成 / 3 人需留意）都由 records 派生，提交过的结论不会被重置；「查看已完成」只做滚动定位，不改数据
- 加载：统计数字与待检列表一起换骨架（3 行 shimmer）；演示态保持到切走，不自动回跳
- 错误：整页错误卡「晨检数据加载失败」+ 重试；重试 700ms 后回正常，按钮防重复点击
- 禁用：提交中该卡全部输入与按钮 `disabled`，操作区透明度 0.55
- 局部：首次提交必失败 → 面板内联「提交失败，请重试」+ 重试；成功后该生移入已完成，顶部 toast「需观察 · 已通知家长」

## token 映射

- 页面 / 卡片 / 描边：`var(--bg)`、`var(--surface)`、`var(--surface-warm)`、`var(--border)`、`var(--radius-card)`、`var(--radius-pill)`、`var(--shadow-sm)`
- 主行动：`var(--accent-gradient)`（健康入园）；需观察 `var(--warning)` + `var(--warning-wash)`；劝返 `var(--danger)` + `var(--danger-wash)`
- 检查 chips：选中「正常」`var(--success)` + `var(--success-wash)`；选中异常 `var(--danger)` + `var(--danger-wash)`；未选中性 `var(--surface-warm)` + `var(--muted)`
- 发热提示、提交失败、隔离开启：`var(--danger-wash)` 底 + `var(--danger)` 字
- 文本：`var(--fg)` / `var(--fg-2)` / `var(--muted)` / `var(--hint)`；字号 `var(--text-*)`；数字 `font-variant-numeric: tabular-nums`

## 与现状的差异

- 源码是「点一行 → 底部弹层填表」；改为行内手风琴，队列上下文不丢，一次只展开一人
- 检查项从分段/下拉改为三态 chips，异常选中立刻变浅底红；异常项才出现拍照入口（源码拍照挂在每个检查项旁）
- 结论三键保留源码语义与顺序，但用「主按钮渐变 + warning/danger 浅底」分档，避免整屏红
- 体温按 `policy.temperature_required` 显示「选填」；填写后 ≥ `fever_threshold`（37.3）立即提示「38.1°C 高于阈值 37.3°C」
- 待检行状态：源码只有「待检查」；原型展开后变「检查中」，提交中禁用全部控件
- 已完成列表可整体收起（源码固定展开），长名单下页面更短
- 未发明字段：`精神状态` 不在 queue / 提交契约里，未画；隔离文案沿用源码「已带到隔离室等待家长」
- 空 / 加载 / 错误：源码分别是一行文字、一行「加载中」、toast；原型做成完整三态并可重试
- 统计标签「待检查」缩为「待检」，与三格窄宽度对齐，语义不变

## 遗留

- 数据为原型固定数据（18 人：5 待检 / 13 已完成），提交只改内存，刷新还原
- 首次提交必失败是刻意留的失败态演示（面板内有「演示：本次提交被模拟为网络失败」说明），重试即成功，不接真实 `POST`
- 体温只做阈值提示，不做必填拦截（本园 policy 为选填；园所开启必填时源码会 toast「本园要求录入体温」）
- 拍照只做占位（原型不生成图片）；备注 200 字由 `maxlength` 限制，仅计数展示
- 「加载」演示态保持到切走（不自动回正常），便于审阅；真实请求结束后自行退出
- 为修 `od-check` 横向溢出，`styles.css` 顶部补了 `box-sizing: border-box`、`html, body` 去默认 margin、`[hidden] { display: none !important }` 三条基础规则，不改 token
- 对比度沿用批次 token（主按钮白字压暖橙渐变 1.90–2.35:1，语义色压同色浅底 2.74–3.08:1），低于 WCAG AA；按 `_shared/REVIEW.md` §6.4 回 `shared-design-tokens/tokens.json` 统一修，本页不单独打补丁
- `app.js` 约 25KB，超过 20KB 建议值（od-audit 仅提示，不阻断）
