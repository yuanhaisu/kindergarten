## 这个页面真实的产品事实（照此设计，不要发明字段）

老师从「班级日历」页点「+ 添加」进入本页，新建一条**本班**活动（园级事件不由老师创建）。页面是一个表单，从上到下三个分组卡片 + 底部固定提交栏：

1. **基本信息**
   - **活动标题** `title`：单行文本输入，必填，占位「请输入活动标题」。
   - **活动类型** `event_type`：必填，默认选中「活动」。5 个选项来自园所字典 `calendar_event_type`，内置为：**通知、活动、假期、家长会、体检**（键 `notice / activity / holiday / meeting / checkup`）。源码用一排可点按钮表示，选中态为品牌色描边 + 浅底 + 加粗。
   - **活动描述** `description`：多行文本，选填，占位「请输入活动描述，如活动内容、注意事项等」。
2. **时间地点**
   - **活动日期** `event_date`：必填，格式 `YYYY-MM-DD`。源码是点开后输入；本原型改为**底部日期滚轮弹层**（年 / 月 / 日三列，中间行高亮，顶部「取消 | 活动日期 | 完成」）。
   - **活动时间** `start_time` / `end_time`：两个独立的时间值，默认 `09:00` 与 `10:00`，格式 `HH:mm`。分别点开**底部时间滚轮弹层**（时 / 分两列，顶部「取消 | 开始时间 / 结束时间 | 完成」）。
   - **活动地点** `location`：单行文本，选填，占位「请输入活动地点」。
   - **全天活动** `is_all_day`：开关，默认关；副文案「不设具体时刻（如假期）」。开启时开始/结束时间两行置灰不可点，值显示「全天」。
3. **发布设置**
   - **通知家长** `notify`：开关，默认开；副文案「发布后向本班家长推送通知（可在通知模块查看已读）」。
   - 卡片脚注一句事实：**存为草稿不会通知家长**（接口契约明确草稿不产生通知）。
4. **底部固定提交栏**：左「存草稿」次按钮，右「发布活动」主按钮（品牌渐变）。上方一行 12px 浅灰摘要，如「活动 · 10月30日 09:00–11:30 · 通知家长」。必须处理安全区：`padding-bottom: calc(12px + env(safe-area-inset-bottom))`，内容区底部留出等高空白，最后一屏卡片不被遮住。

**校验与提交（原型必须真的按这个逻辑工作）**
- 必填未填时**不许事后 toast**：在字段下方就地显示 `--danger` 小字提示（标题 →「请输入活动标题」，日期 →「请选择活动日期」），同时把底部摘要替换成「还差标题和日期」这类阻断文案，主按钮置灰禁用；用户补齐后提示消失、按钮恢复。
- **时间冲突**：非全天时若结束时间不晚于开始时间，在时间行下方就地显示「结束时间需晚于开始时间」，并阻断提交。
- 点「发布活动」通过校验后：按钮进入 loading（小转圈 + 文案「发布中…」，两个按钮都不可点），约 1.4 秒后顶部 toast「发布成功」。
- 提交失败时：表单内容保留，底部栏上方出现一条 `--danger-wash` 底的失败条「发布失败：网络异常，请重试」+「重试」按钮，主按钮恢复可点。

**源码里不存在、绝对不要画的字段/控件**：参与班级/班级多选（创建接口无 `class_ids`，作用域由老师所在班决定）、报名人数上限、费用、重复日程、提醒提前几分钟、是否置顶、封面图/附件、参与人名单、审批流。

## 视觉与结构硬约束
- `<html lang="zh-CN" data-surface="teacher">`，390px 手机视口，单列纵向流，不做桌面布局。
- **外壳必须原样使用共享 shell**：先读 `D:/yuanhaisu/personal_projects/kindergarten/docs/design-previews/2026-10-25-full-redesign/_shared/shell.md` 与 `shell.css`，照抄其中 `mp-statusbar` / `mp-time` / `mp-status-icons` / `mp-navbar` / `mp-back` / `mp-title` / `mp-capsule` / `mp-main` / `mp-demo` 的标记与 SVG，不许自造状态栏。
- 引入顺序：`tokens.css` → `../../_shared/shell.css` → `styles.css`；末尾先 `<script src="../../_shared/shell.js"></script>` 再 `<script src="app.js"></script>`（app.js 监听 `document` 的 `mp:state` 事件）。
- **禁止把 shell.css 复制进项目**，也不要改写状态栏 SVG；只写 `<link href="../../_shared/shell.css">`，文件在当前项目里不存在也没关系（最终由流程拼装）。
- **styles.css 里绝对不许出现任何 `.mp-*` 选择器或覆盖**（唯一例外是 `[data-state]` 状态选择器，可写成 `.mp-app[data-state="empty"] .xxx`）。
- 子页：导航栏**保留返回箭头**，标题「添加活动」。老师端**不画 tabBar**。
- 表单节奏参考小程序 cell：分组标题在卡片外（12px `--muted`），卡片 `var(--radius-card)` + `var(--shadow-sm)`；可点的行（日期/开始时间/结束时间）右侧显示当前值 + `›` 箭头，行高 ≥ 52px，整行可点。
- 输入类字段用「标签在上、输入在下」的堆叠式（标题、描述、地点），标签 13px/500；不要用桌面端 label 右对齐表单项。
- 颜色只写 `var(--*)`，禁止裸 hex / rgb / hsl；无直角（最小 `var(--radius-sm)`）；阴影只用 `var(--shadow-*)`。
- **暖色克制**：橙色只出现在选中的类型胶囊、开关开启态、顶部日期/时间值、底部「发布活动」按钮；大面积是 `var(--bg)` 与 `var(--surface)`。
- 触控目标 ≥ 44×44px；正文 ≥ 13px；`:active` 必须有反馈（缩放或压暗）。
- 禁止对可能超宽的文本用 `white-space: nowrap`；所有容器 `max-width: 100%`，页面不得横向滚动；长标题/描述/地点自然折行。
- 不用 `<select>`、alert、prompt；无 console 报错。

## 状态覆盖（`data-state` 驱动，演示条用 `mp-demo`，五个芯片：正常 / 空态 / 加载 / 提交中 / 失败）
- **正常**：上面的示例数据已填，摘要完整，「发布活动」可点（`aria-disabled="false"`）。
- **空态**：标题、描述、地点清空，日期显示「请选择日期」；标题与日期下方各显示 `--danger` 提示；摘要变成「还差标题和日期」；主按钮置灰禁用（`--surface-warm` 底 + `--border` 边 + `--muted` 字，`aria-disabled="true"`）。
- **加载**：三张卡片内容换成骨架条（标题输入条、5 个胶囊占位、2 行 cell 占位、开关占位），摘要「正在加载…」，两个按钮禁用。
- **提交中**：表单保持正常态内容但整体不可编辑（输入/胶囊/开关 `aria-disabled` 且视觉降级），主按钮内小转圈 +「发布中…」，摘要「正在发布…」，次按钮禁用。
- **失败**：表单保持正常态内容，底部栏上方出现失败条（`--danger-wash` 底、`--danger` 图标与文字）「发布失败：网络异常，请重试」+「重试」按钮；点「重试」→ 失败条收起、toast「已重新提交」、恢复可提交。
- 另外（与芯片独立）：正常态下手动清空标题或把结束时间调到早于开始时间，再点「发布活动」，必须就地出现对应错误并阻止提交，`data-state` 不变。

## 交互（app.js，全部真实可点）
- 类型胶囊单选，切换选中态。
- 两个开关可切换；「全天活动」开启时两个时间行置灰不可点，值显示「全天」并收起时间校验。
- 日期 / 开始时间 / 结束时间 → 打开底部滚轮 sheet，可滚动选择（CSS scroll-snap），「取消」关闭不改值，「完成」写回并更新摘要。
- 点击「存草稿」：同样先做必填校验（标题、日期），通过后按钮 loading「保存中…」→ toast「已存草稿」。
- 点击「发布活动」：按上面的校验与提交逻辑；空态芯片下按钮禁用不可点。
- 演示条芯片切换五态；`mp-demo` 需用行内 `style="bottom: calc(112px + env(safe-area-inset-bottom))"` 避让底部固定栏（这是唯一允许的行内外壳覆盖）。
- 所有按钮/行有 `:active` 反馈；无 console 报错。
