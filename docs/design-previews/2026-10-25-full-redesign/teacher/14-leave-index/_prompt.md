## 这个页面真实的产品事实（照此设计，不要发明字段）

老师从工作台点「请假」进入（`uni.navigateTo` 子页）。页面作用域是**老师自己带的班**，数据由后端按班级过滤，页面本身没有班级筛选器。老师在这里审批家长提交的请假申请。

**数据结构（列表项，全部真实存在）**
- `student.name`（孩子姓名）、`student.avatar`（可能为空）
- `applicant.nickname`（提交家长昵称，如「乐乐妈妈」；老师端接口**不返回** relation 文案）
- `reason`（请假事由，可能为空 → 显示「未填写」）
- `start_date` / `end_date`（`YYYY-MM-DD`）、`days`（天数）
- `status`：0 待审批 / 1 已同意 / 2 已拒绝；`status_label` 为对应中文
- `created_at`（提交时间，RFC3339）、`reviewed_at`（审批时间，可能为空）
- `review_remark`（审批意见 / 驳回理由，可能为空）

**统计接口** `GET /teacher/leaves/stats` 返回：`pending`、`approved`、`rejected`、`monthly_total`（本月总计）。四个数字与文案「待审批 / 已同意 / 已拒绝 / 本月总计」一一对应。

**列表接口** `GET /teacher/leaves?status=&page=1&page_size=20`：`status` 可传 `pending` / `approved` / `rejected`，不传为全部；按 `created_at DESC` 排序。

**动作**
- 同意：`PUT /teacher/leaves/:id/approve`，请求体 `{ remark }` 可选；成功后 toast「已同意」并重新拉取列表。源码无二次确认，点击即提交。
- 拒绝：`PUT /teacher/leaves/:id/reject`，请求体 `{ reason }` **必填**。源码用 `uni.showModal({ editable: true, title: "拒绝原因", placeholderText: "请输入拒绝原因" })`：未填内容点确定 → toast「请填写拒绝原因」，不发请求；成功后 toast「已拒绝」并重新拉取。
- 下拉刷新整页。

**源码里不存在、绝对不要画的东西**：请假类型（病假/事假等，模型与接口都没有该字段）、每条记录的班级名（老师端列表 payload 不含 `class_name`）、附件/诊断证明（仅详情接口有）、审批人姓名（老师端列表不返回 reviewer）、批量审批、新建请假、详情页跳转、消息通知入口、日期范围筛选、搜索。**不要造这些。**

## 页面结构与要求

1. **顶部统计卡**：4 列等宽（`grid-template-columns: repeat(4, minmax(0, 1fr))`），数字在上、标签在下，依次「待审批 / 已同意 / 已拒绝 / 本月总计」。数字用不同语义色区分（待审批＝品牌暖橙或警示色，已同意＝`--success`，已拒绝＝`--muted`，总计＝`--fg`），字号 22px / 700。
2. **状态分段控件**：紧贴统计卡下方，4 项「全部 / 待审批 / 已同意 / 已拒绝」，每项带数量（如「待审批 3」）。这是小程序内联分段控件（一个圆角轨道里的 4 个等宽按钮），**不要用桌面下拉、不要用 `<select>`**。选中项：`--accent-wash` 底 + `--accent-deep` 文字 + 轻微阴影；未选中：透明底 + `--muted`。切换后列表按状态过滤，统计卡数字不变（统计是本月全量）。分段条滚动时吸顶在导航栏下方（`position: sticky; top: 64px`），底色用 `var(--bg)`。
3. **列表区**：标题行「最近 20 条」，右侧小字「统计为本月，列表仅显示最近 20 条」——把统计与列表口径写清楚，避免审阅者误读。
4. **待审批卡片**（每张都要有动作）：
   - 第一行：44px 圆形头像（无头像时用孩子姓名首字，`--accent-gradient-soft` 底 + `--accent-deep` 字）+ 孩子姓名（15px / 600）+ 状态胶囊「待审批」；右侧提交时间（如「今天 09:12」，11–12px `--muted`，允许折行）。
   - 第二行起：家长行「家长 乐乐妈妈」；两条事实行「请假时间」与「事由」，label 12px `--muted`、值 13px `--fg-2`，值自然折行。
   - 底部动作条（上方一条细分隔线）：左「驳回」次按钮（`--surface` 底 + `--danger` 描边与文字），右「同意」主按钮（品牌渐变 + `--on-brand` 字）。两个按钮等宽、高 44px。
   - 点击「同意」：按钮立即进入「处理中…」禁用态（两个按钮都不可点），约 1 秒后 toast「已同意」，卡片移入已审批分组，对应计数 -1，统计卡「待审批」与「已同意」同步更新。
   - 点击「驳回」：打开**微信风格居中对话框**（不是底部弹层）：标题「拒绝原因」、说明「请填写拒绝原因，家长会收到这条说明」、多行输入框（占位「请输入拒绝原因」，最多 100 字，右下角字数 x/100）、底部左右两个按钮「取消 / 确定驳回」。输入为空时「确定驳回」置灰禁用（`aria-disabled="true"`）；输入后可点。确定后 toast「已拒绝」，卡片移入已审批分组并带上驳回理由。
5. **已审批卡片**（已同意 / 已拒绝）：同样头像与姓名，状态胶囊用 `--success` / `--muted` 语义色；显示「审批时间」；已拒绝的卡片显示一行「驳回理由：…」（`review_remark`）。整卡可点击展开/收起「审批留痕」区（审批时间 + 审批意见，已同意但无意见时显示「未填写审批意见」），右侧 `›` 旋转 90° 表示展开。不要给已审批卡片画同意/驳回按钮。
6. **底部留白**：`padding-bottom: calc(24px + env(safe-area-inset-bottom))`，确保最后一张卡不被演示条遮住。

## 状态覆盖（`data-state` 驱动，演示条用 `mp-demo`，四个芯片：正常 / 空态 / 加载 / 失败）
- **正常**：7 条数据按分段「全部」展示（3 张待审批卡带动作 + 4 张已审批卡）。
- **空态**：统计卡保留（数字显示 0 的版本更自然，可一起切换）；列表区显示图标 + 一句「暂无请假申请」+ 副文案「家长提交后会出现在这里，下拉可刷新」+ 主按钮「刷新列表」。若当前是某个状态分段，空态文案改为「没有待审批的申请」等对应文案，按钮改为「查看全部」。
- **加载**：3 张骨架卡（头像圆 + 两条文字条 + 两个按钮占位），带轻微 shimmer；统计卡数字显示为短横线；分段保留但不可点。
- **失败**：图标 + 「请假列表加载失败」+ 一句「网络异常，请检查网络后重试」+ 按钮「重试」；重试后回到正常态并 toast「已重新加载」。
- **禁用态**：驳回对话框输入为空时「确定驳回」必须可见地置灰禁用；同意按钮提交中的禁用态也要画出来（正常态下点击即可看到）。
- 演示条固定在右下（无固定底栏，用默认 `bottom` 即可）。

## 交互（app.js，全部真实可点）
- 分段控件切换 4 个状态，列表与空态文案跟随；选中项 `aria-pressed`/`aria-current` 同步。
- 「同意」：进入处理中禁用态 → 约 1 秒 → toast「已同意」→ 卡片状态改为已同意并移到已审批分组，计数与统计数字更新。重复点击不重复提交。
- 「驳回」：打开居中对话框；输入为空时确定按钮禁用；点「取消」/遮罩关闭不改数据；点「确定驳回」→ toast「已拒绝」→ 卡片带驳回理由移入已审批分组。
- 已审批卡片点击展开/收起「审批留痕」，箭头旋转，`aria-expanded` 同步。
- 空态「刷新列表」→ 回到正常态并 toast「已刷新」；错误态「重试」同上。
- 所有按钮有 `:active` 反馈；无 console 报错；不用 alert/prompt。
