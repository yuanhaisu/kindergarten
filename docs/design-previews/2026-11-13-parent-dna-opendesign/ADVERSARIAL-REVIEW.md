# 家长端设计稿 · 交互与业务对抗性审查

- 日期：2026-11-14
- 对象：`docs/design-previews/2026-11-13-parent-dna-opendesign/parent/`（31 页 + 10 状态）
- 对照：`2026-11-12-parent-dna-full/`、`briefs/`、`backend/api/api-parent/`、`parent/src/pages/` 当前实现
- 范围：交互连贯性、状态机、业务规则、跨页事实；**不评 DNA / 视觉**
- 结论：**DNA 过关，交互与业务不过关。** 这批稿仍是 31 张独立页面，不是一条能走通的产品流程；11 个 P0 和 18 项跨页矛盾全部来自 brief，手工批次同样存在。先不要拿任何一版去移植。

## 审查方法

- 逐页读 `index.html` + `app.js`，抽取所有可点元素、跳转目标、状态切换。
- 对照 31 份 brief、`backend/api/api-parent/`、`parent/src/pages/` 当前实现，区分「OpenDesign 生成偏差」与「brief / 产品口径错误」。
- `href="#"` 是静态稿惯例，不逐条当 bug；只 flag 结构性缺失（没有入口、没有状态、点下去结果错误）。

### P0-0 同一天的身份矛盾（最高优先级）

- 01 `:69`：`今天 已入园，07:52 到园`。
- 17 `:63`：`07:52 由妈妈送入，下午 17:00 后可接`。
- 08 `:87`：`11 月 12 日 · 1 天` 病假；`:92` `提交于 11 月 12 日 08:20`；`:93` `待审批`。
- 10 `:117`：`医生建议在家观察一天，麻烦老师今天不用准备他的午餐`。

乐乐不可能同时在园午睡、又在家发烧。这不是某一页写错时间，而是三页对“今天”用了三个互斥的事实；首页、接送、请假不能同时成立。

**改法**：先定一个 canonical day story。建议 11/12 乐乐因病请假在家；01/17 改成“今日请假”态，或把请假记录挪到 11/11。如果坚持“在园”，08/10 的请假日期改成 11/11 或 11/13。这个决定会影响 01、08、10、17 四页的默认态。

### P0-1 首启顺序（展开）

当前产品的真实顺序是：登录 → `consent_required` → 同意页 → 首页（`parent/src/pages/auth/login.vue:73-74`、`consent.vue:3-4`）。绑定属于 `/parent/students/bind` 业务接口，被 `consentGate` 包住。设计把 03 放在 04 前面，等于让用户在未同意时先提交绑定，接口会拒绝。

**改法**：`02 登录 → 04 同意 → 03 绑定 → 首页`；04 必须在任何儿童信息收集之前。

### P0-2 绑定字段（展开）

`backend/api/api-parent/09-student.md:94-109` 的请求体只有：

```json
{ "invite_code": "ABC12345" }
```

`parent_portal_service.go:3628` 的 `BindStudent` 只接收 `inviteCode`，并在 `:3654` 写入 `Relation: "other"`。设计 03 的“幼儿姓名”“与孩子关系”没有对应的提交字段；6 位数字也与 API 示例的 8 位字母数字不一致。

**改法**：只收绑定码；绑定成功后展示服务端返回的孩子姓名/班级；如果产品确实要关系，先改 API 和 service，再画关系选择器。

### P0-3 设置页（展开）

当前产品 `parent/src/pages/settings/index.vue:29-40` 的开关：

- 通知：`notice_push` / `leave_push` / `pickup_push` / `growth_push` / `task_push` / `announcement_push`
- 隐私：`show_phone_to_teacher` / `allow_class_share` / `allow_external_share`（Phase 1 不展示）

设计 29 只有“接收园所通知”“接收老师消息”“免打扰时段”。前两个无法映射到 6 个细分开关，免打扰在 API 里不存在。

**改法**：按 9 项重画；删掉免打扰，或先加后端字段与契约。

### P0-4 报告 / 积分（展开）

- 14 `:47-71`：标题 `本学期成长报告`，统计标签 `本期积分`，值 `+128`。
- 24 `:56-62`：`本月获得 +180`。

“本学期”包含“本月”，累计获得不可能更小。除非 14 的“本期”不是本学期——但页面标题、aria-label 和老师寄语都指向学期。

**改法**：明确“本期”定义；用同一数据源重算，或把 14 改成“本月报告”。

### P0-5 接送授权（展开）

- 17 `:116`：`妈妈、爸爸、外婆，共 3 位`。
- 19 `:80-83`：外婆 `待审核`。
- 17 `:168-173`：11/10 外婆接走。
- 19 `:94-97`：叔叔 `已拒绝`；列表 4 人。
- 19 没有任何编辑/删除/停用入口；当前产品 `authorized.vue:155-166` 有删除，并且会提示“删除今日指定接走人会让二维码失效”。

**改法**：可接送人数只算 `已通过`；待审核单列；补编辑/删除/停用；删除当日指定人必须提示二维码失效。

### P0-6 时间线（展开）

- 01 `:14` 状态栏 `9:41`；`:77` `10:20 更新`；`:106` `午睡 / 进行中`。
- 17 三态共用 `9:41`：`:64` away 要求 `08:30 前送入`（已过点）；`:65` done 说 `17:12 接走`（还没到）。

**改法**：按状态改状态栏时间（away 08:10 / in 09:41 / done 17:30）；01 改成下午或把午睡改为“12:30 开始”；“更新”时间不得晚于状态栏。

### P0-7 接送码（展开）

API `05-pickup.md:96-119`：`qr_code` 是纯随机串，`expire_at` 为当日 23:59:59，“凭证当日过期、一次有效”。当前产品 `qrcode.vue:285` 也写“凭证当日 23:59 过期”。

设计 18 `:53` 叫“动态二维码”，`:66` 58 秒自动刷新，`:83` “截图不可用”，`:104` “一次有效”；17 `:99` “刷新即可更新”；30 `:123` “本学期的接送码”。这里有四种寿命：58 秒、一次、当日、本学期。

**改法**：以 API 为准改成“当日有效、核验后失效”；如果确实要短时轮换，后端要加短时 token + 旧码失效，否则删掉“截图不可用”的承诺。

### P0-8 同意页（展开）

- 02 `:68` 的勾选框默认 `checked`；04 `:55/71/87` 三个勾选框全部 `checked`。
- 04 的每一行是 `<label for="consent-...">`，整行点击只会切换勾选；没有 `<a>` 进入 05。05 实际无入口。
- 04 的“暂不同意”只 toast；当前产品 `consent.vue:73-74` 会弹阻断提示“不同意隐私政策将无法使用家长端”。
- 04 承诺“随时可以在我的 · 隐私与协议中查看全文或撤回授权”，但 31 的“隐私与协议”是死链，API 也只有 GET/POST consent，没有撤回接口。

**改法**：默认不勾选；每行加“查看”链接进 05；拒绝用阻断弹窗并给出退出路径；按后端单一 `policy_version` 记录同意；“撤回”要么实现，要么删掉承诺。

### P0-9 任务积分（展开）

`backend/api/api-parent/06-task.md:6` 的开头就写“无积分”，`:61` 写“points 已移除；任务不发放积分”，`:144` 写“points、streak_days、my_completion_rate 已移除”。任务列表里也没有“截止时间”字段。

但设计 21 `:52/:86/:114` 写 `+10 积分`、`+15 积分`、`打卡成功 · +10 积分`，22 `:51` 写 `+10 积分`，24 `:82` 写 `任务打卡 +10`，21 还画了“本周 2/3 天”。这些都无法从任务接口渲染。

`07-points.md` 又保留“任务打卡”作为积分来源，说明两份契约本身没对齐。设计不能替它们掩盖。

**改法**：先定契约——要么 06 恢复 points/streak，要么 21/22 去掉积分与三段进度、24 删掉“任务打卡”流水。契约明确前不要把 +10/+15 画成既定事实。

### P0-10 通知报名（展开）

07 `:99` 的“我要报名”对应 `app.js:146-149` 的 `showToast('报名成功')`；后端只有 `PUT /parent/notices/:id/confirm`（`02-notice.md:79-93`），语义是“确认已读/知悉”，没有报名接口、没有报名表字段、没有 `my_signup` 状态。

结果是：报名只存在于前端 toast，刷新即丢，可以无限重复，截止后也没有禁用态。正文还写“小一班全体家庭参加”，与“自愿报名 + 截止时间”语义冲突。

**改法**：二选一——改成“确认知悉”，用 `is_confirmed` 渲染已确认横幅/禁用按钮；或先在 `backend/api/` 增加报名契约与状态。补“已报名/取消报名”和截止后禁用态。

## 三、P2：一致性与体验

- **28 反馈**：提交只 toast，没有成功页/清空/联系方式校验（`app.js:160-171`）。
- **23 班级墙**：卡片打开 sheet 后只能看，不能点赞；“老师点赞”没有解释。
- **17 历史**：“近 30 天”只列 3 天；11/7 周六全日接送，若为调休补课，26 应标“补课”。
- **31 “消息通知 已开启”**：看不出是设置还是消息入口；与 30 的关系不清。
- **01 切换孩子**：sheet 只有一个孩子，切换没有意义；要么补第二个孩子，要么只有多孩时才显示。
- **03 绑定码**：设计写“6 位数字”，API 示例是 8 位字母数字；以 `student_no` 实际格式为准。
- **18 调亮屏幕**：文案让用户“把屏幕调亮一点”，但没有 `wx.setScreenBrightness` 之类的实际动作。
- **05 政策页**：只有返回，没有“同意并返回”的捷径；从 04 进来后要再返回勾选。
- **24 流水**：本周 +45，可见流水 10+5+20=+35；11/9 是周一，若这 4 条覆盖本周，则数字不对。要么补一条流水，要么标注“仅展示最近 N 条”。
- **31 统计口径**：section aria-label 是“本学期数据”，里面却放 `1245 累计积分`；标签虽写“累计”，外框是“本学期”，容易被读成本学期获得。
- **27 年龄/班级**：2021-09-08 出生、2025-09 入园，2026-11 已 5 岁 2 个月，仍写“小一班”；按常规学制应是中班/大班，或把入园年份改成 2026-09。
- **07 已读人数**：`已读 32 人` vs 班级 28 名幼儿；若“人”指家长（28 个孩子可能有 32 位家长）则成立，但文案要写清“32 位家长已读”，否则看起来像 32 个孩子。
- **15/16 相册**：15 的 7 个相册卡片是 button，但 `app.js` 没有 handler；16 也走不到。
- **06/30 筛选**：筛选本身可用，但没有“全部已读”“按时间分组”等批量操作。

## 六、根因：不是 OpenDesign 画错了，是 brief 写错了

- **绝大多数 P0 在手工批次同样存在**：01 的时间、14/24 的口径、17 的“3 位”、18 的 58 秒/截图、29 的 2 个开关、03 的姓名/关系、21/22/24 的任务积分、07 的报名。OpenDesign 只是忠实复现了 brief。
- **跨页审计的 18 项矛盾全部来自 brief**：包括“今天既在园又请假”、家长会三套日期、午睡在上午、31 的 48 vs 14 的 32、27 性别女 vs 用“他”、爸爸两个手机号。生成层没有自行发明事实，连 brief 的算术错误也照抄了。
- **brief 是从手工稿反推的，不是从 API / 当前产品正推的**：所以两批一起错。`REVIEW.md` 说“业务口径已对齐 API”，但与 `09-student`、`11-settings`、`05-pickup`、`06-task` 的实际字段对不上。
- **当前产品已经有的能力被 redesign 丢掉**：消息菜单、9 个设置、授权人删除、二维码当日过期、学生资料 API。
- **当前产品没有的能力被 redesign 发明**：免打扰时段、58 秒动态码、绑定姓名/关系、三份协议、报告 PDF 导出。
- **OpenDesign 的额外问题**：交互深度极不一致——01/07/09/18/26 有完整 JS，17/19/24/31 几乎全静态；同一个批次里有的页面能筛选、能提交，有的页面所有按钮都是死的，评审会误判流程是否成立。

## 七、修复顺序

1. **先定“今天”的唯一事实**：11/12 乐乐到底在园还是请假在家；这一个决定会改 01、08、10、17 四页。
2. **再定 11 个 P0 的契约口径**：任务积分/streak、通知报名、设置项、绑定字段、报告/积分、接送授权、接送码生命周期、同意顺序。以 `backend/api/api-parent/` 和 `parent/src/pages/` 为唯一真相源。
3. **重画首启**：`02 登录 → 04 同意 → 03 绑定 → 首页`；04 放在任何儿童信息收集之前。
4. **补回当前产品已有能力**：消息入口、9 个设置、授权人编辑/删除、二维码当日过期、学生资料可编辑字段、请假“已取消”。
5. **画一张 31 页导航图**：每个二级页写清入口/返回/空态；补 05/10/12/22/30 五个入口；统一 08-sheet 与 10-page 两套详情；补齐任务墙/日历/通知分类的真实字段。
6. **再决定视觉批次**：不要把任何一批直接移植；先让流程和业务口径过评审。

## 八、值得保留的 OpenDesign 手法

- 01 切换孩子 sheet 的焦点陷阱、`inert`、ESC 关闭（无障碍做得对）。
- 18 接送码的倒计时视觉与“核验后失效”文案（但需后端支持短时 token）。
- 26 日历点选日期后议程联动（真的在换内容）。
- 07 报名确认 sheet 的焦点管理。
- 06/11/13/30 的筛选（不是只切换高亮，真的在过滤）。
- 09 表单错误聚焦 + 就医凭证数量上限。
- 21 打卡的乐观状态（但应先进入 22 的步骤，而不是直接 +10）。

## 九、一句话

**先不要把任何一版拿去移植。** 视觉已经够好，但业务口径和流程断点会把错误直接写进代码；先把 brief 修到与 API / 当前产品一致，再谈哪一版更好看。
