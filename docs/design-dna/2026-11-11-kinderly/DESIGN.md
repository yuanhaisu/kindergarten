## 一、它是什么

给 2–10 岁孩子家长（尤其自闭症 / ADHD / 焦虑 / 感官敏感）的陪伴型 App。界面几乎不承担"管理"职责，只做三件事：**看懂孩子、给出下一步、记录微小进步**。

这决定了它的视觉策略：**低信息密度、低刺激、慢节奏、强文字**。我们的家长端虽然业务不同（家园沟通、接送、成长记录），但"家长在疲惫状态下使用"这一使用场景高度重合，DNA 可迁移。

## 二、三条决定一切的规则

### 1. 暖纸底 + 深松绿，不用黑白

| 角色 | 值 | 用途 |
|---|---|---|
| 画布 | `#ECE6D7` (bone) | 所有页面底色 |
| 卡片 | `#FFFFFF` | 抬升面 |
| 次级面 | `#F2EDDE` (bone-cool) | 分区、未激活轨道 |
| 正文/主色 | `#173220` (pine) | 文字、主按钮、图标 |
| 次要文字 | `#728173` (ink-soft) | 说明、时间戳 |
| 暖强调 | `#C36540` (terracotta) | 行动、播放/录音、少量强调 |
| 正向强调 | `#DDB14A` (marigold) | 奖励、完成、庆祝 |
| 植物绿 | `#CFD9C5` / `#8DA386` / `#5C7359` | 标签底、插画、勾选 |

- 禁止纯黑 `#000` 和纯白文字面。最深的墨是 `#0D2014`。
- 面的区分靠**几级明度差 + 1px 发丝线**，不靠阴影。
- 语义色没有独立色相体系（success/warning/error 都从这套土色里取），这是刻意的：全屏只有一个色温。

### 2. 衬线标题 + 无衬线正文，权重永远 400

- 标题：**Instrument Serif**（或同类高对比、略窄的衬线），400 字重，负字距（-0.02 ~ -0.04em），行高 0.95–1.15。
- 正文/UI：**Geist**（或同类中性无衬线），400 / 600 两档。
- 第三档：手写体（Gochi Hand）只用于插画里的标注，不进 UI。
- **标题不许加粗**。层级靠字号和留白，不靠 weight。
- 尺寸阶梯：80 / 56 / 36 / 20 / 16 / 14 / 12，caption 带 0.14em 字距（像眉题）。

### 3. 留白是结构，不是装饰

- 一屏只放一个焦点块，内容集中在上 60%，下方留空。
- 单列、左轴对齐（官网 hero 可居中，应用内不居中）。
- 分区间距 24–32px；页面左右 20–24px；营销区段 96px。
- 低于 3 个元素的区域不要加容器——直接放在画布上。

## 三、组件配方

### 按钮

- 胶囊：`border-radius: 999px`，高 56px，17px/600。
- 主按钮：pine 填充 + bone 文字；次按钮：白底 + 1px pine 描边 + pine 文字。
- 无阴影、无渐变、无 hover 位移。按下只做透明度或明度变化。

### 输入框

- 高 52px，圆角 14px，白底，1px `rgba(23,50,32,.22)` 描边，16px 文字。
- 聚焦：描边不变，外加 `0 0 0 3px rgba(23,50,32,.12)` 光晕。

### 卡片 / 列表行

- 白面，圆角 18–24px（行可到 9px），1px `rgba(23,50,32,.1)` 发丝线，**无阴影**，内边距 20–24px。
- 列表行高 56–64px，行间靠 8–12px 间距，不画分隔线；需要分隔时用同一条发丝线。

### 标签（关键差异点）

**不要做胶囊 chip。** 参考产品把标签做成**行内文字高亮**：句子里的词背后刷一块 sage 或 marigold 底色，文字仍是正文色。这是它最容易被认出的特征，也是最值得迁移的一个。

```
Milo  6 years old · ADHD
[Loves dinosaurs] [Big feelings] [Busy body]   ← 词背后是色块，不是边框胶囊
```

### 对话气泡

- 用户：pine 填充，bone 文字，圆角 `10px 3px 10px 10px`（右下角收紧）。
- 系统/陪伴者：白面 + 发丝线，圆角 `3px 10px 10px 10px`（左上角收紧）。
- 更激进的做法（参考产品的实际选择）：**系统回复直接裸排**，不加气泡，只用粗体行内小标题分隔建议。

### 勾选 / 进度

- 方形勾选框 16px，圆角 3px，sage 底 + sage-deep 描边；完成后填充并加对勾。
- 进度条/轨道：bone-cool 底 + 99px 圆角；进度填充用 pine 或 terracotta。

## 补充：登录后真实应用的关键模式（优先于上文）

登录后抓了 24 屏，营销稿里的推断有三处需要修正，也补出了三条最有迁移价值的新模式。

### 三处修正

1. **有持久导航**：底部是**悬浮白色胶囊导航**（Kin / Children / Today / Stories / Settings），固定在底部上方，阴影 `rgba(23,50,32,.35) 0 10px 30px -14px`。激活项是 sage 胶囊底色 + 图标 + 16px 标签，未激活是 `#728173`。
2. **卡片底色有两种**：主内容卡是纯白 `#FFFFFF`，设置/资料类分区是 `#FCFAF4`（bone-cool），都配 1px 发丝线，仍然没有阴影。
3. **应用内标题不是 56–80px**：h1 实际是 34–40px 的 Instrument Serif；`18px/1.5` 的衬线正文只用于"反思性长文"（基线描述），控件和元数据是 13–16px Geist。

### 三条新签名模式

- **天气三选一**：情绪记录不用 1–5 分，用 Sunny / Cloudy / Stormy 三张卡。低摩擦、无评判、一眼可读——这是整套设计里最聪明的交互，值得直接迁移到"今日心情 / 接送状态"。
- **悬浮胶囊导航 + 右下圆形 FAB**：FAB 是 pine 底 + terracotta 图标，浮在导航之上。导航不是贴底边，而是留出呼吸距离。
- **虚线三段进度**：用三段虚线段表示"再 3 次打卡解锁"，比进度条更轻，也不制造完成压力。

### 主要屏幕清单（登录态）

| 模块 | 屏幕 | 关键模式 |
|---|---|---|
| Children | 孩子列表 / 添加孩子 | 26px 资料卡、32px 圆形头像 + 2px sage 环、行内高亮标签 |
| Kin | 对话 / 语音输入 | 不对称气泡、零 UI 裸排回复、语音/文字切换胶囊 |
| Today | 周历 + 打卡 | 天气三选一、虚线进度、三段式卡片（白 / pine / sage-deep） |
| Stories | 列表 / 详情 / 新建 | 12–20px 故事卡、列表内嵌操作（刷新 / 计数 / ···） |
| Learn | 文章库 / 文章 | 26px sage-deep 推荐卡、22px tip 卡、999 过滤胶囊 |
| Recipes | 食谱库 | 纹理筛选胶囊、20–22px 图文卡 |
| Settings | 设置 / 个人 / 安全 / 家庭 / 日历 / 邀请 | bone-cool 分区卡 + 白行、行尾 chevron |
| Tools | 呼吸引导 | 全屏沉浸，无导航干扰 |

## 补充：覆盖层、状态与主题（第二轮采集，2026-11-11）

### Today 的可点击入口（实测，逐卡）

顶部日期条：`‹ ›` 切周（未来周禁用 `opacity .35`）；`M/T/W…` 切换当天，卡片标题随之变成 `JUNYAN'S MONDAY CHECK-IN`。

| 卡片 | 主区域 | 底部文字链 | 备注 |
|---|---|---|---|
| Junyan's check-in | `i` 展开 tooltip；Sunny/Cloudy/Stormy 选天气；Send 提交；「That's all for today」 | — | 天气与 Send 会写记录，未点击；「That's all for today」未点 |
| Today's Read | 整卡（368px 高）→ `/learn/<slug>?from=today` | 「Browse all reads in Learn ›」→ `/learn?from=today` | 卡内还有「Read it ›」，与整卡同一目标 |
| Kinderly Picks | 图标行（96px 高）→ `/picks` | 「See the picks ›」→ `/picks` | **主区域链接没有可读文本**（只有图标），依赖 aria/上下文 |
| Kinderly Recipes | 「Open Kinderly Recipes」（102px）→ `/recipes` | 「See the recipes ›」→ `/recipes` | 主区域与文字链同目标 |

**触控尺寸问题**：三张卡底部文字链高度只有 **18px**，宽度 93–166px，远低于 44px 的触控建议；主区域卡片是 96–368px，安全。参考产品在这点上并不符合它自己的其他规格，不要照搬。

### 行内 tooltip

`role="tooltip"`：松绿底 `#173220` + 骨白字，圆角 12px，内边距 `10px 12px`，字号 12.5px，最大宽 305px，绝对定位，阴影 `rgba(23,50,32,.4) 0 8px 24px -12px`。触发按钮 16×16、1px 描边圆形。

### 空态（按天）

某天没有打卡时，卡片显示「Nothing was shared about Monday. That's okay, every day doesn't need a note.」——**不施压**的文案基调。卡片：白底、20px 圆角、18px 内边距、发丝线；overline 10.5px、正文 14.5px。

### Recipes 列表页（390 实测）

- **页头**：`‹ Today` 返回（60px 宽）+ `Saved / List` 两个 32px 胶囊 tab；H1 「Kinderly Recipes」30px 衬线；说明文案 14px/21px。
- **搜索**：`<label>` 包 `<input type="search">`，容器 48px 高、`#F2EDDE`、圆角 999、1px `rgba(23,50,32,.2)`、内边距 0 16；输入文字 16px 无边框。
- **筛选胶囊**：未选 28px 高、12px 字、透明底；选中态 `rgba(141,163,134,.2)` 底 + 1px 松绿描边 + 松绿字。
- **网格**：2 列，列宽 161.5px，间距 8px。
- **卡片**：162×266，`#F2EDDE` 底、18px 圆角、8px 内边距、无阴影；内部插画块 150×144（SVG 123×123），底部标题 + 蛋白/纤维/口感/时间元信息；保存按钮 32×32。
- 一页 40 张卡片。
- **触控尺寸**：筛选胶囊 28px、保存按钮 32px，都低于 44px —— 与它自己的底部文字链一样，是参考产品的不一致处。

### Recipes 集合页（Lunchbox ideas，390 实测）

- **路由不变**：从 `/recipes` 进入集合后 URL 仍是 `/recipes`，集合是客户端状态，不是独立路由。
- **返回**：`Recipes` 是按钮（无 href），客户端回退。
- **页头**：H1「Lunchbox ideas」30px 衬线；说明 14px/21px，颜色 `#3D5141`。
- **筛选**：每个集合有自己的词表——Lunchbox 是 `All / No-cook / Make ahead / Build your own`，After-school 是 `All / Crunchy / Cool / Sweet`；统一 28px 高、12px 字、**全部带 1px `rgba(23,50,32,.2)` 描边**，选中态再加 sage 20% 底 + 松绿描边。
- **卡片**：与主列表相同——162×266、`#F2EDDE`、18px 圆角、8px 内边距；标题 14px/600；蛋白/纤维 12px/400 `#3D5141`；口感标签 12px/400 `#728173`（纯文字，不是胶囊）。
- 一页 20 张（`20 RECIPES`）。

### 弹窗体系

- **底部抽屉**（Stories 的 `···`）：白色面板贴底，**上圆角 24px**，内边距 `14px 20px 24px`，顶部有拖拽把手；行高 84px、文字 16px/400，底部 Cancel 是 14.5px 胶囊；遮罩 `rgba(23,50,32,.55)`。
- **破坏性确认不是弹窗**：删除账号走独立路由 `/settings/delete`，主按钮 `#A8323A`（深红，实测），次按钮透明底。产品里**没有居中对话框**。
- 语义色更正：`error` 从推断的 `#A04D2A` 改为实测的 `#A8323A`；success 仍未观察到。

### 表单与控件

- 校验方式：不显示行内错误，**CTA 直接禁用**（`disabled` + `opacity .6`，填充色不变），必填齐了才可点。
- 下拉选择用**原生 `<select>`**，没有自定义 picker。
- **没有 switch 组件**：两步验证用整行「Turn on」按钮，不是开关。

### 反馈

- 保存设置、刷新故事、切换语言都**没有 toast**，静默生效或按钮短暂显示「保存中…」。DNA 里不应假设存在 toast 组件。

### 主题与视口

- **不支持深色模式**：模拟 `prefers-color-scheme: dark` 后 body 仍是 `#ECE6D7` / `#173220`。
- 390×844 下 h1 为 36px（桌面 Settings 是 36px、Children 是 34px）；悬浮底栏会盖住滚动内容，需要页面自行留底部 padding——参考产品也这样。

### 中文排版的边界

参考产品只有 English / Français，**没有任何中文界面**。所以「中文用衬线还是无衬线」不是从参考里提取的规则，而是我们必须自定的决策；不要把它写成 DNA 的一部分。

## 补充：SVG 与插画（/picks 实测）

参考产品的图形分两层，之前只记了第一层，漏了插画这一层：

> 以下数字来自 2026-11-11 对 `/picks` 的实际测量（27 个 24 网格图标 + 12 个 120 网格插画），不是估的。第一次写这节时用了「线宽统一 3」「主体占 80–100」等未测量的说法，已按实测更正。

### 第一层：UI 图标（24 网格，27 个样本）

- `viewBox="0 0 24 24"`，`fill` 必须为空，`stroke: currentColor`
- 线宽 **1.6 / 1.7 / 1.9 / 2.0 都出现过**，按图标光学重量逐个取，不强制统一
- 内容 bbox 约 **x 4–20、y 4–21**，留白 2–5 且允许不对称，不要求居中留 2
- 尺寸档位：14 / 17 / 18 / 20 / 22（不是只有三档）
- 元素数 1–5 都允许；颜色跟随文字（pine 或 `#728173`），不做双色

### 第二层：插画瓦片（120 网格，12 个样本）

- `viewBox="0 0 120 120"`，渲染 **128×128**
- 线宽分层：主体轮廓 **3**、细节 **2**、强调 **4–6**；线宽不是全局常量
- 填充白名单（单图 1–3 个）：`#C36540`、`#8DA386`、`#DDB14A`、`#FCFAF4`、`#173220`
- 主体 bbox 宽 **52–80**、高 **36–80**；元素数 2–8
- 圆角矩形 `rx=10`，`stroke-linecap/linejoin: round`，无渐变/投影/明暗
- 底：浅 sage / marigold 的圆或圆角方形容器，插画不要贴边
- `/picks` 一页有 12 个这样的瓦片（耳罩、计时器、日程、餐盘、书……），这是产品最像"自己"的地方

### 怎么执行（不许再手写语法）

```bash
node scripts/design-svg-audit.mjs <file.svg> [more.svg] [--json]
```

校验 viewBox、线宽区间、填充白名单、元素数；PASS 才进入设计稿。14px 可读性仍需人工/视觉评审，脚本不管。

### 小程序落地

- WXML 不支持内联 `<svg>`：插画必须导出为 `.svg` 文件走 `<image>`，或 base64 data-URI
- UI 图标可以继续用 iconfont（现有 remixicon）；插画**不能**用 iconfont 代替，会丢掉描边与填色两层结构
- 插画按 128rpx 容器切图，导出时保留 120 网格的留白，避免贴边

### 我们目前的缺口

迁移的接送页只用了第一层（remixicon 字形），没有插画层；空态、引导页、首次使用页是最该用插画的地方，但需要先补一套 120 网格的插画资产，不能拿图标字体硬凑。

## 四、动效

| 场景 | 规则 |
|---|---|
| 入场 | 透明度 0→1 + 上移 64px + 缩放 .98→1，1150ms，`cubic-bezier(.16,.68,.22,1)` |
| 微交互 | 150–200ms，只改透明度/明度 |
| 加载 | 呼吸/脉冲，不用旋转 spinner |
| 连续运动 | 仅限横向 marquee（36s linear）；其他地方一律静止 |
| 禁止 | 弹跳、弹簧、视差、光标特效、3D、WebGL、着色器 |

## 五、明确不要抄的部分

- 品牌标识（圆形 sprout mark）、"kinderly / Kin" 字样、Gochi Hand 手写签名
- 儿童摄影照片、插画资产（罐子、弹珠）
- 文案语气中的具体措辞与产品隐喻（"Kin always here"）
- 版式中的独特构图（超大 `$0`、被裁切的巨型衬线字母）

这些是**身份**，不是**规则**。规则可以迁移，身份必须重做。

## 六、迁移到我们项目的建议

### Token 映射（家长端）

| 我们的 token | 现值 | DNA 建议 |
|---|---|---|
| `color.bg.page` | `#F7F3EA` | 已接近，建议改为 `#ECE6D7` 或保留现值作为"更亮版本" |
| `color.bg.card` | `#FFFAF0` | 改为 `#FFFFFF`，靠发丝线区分，不用暖白卡片 |
| `color.text.primary` | 深灰 | 改为 `#173220`（深松绿） |
| `color.brand.primary` | `#F97316` | **保留**橙色作为行动色，不要换成 terracotta；DNA 的可迁移部分是"低饱和土色 + 单一强调"，不是具体色值 |
| 标题字体 | 系统无衬线 | 引入一款衬线做 display（微信小程序需自托管子集，注意包体） |
| 圆角 | 24rpx 左右 | 与 DNA 一致（12–14px 设计值） |

### 落地顺序

1. 先做**家长端 4–5 页验证集**（首页 / 接送 / 成长列表 / 表单页），验证"衬线标题 + 暖纸底 + 行内高亮标签"在真实业务信息密度下是否成立。
2. 成立后再决定是否改 `tokens.json`；不成立就只保留色彩与动效规则，放弃衬线。

### 不适用场景

- 管理后台（admin）：信息密度高、表格多，这套低密度规则会浪费屏幕，只迁移色板与圆角。
- 老师端：介于两者之间，可迁移色彩与组件形状，不迁移"一屏一焦点"。
